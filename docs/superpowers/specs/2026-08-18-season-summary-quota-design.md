# 현재 시즌 전적 카드와 PUBG API 한도 보호 설계

## 목표

전적 페이지 상단에 PUBG 게임 결과 화면처럼 현재 시즌의 핵심 경쟁전 요약을 추가하고, 시즌 카드가 기존 캐시 응답만 사용하도록 하여 사용자 조회가 PUBG API 호출을 늘리지 않게 한다. 동시에 일일 유지보수 작업에서 PUBG API `429`가 발생하면 이후 저우선 수집 작업이 같은 키를 반복 호출하지 않도록 중단·스킵한다.

## 현재 구조와 원인

- `/api/pubg/player`는 `pubg_player_cache.season_stats_data`, `seasons_list`, `last_season_id`와 `pubg_response_cache`를 사용한다.
- 캐시 적중 시 응답에는 이미 시즌 목록과 시즌별 `ranked`/`normal` 통계가 들어 있으므로 시즌 요약 카드에 별도 API 엔드포인트가 필요 없다.
- `PlayerProfileHeader`에는 현재 랭크, RP, 시즌 선택이 있고, `StatSummaryPanel`에는 선택 모드·파티의 게임 수, KDA, 평균 딜량, Top 10이 있다.
- 일일 작업의 `sync_user_matches`는 PUBG API `429`를 감지하고 종료하지만, 워크플로는 이를 공유하지 않아 뒤의 `Run Hotdrop Collection`이 계속 호출한다. 이 중복 호출이 한도 초과와 유지보수 실패를 만든다.

## 사용자 경험 설계

### 상단 현재 시즌 카드

`PlayerProfileHeader` 내부의 랭크 행을 현재 시즌 대표 카드로 확장한다. 기본 기준은 사용자가 승인한 대로 `현재 시즌 · 경쟁전 · 스쿼드`다.

- 헤더: `시즌 42 | 경쟁전`에 해당하는 현재 시즌명과 `스쿼드` 보조 라벨
- 왼쪽: 티어 아이콘, 티어명, RP
- 오른쪽 핵심 지표: 경기 수, 승리 수, 승률, Top 10률
- 하단 보조 지표: 평균 딜량, KDA, 평균 생존시간, 헤드샷률
- 데이터가 없으면 0을 만들어내지 않고 `기록 없음` 또는 `—`로 표시한다.
- `updatedAt`을 카드 하단에 `캐시 기준: N분 전`으로 표시해 사용자가 정보의 신선도를 이해할 수 있게 한다.
- 모바일에서는 핵심 지표를 2열 그리드로 접고, 보조 지표를 가로 스크롤 없이 2열로 유지한다.
- 기존 시즌 `<select>`와 전적 갱신 버튼은 유지한다. 카드 자체에 추가 모드 선택을 넣지 않아 시각적 복잡도를 막는다.

### 기존 상세 통계와의 관계

기존 `StatSummaryPanel`의 경쟁전/일반전, 솔로/듀오/스쿼드 컨트롤은 그대로 둔다. 상단 카드는 현재 시즌의 대표 성적을 빠르게 읽는 역할이고, 아래 패널은 사용자가 모드와 파티 크기를 바꿔 비교하는 역할로 분리한다.

대표 카드 지표 계산은 다음과 같다.

| 지표 | 계산 | 표시 규칙 |
| --- | --- | --- |
| 경기 수 | `roundsPlayed` | 정수 |
| 승리 수 | `wins` | 정수 |
| 승률 | `wins / roundsPlayed * 100` | 소수 1자리 `%` |
| Top 10률 | `top10Ratio` 또는 `top10s / roundsPlayed` | 소수 1자리 `%` |
| 평균 딜량 | `damageDealt / roundsPlayed` | 정수 |
| KDA | `(kills + assists) / deaths` | 소수 2자리 |
| 평균 생존시간 | `timeSurvived / roundsPlayed` | `분:초` |
| 헤드샷률 | `headshotKills / kills` | 소수 1자리 `%`, 킬 0이면 `—` |

평균 순위는 PUBG 시즌 통계 응답에 명시적으로 제공되지 않는 경우가 있으므로 억지로 최근 매치의 일부 값으로 대체하지 않는다. 시즌별 매치 집계가 충분히 쌓이면 별도 지표로 확장할 수 있다.

## 데이터 흐름

1. 기존 `/api/pubg/player` 응답을 받는다.
2. 클라이언트에서 `seasonId`와 `stats.ranked.squad`를 사용해 대표 카드 지표를 계산한다.
3. 시즌 선택 변경은 기존 컨트롤러 경로를 사용한다.
4. 캐시 응답에 선택 시즌이 없을 때는 자동으로 새로운 API 호출을 하지 않고, 서버가 제공한 캐시 상태와 `updatedAt`을 기준으로 빈 상태를 보여준다. 사용자가 명시적으로 `전적 갱신`을 눌렀을 때만 기존 강제 갱신 쿨다운 경로를 사용한다.

## API 한도 보호 설계

### 웹 요청

- 시즌 카드 전용 API를 추가하지 않는다.
- 기존 응답 캐시를 카드와 상세 패널이 함께 사용한다.
- 강제 갱신은 현재의 분산 락/60초 쿨다운을 유지한다.
- 캐시가 불완전한 경우 자동 재시도를 하지 않고, 사용자가 명시적으로 갱신할 수 있게 안내한다.

### 일일 유지보수

- `sync_user_matches`가 플레이어 조회 또는 매치 상세 조회에서 `429`를 받으면 `GITHUB_OUTPUT`에 `rate_limited=true`를 기록하고 정상 종료한다.
- `maintenance` 잡은 해당 출력값을 job output으로 전달한다.
- `Run Hotdrop Collection`은 `rate_limited=true`이면 실행하지 않고 `::warning::`과 스킵 사유를 남긴다.
- 같은 실행 안에서 이미 한도 초과가 발생했으므로 핫드랍을 다시 호출하지 않는다. 다음 스케줄에서 재시도한다.
- 기존 백필은 독립적으로 실행하되, 자체 `429` 처리 규칙은 유지한다.
- Discord 실패 알림은 실패 원인 추출 시 환경변수 이름보다 실제 오류 문장을 우선하도록 필터를 좁힌다.

## 오류·빈 상태

- 현재 시즌 통계가 없으면 카드 제목은 유지하고 각 값은 `—`, 설명은 `현재 시즌 기록이 아직 없습니다.`로 표시한다.
- 캐시 시각이 오래되어도 자동 호출하지 않고 `마지막 저장: ...`을 보여준다.
- API 429 응답은 기존 컨트롤러의 재시도 시각을 사용하며, 사용자가 기다리는 동안 동일 identity 요청을 차단한다.
- 시즌 데이터의 일부 필드가 빠져도 카드 전체를 숨기지 않고 해당 필드만 `—`로 대체한다.

## 변경 범위

### 수정 대상

- `types/stats-page.ts`: 대표 시즌 카드 지표 타입과 필요한 시즌 메타 타입
- `lib/stats/statsPageModel.ts`: 경쟁전 스쿼드 대표 bucket 선택 및 지표 계산 순수 함수
- `components/stat/profile/PlayerProfileHeader.tsx`: 현재 시즌 카드 UI
- `components/stat/overview/StatsOverviewRail.tsx` 또는 공용 포맷터: 중복 지표 포맷 규칙 정리
- `scripts/sync_user_matches.ts`: 429 상태 출력
- `.github/workflows/daily-tasks.yml`: 출력 전달 및 핫드랍 스킵 조건
- 관련 Vitest/React 테스트와 fixture

### 추가하지 않는 것

- PUBG API를 호출하는 새 시즌 전용 라우트
- 새 Supabase 테이블 또는 RLS 변경
- 평균 순위를 위한 최근 매치 재조회
- 상단 카드 안의 추가 모드/파티 드롭다운
- API 429를 무조건 성공으로 숨기는 처리

## 테스트 전략

- 순수 지표 함수: 승률, Top 10률, KDA, 생존시간, 누락 필드, 0경기 케이스
- 기존 fixture 기반 프로필 카드: 현재 시즌 경쟁전 스쿼드 수치와 `—` 빈 상태
- 응답 캐시: 카드가 별도 fetch를 만들지 않는 기존 컨트롤러 계약 유지
- `sync_user_matches`: 429 발생 시 `rate_limited=true` 출력과 다음 사용자/매치 중단
- 워크플로 정적 계약: hotdrop 조건이 rate-limit output을 존중하는지 검증
- 브라우저 검증: 모바일 2열, 데스크톱 카드 가독성, 시즌 선택과 갱신 버튼의 기존 동작

## 성공 기준

1. 캐시가 있는 전적 조회에서 시즌 카드 때문에 추가 PUBG API 요청이 발생하지 않는다.
2. PUBG API 429 이후 동일한 일일 작업에서 핫드랍 API 요청이 발생하지 않는다.
3. 상단 카드에서 사용자가 3초 안에 시즌, 티어, RP, 경기 수, 승률, Top 10률을 읽을 수 있다.
4. 기존 상세 통계 모드 전환·시즌 선택·강제 갱신·매치 피드가 깨지지 않는다.
5. 관련 단위 테스트, 타입 검사, 린트, 브라우저 스모크가 통과한다.
