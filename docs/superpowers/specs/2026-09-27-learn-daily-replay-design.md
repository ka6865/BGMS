# /learn: 전날 랭커 우승 경기 복기 고도화

작성일: 2026-09-27. 상태: 2026-09-28 로컬 구현·통합 검증 완료, 모델 품질 56건·추가 한도 검증 3건 관측, 25건 미완료. 일일 20회 단정 철회 및 65초/5분 대기 재검증 기록, 현재 모델 유지·교체 판단 보류. 운영 DB 적용·배포·모델 전환 미실행.

## 사용자 의도와 범위

경쟁전 솔로·듀오·스쿼드에서 전날 상위권 선수의 우승 경기를 모드별 한 편씩 선정한다. 일반 사용자가 지도와 짧은 해설로 한 판을 따라가고, 다음 경기에 적용할 점 하나를 얻는 경험을 만든다. 목표 열람 시간은 약 3분이며, 실측 전에는 예상 시간으로만 취급한다.

작업 순서는 **공통 입력·검증 개선 → 모드별 발행과 장면형 화면 → 동일 조건에서 모델 재평가**다. 지난 출력의 문체나 단일 응답 속도로 모델을 먼저 교체하지 않는다. 새 모델 선택은 개선된 제품 흐름에 대한 평가 결과로 결정한다.

## 모드와 출처 기준

- 초기 플랫폼·시점 범위는 기존 서비스와 같은 Steam·TPP다. FPP를 TPP로 조용히 합치지 않는다.
- 솔로·듀오·스쿼드는 실제 매치 `gameMode`, `matchType=competitive`, `isCustomMatch=false`, 계정 ID, 우승 결과, 텔레메트리 매치 ID를 대조한다. 파티 인원만으로 모드를 추측하지 않는다.
- 로컬 솔로 원본 `cdd3a704-a14c-4ef9-9cbe-01ededea7319`는 매치 응답에 `competitive + solo`, 텔레메트리 `LogMatchDefinition`에 동일 매치의 `competitive...steam.solo.as`가 있다. 공식 시즌 36 안내와 차이가 있다는 이유만으로 이 샘플을 일반전으로 바꾸거나 삭제하지 않는다. 최근 실제 수집 결과로 발행 가능 모드를 재확인한다.
- 리더보드 출처와 경기 지역은 별개다. 기존 비교 스쿼드 원본의 텔레메트리는 `steam.squad.sea`이므로 AS 리더보드 선수를 AS에서 열린 경기로 표시하지 않는다.
- 상위권 기준은 현재 시즌 AS 리더보드 조회 상위 20명으로 시작한다. 순위와 조회 시각·시즌·리더보드 출처를 보관하고 ‘모드별 순위’로 표기하지 않는다.
- 모드별 리더보드 응답의 실제 동일성·지원 여부를 점검한다. 같은 통합 명단이면 계정과 경기 요청을 실행 내에서 공유한다. 특정 모드 리더보드가 없다는 이유만으로 그 모드 경기가 없다고 판단하지 않는다.
- 공식 안내 참고: [시즌 36 경쟁전 개편](https://pubg.com/en/news/8722). 위 로컬 원본 확인과 안내를 구분한다.

## 사용자 화면

`/learn` 상단은 전날 경기일(KST)과 솔로·듀오·스쿼드 카드다. 각 카드는 학습 주제가 드러나는 제목, 맵, 선수, 순위 조회 시점, 장면 수, `우승 과정 따라보기`를 보여준다. 기록이 없는 모드는 ‘해당 날짜에 공개된 분석이 없습니다’로 표시한다. 실패인지 미지원인지 확인할 근거가 없으면 이유를 단정하지 않는다. 지난 경기에는 원래 날짜를 표시한다.

상세는 기본 3~5개의 장면으로 구성한다. 착지 → 이동 → 주요 교전/복구 → 마지막 원 → 우승 흐름을 우선하되, 근거가 없는 장면을 채우지 않는다. 같은 근거 묶음의 중복 장면을 허용하지 않는다.

장면마다 `당시 상황 / 기록된 행동 / 확인된 결과 / 내 판에서 점검할 것`을 짧게 보여준다. 앞의 세 항목은 근거 ID와 코드 계산에 연결한다. 마지막 항목은 조건이 맞는 검토된 학습 문구에서 고르며, 선수의 의도나 승리 원인으로 표현하지 않는다. 적용할 문구가 없으면 그 항목을 생략한다.

PC는 지도와 해설을 나란히, 모바일은 지도 아래 장면 카드와 이전/다음 버튼을 둔다. 장면을 바꾸면 시간·강조 인물·원·표본 위치가 함께 바뀐다. 선택 장면과 무관한 상대는 기본 숨김이다. 관측되지 않은 위치를 채워 넣지 않고, 표본 시각과 점선의 의미를 안내한다.

전체 이벤트와 무기별 수치는 펼쳐보기로 둔다. 리플레이가 보관된 경기에는 해당 장면 시작점 링크를 제공한다. 리플레이 자료가 없거나 로딩에 실패해도 저장된 장면 지도·해설은 읽을 수 있어야 한다. 자동 재생은 기본 끔이다.

모드별 강조점은 솔로의 개인 이동·회복, 듀오의 두 사람 간격·소생·재합류, 스쿼드의 집결·여러 팀원 교전 참여·인원 복구다. 인원수·생존 상태는 해당 시점의 근거가 있을 때만 표시한다.

## 공통 근거와 장면 생성

기존 추출기를 확장한다. 별도 분석 엔진이나 모델 라우팅 프레임워크는 만들지 않는다.

1. `buildDailyEvidence`가 인물 ID, 팀 ID, 이벤트 유형, 원본 인덱스, 시각과 관련 필드를 가진 근거를 생성한다. 피해·기절·처치·소생·아이템 획득·실제 발사를 구분한다. 같은 시각 이벤트도 원본 인덱스로 구별한다.
2. 검증된 근거로 장면 후보를 만든다. AI는 후보 ID를 고른다. 반환 ID, 개수, 중복, 시간 순서와 필수 종료 장면 누락을 검사한다. 누락 보충은 기록하고 모델 원본 성과로 계산하지 않는다.
3. 공개 상황·행동·결과는 근거에서 조립한다. 지형, 시야, 엄폐, 소통, 유인·추격 의도, 특정 행동의 승리 인과관계를 추측하지 않는다. 자유 산문은 재평가용 출력에만 둔다.
4. 장면 지도에 필요한 자기장 중심·반경, 아군·상대 위치, 표본 시각을 함께 저장한다. 기존 `zones`의 거리 요약만으로 원을 그리지 않는다. 공개 데이터에는 필요한 장면 표본만 포함한다.
5. 한 경기의 마지막 아군 킬을 곧바로 최종 승리 행동으로 간주하지 않는다. 최종 생존 결과·경기 종료 근거와 확인하고, 자기장 사망 등으로 끝났다면 마지막 아군 교전과 우승을 분리한다.

새 JSON에는 `schemaVersion`, `evidenceVersion`, `promptVersion`과 출처를 남긴다. 구버전 문서는 기존 표시 경로로 읽고 원본이 있을 때만 재생성한다. 이전 발행물을 새 데이터인 것처럼 보강하거나 덮어쓰지 않는다.

## 저장·발행·호환성

- KST 전날 00:00 이상, 다음 날 00:00 미만의 경기 시작 시각을 사용한다.
- 기존 `daily_ranker_stories`를 확장해 PK를 `(day_kst, mode)`로 바꾸고 듀오를 허용한다. `match_id` 중복 금지, Steam 제한, 서버 전용 읽기·쓰기 권한과 RLS를 유지한다. 기존 마이그레이션을 수정하지 않고 새 마이그레이션을 만든다.
- 새 상세 URL은 `/learn/daily/[day]/[mode]`. 기존 `/learn/daily/[day]`는 한 편이면 해당 상세로 연결하고 여러 편이면 그날 모드 선택을 보여준다. 기존 고정 샘플 주소를 유지한다.
- 존재 확인·중복 충돌 처리·재실행 모두 날짜와 모드로 판단한다. 다른 모드 발행이 기존 성공을 막지 않는다. 같은 날짜·모드 동시 실행은 한 건만 남기고, 다른 날짜에 이미 발행된 `match_id` 충돌을 성공으로 오인하지 않는다.
- 일반 후보 실패는 다음 후보·모드로 진행하되 429는 공통 API 한도 신호로 취급한다. 성공한 발행은 유지하고 호출을 중단한다. 재시도는 미완료 모드부터 한다.
- 기존 모드당 상위 20명·최근 최대 14경기 탐색 한도와 실행 전체 12분 제한을 유지한다. 검증 후보 최대 3경기/모드 중에서 선택한다. 기록 완전성 → 서로 다른 유효 장면 수 → 직전 7일 선수·맵 반복이 적은 순으로 고른다. 동률은 경기 시작 시각과 매치 ID로 정렬해 재현한다.
- AI 생성과 근거 저장은 발행 시 한 번 수행한다. 열람마다 원본 텔레메트리나 Gemini를 호출하지 않는다. 하루 발행량 확대 비용은 모델 호출 횟수뿐 아니라 PUBG 탐색량·원본 다운로드량·JSON 크기를 함께 측정한다.

## 고도화 후 모델 재평가

**실행 전 조건:** 공통 입력 완전성, 원본 근거 연결, 공개 검증, 새 장면 화면이 검증돼야 한다. 입력·프롬프트·평가 코드 버전과 SHA-256을 고정한다. 기존 결과는 과거 기준선이며 새 실험과 같은 조건의 수치로 합산하지 않는다.

**대상:** 실행 시 Models API로 실제 호출 가능 여부와 정확한 모델 ID를 확인한다. 과거 비교의 3.6/3.7/3.8 Flash와 현재 코드의 `gemini-3.5-flash-lite`를 후보로 삼되, 호출 불가 모델은 그대로 표기한다. 비슷한 이름으로 조용히 대체하지 않는다. 모델 변경은 평가 완료 후 별도 결론으로 남긴다.

**데이터:** 과거 오류 경기와 검증된 솔로 샘플로 입력 사전 점검을 한다. 정식 비교는 검증된 모드별 최소 3경기, 모델당 경기별 3회로 구성한다. 가능하면 모드별 2개 이상 맵을 포함한다. 특정 모드의 실경기를 확보하지 못하면 그 모드는 미평가로 남기고 전체 지원·우열을 주장하지 않는다. 합성 fixture는 오류 검증용이고 실경기 수에 넣지 않는다.

**두 평가를 분리한다:** 운영과 동일한 ‘장면 ID 선택 → 검증 → 공개 문장’ 비교가 주 평가다. 자유 해설의 가능성은 같은 근거 묶음에서 문장별 근거 ID를 붙이는 별도 실험으로 평가한다. 두 출력 형식의 점수를 하나의 순위로 섞지 않는다.

**실행 조건:** 비교 내에서는 동일 입력·프롬프트·출력 한도와 공통 지원 생성 설정을 사용한다. 모델별 미지원 설정은 보고하고 동등 조건이라고 주장하지 않는다. 실행 순서는 라운드마다 순환한다. 각 시도마다 상태 코드, 최초·전체 지연, 재시도, 종료 사유, 토큰·캐시 토큰·모델 버전을 남긴다. 429/503/타임아웃에는 동일한 최대 3시도 정책을 쓰고, 내용 오류를 좋은 답이 나올 때까지 재호출하지 않는다.

**판정:**

- 입력에 정답 근거가 없으면 `input_missing`으로 분류한다. 모델 정확도 비교에서 해당 사례를 제외하고 입력 보완 후 모든 후보에 같은 입력으로 다시 실행한다.
- 원본 응답의 인물·팀·시각·무기·이벤트 종류 오류, 근거 없는 주장, 핵심 사실 누락을 각각 집계한다. 형식 오류·알 수 없는 근거 ID·호출 실패도 분모에서 숨기지 않는다.
- 최종 게시물의 중대한 사실 오류는 0건이어야 한다. 모델이 모두 거절되거나 고정 대체문만 사용돼 정확해 보이는 경우를 막기 위해 원본 채택률, 대체율, 장면 커버리지를 함께 보고한다.
- 장면 커버리지는 경기별 미리 검토한 필수 근거 묶음 중 게시 장면이 포함한 묶음의 비율이다. 선정·검증 과정에서 생긴 누락을 분리한다. 입력 없는 전술을 필수 정답으로 만들지 않는다.
- 읽기 쉬움·학습 유용성은 모델명을 숨긴 사람이 같은 기준으로 1~5점을 부여한다. 인간 평가가 없으면 해당 항목은 미평가이며 LLM 자체 점수로 대체하지 않는다.
- 중대한 게시 오류가 없는 후보 안에서 커버리지·가독성·대체율을 먼저 비교하고, 차이가 뚜렷하지 않으면 성공 게시물당 비용과 전체 지연을 본다. 과금 단가는 실행 시 공식 가격과 조회일을 기록한다. 표본이 작거나 평가가 미완료면 승자를 정하지 않는다.

결과물은 재현 가능한 입력 manifest, 모든 시도의 원본/검증/게시 출력, 오류별 집계, 비용·지연, 모델 유지 또는 교체의 근거다. 운영 모델을 자동으로 전환하지 않는다.

## 완료 기준과 현재 확인

- 지원되는 각 모드의 전날 경기 한 편이 독립 발행되고, 재실행·동시 실행·날짜 경계에서 중복이 없다.
- 기존 날짜 링크와 고정 샘플이 열리며 구버전 콘텐츠도 읽힌다.
- 장면 선택 시 지도·해설 시간이 일치하고, 근거 없는 위치·생존 인원·의도가 표시되지 않는다.
- 모바일 `375×667`, `390×844`, `430×932`와 데스크톱 `1280×720`에서 실제 화면을 확인한다. 키보드 장면 이동, 선택 상태, 터치 영역, 하단 메뉴 간섭, 빈 상태·오류·느린 지도 로딩을 포함한다.
- 기존 분석·근거 테스트와 새 회귀·발행·UI 검사를 통과한 뒤 모델 비교를 실행한다.
- 2026-09-27 준비 단계의 기준선: 기존 4개 테스트 파일, 22개 테스트 통과. 새 기능, 입력 보완, 모델 재평가가 완료됐다는 뜻은 아니다.

이번 준비에서 3D 복각, 별도 모델 라우터, 방문별 AI 생성, 개인 맞춤 비교, 퀴즈·음성 해설은 범위에 넣지 않는다.
