# 다른 플레이어 계산 갱신 — 기능별 적용 결과

## 집계 단위

- 개별 경기 계산: `match_id + platform + player_id` 한 건. 같은 경기의 플레이어 3명을 갱신하면 개별 계산은 3건이고 원본 경기는 1개다.
- 최근 10경기 AI 분석: 플레이어 화면에서 전달하는 최근 후보 최대 25개 중 유효한 최대 10경기를 선정한다. 코칭 근거는 그 안의 최대 5경기를 사용한다. 개별 계산 갱신과 AI 문장 생성을 구분한다.
- 스쿼드 분석: 같은 팀원 조합의 최근 최대 10경기에서 계산 완료 경기를 고르고 최대 5경기를 전술 분석에 사용한다. 개별 경기의 게임 모드가 squad라는 사실과 스쿼드 분석 보고서 생성은 다르다.

## 이번 운영 적용: 개별 경기 계산

최근 저장 후보 100건을 확인하고, Steam 스쿼드 모드의 실제 3경기에 참여한 다른 플레이어 7명의 개별 계산 7건을 갱신했다. 이들은 플랫폼·PUBG 닉네임 기준이며 사이트 회원 7명이라는 뜻은 아니다.

| 플레이어 | 경기 유형 | 갱신 개별 기록 | 내부 전술 점수 전 → 후 |
|---|---|---:|---:|
| gensalute1234567 | 경쟁전 스쿼드 | 1건 | 12.3 → 14.7 |
| taemin98 | 경쟁전 스쿼드 | 1건 | 48.9 → 51.2 |
| kdm56782 | 일반전 스쿼드 | 1건 | 58.0 → 58.3 |
| bigheadrich04 | 경쟁전 스쿼드 | 1건 | 20.6 → 20.0 |
| laatata | 경쟁전 스쿼드 | 1건 | 43.5 → 43.5 |
| y_moon97 | 일반전 스쿼드 | 1건 | 34.5 → 37.5 |
| 315hz | 일반전 스쿼드 | 1건 | 46.2 → 47.1 |

모든 대상은 기존 v73·모집단 증거가 있는 기록이며 계산 마커를 실제 재계산 후 v2로 바꿨다. 킬·피해량·순위·어시스트·기절 수는 공식 기본 기록과 동일하다. 내부 점수 변화는 미측정 종합 등급을 공개할 수 있다는 의미가 아니다.

공식 match 조회 3회, telemetry 다운로드 3회, telemetry 수신 65,116,348바이트. 원본은 같은 경기의 다른 플레이어 계산에서 재사용했다. raw/full projection/복원 후 계산 대조는 세 경기 모든 팀원에서 차이 없음. RPC 7회 성공, 저장 후 fullResult 목표 hash 및 benchmark 값 일치, 오류 0회. 삭제·R2 쓰기·Gemini 호출은 없다.

## 최근 10경기 AI 분석 영향

실제 `pubg_player_cache.recent_match_ids`에 저장된 각 20개 후보를 읽고, 기존 canonical만 대상으로 현행 selector의 선정 결과를 적용 전후 비교했다. 누락 원본을 자동 수집하는 API fallback이나 Gemini 호출은 하지 않았다. 따라서 이는 **현재 저장 데이터로 이용 가능한 근거 수**이며 생성된 AI 보고서 수가 아니다.

| 플레이어 | 유효한 최근 경기 수 전 → 후 | 코칭 후보 수 전 → 후 |
|---|---:|---:|
| gensalute1234567 | 0 → 0 | 0 → 0 |
| taemin98 | 0 → 0 | 0 → 0 |
| kdm56782 | 0 → 1 | 0 → 1 |
| bigheadrich04 | 0 → 1 | 0 → 1 |
| laatata | 0 → 1 | 0 → 1 |
| y_moon97 | 0 → 1 | 0 → 1 |
| 315hz | 0 → 1 | 0 → 1 |

앞의 두 플레이어가 갱신한 경기는 현재 최근 요청 목록 밖이다. 나머지 5명도 아직 10경기가 채워진 것이 아니며 각 1경기의 근거만 확보됐다. AI 요약 문장을 재생성하거나 요약 캐시를 강제로 삭제하지 않았다.

## 스쿼드 분석 영향

develop production build의 실제 `/api/pubg/squad-analyze`가 운영 DB를 읽은 응답을 전후 대조했다. 분석 대상은 이번 개별 기록의 같은 파티 그룹이다.

| 플레이어 | 해당 파티 최근 기록 수 | 계산 완료로 분석 가능한 경기 전 → 후 | 남은 재계산 대기 |
|---|---:|---:|---:|
| kdm56782 | 5 | 0 → 1 | 4 |
| bigheadrich04 | 2 | 0 → 1 | 1 |
| laatata | 4 | 0 → 1 | 3 |
| y_moon97 | 5 | 0 → 1 | 4 |
| 315hz | 5 | 0 → 1 | 4 |

위 5명은 해당 그룹의 기본 기록만 제공되던 상태에서 **1경기에 대한 팀 관측 지표를 제공 가능한 상태**로 바뀌었다. 스쿼드 AI 코칭 문장은 생성하지 않았다.

gensalute1234567·taemin98의 같은 파티 그룹은 각각 최근 10경기가 이미 존재하며, 갱신한 과거 경기는 그 범위 밖임을 별도 GET으로 확인했다. 이 두 명은 이번 갱신으로 해당 스쿼드 분석 입력이 바뀌지 않는다.

## 검증과 한계

- 배치·실행기·원본 제한 회귀 테스트 20개 통과. 이번 확장 과정에서는 제품 코드 변경 없음; 직전 전체 테스트 2,463개 및 production build 통과 상태를 사용했다.
- 입력 snapshot 전체 비교, 저장 후 재조회, 기본 기록 불변, 원본/필터링 산술 일치를 확인했다.
- 첫 보충 스쿼드 조회 중 Supabase 연결이 한 차례 ECONNRESET으로 실패했다. 완료된 7건의 쓰기·사후 검증은 성공한 상태였으며, 읽기 요청을 한 번 다시 실행해 파티 최근 10경기 제외 여부를 확인했다. 적용 실패나 재쓰기와 구분한다.
- 작업 시작 시 검증된 비교용 개별 기록은 4,805건(플랫폼·닉네임 708조합), 이 중 이전 계산 4,799건이었다. 전체 회원 수나 전체 AI 보고서 수가 아니다. 이번 적용은 그중 7건이다.
- 솔로·듀오·FPP·Kakao에 대한 이번 신규 적용은 없다. 모든 유저의 전체 과거 경기 갱신이 완료된 상태도 아니다.
- 코드 커밋·푸시·main 병합·배포는 하지 않았다. 운영 데이터 갱신과 develop의 UI/API 변경 배포는 별개다.

## 다음 배치의 우선순위

최근 저장 시각만으로는 갱신 대상이 현재 분석 화면 범위에 들어가는지 알 수 없다. 다음 후보는 실제 최근 요청 목록 포함 여부, 같은 파티 최근 10경기 포함 여부를 먼저 확인하고, 현재 화면의 유효 근거가 늘어나는 기록을 우선한다. 그 외 과거 기록은 개별 경기 조회 개선으로 구분해 처리한다. 원본 보관·제공 여부와 기존 canonical/benchmark 검증은 계속 필요하다.

검증 산출물은 git 제외 tmp의 `calculation-upgrade-other-users-prepared.json`, 그 checkpoint, `calculation-upgrade-others-before.json`, `calculation-upgrade-others-after.json`, `calculation-upgrade-others-window-exclusion.json`에 보관한다. 원본과 서버 비밀키는 커밋하지 않는다.
