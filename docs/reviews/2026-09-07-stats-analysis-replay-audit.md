## 중복·성능 개선 방향

1. **현재 반영:** 중복 경기 ID 제거로 API 슬롯과 경기 수 정상화, 알려진 이전 계산의 내부 재조회 중단, terminal 재시도 차단. 스쿼드의 요청 공유/60초 재사용과 개인 benchmark 조회 제거를 유지한다. Canvas는 전체 위치 이벤트를 매 프레임 순회하지 않고 효과 이벤트를 미리 추린다.
2. **다음 우선순위:** 3D 장면 생성과 표시 옵션 갱신을 분리한다. 현재 궤적/적 표시/고도 변경 시 장면 재생성과 타일 이미지 16개 요청이 다시 생길 수 있다. 타일 캐시·장면 유지·geometry 변경을 분리하고 요청 수·프레임 시간·GPU 메모리를 전후 측정해야 한다. 일부 플레이어는 마지막 위치가 비행 중인 채 후속 관측이 없어 공중 위치와 긴 수직 가이드가 남는다. 마지막 위치를 현재 위치처럼 보지 않도록 관측 시각/신선도 표시와 종료 조건을 추가 검토해야 한다. 보급상자 연기도 지도 폭100에 높이50의 원기둥으로 표현되어 시각적으로 크므로 표시 크기와 지속 시간을 별도 조정할 필요가 있다. 이번에 실제 FPS 향상을 측정한 것은 아니다.
3. **다음 정확도 작업:** 엄호 집계, 집중사격 기준 보정, 팀 전체 거리/전멸 정의를 원본 기회·분자·분모 계약부터 검증한다. 구현 전에 0이나 등급으로 대신하지 않는다. 다양한 맵·리콜/부활·투척 이벤트를 추가 원본으로 대조한다.
4. **점진 이행:** 과거 6,665개 benchmark를 현버전으로 바꾼 것은 아니다. 원본과 정식 identity가 있는 실제 수요 경기부터 작은 배치로 갱신한다. 이전 계산만 있는 상세/AI는 대기하고 기본 전적은 제공하므로, 전면 활성화 전에 대기 비율·회복 속도를 확인해야 한다. 일괄 Gemini 재생성은 필요하지 않다.
5. **리팩터링 범위:** 2D·3D의 시간/생명주기 등 순수 규칙은 공통 검증 가능 helper로 분리한다. Leaflet과 Three의 좌표·자원 관리까지 무리하게 하나로 합치지 않는다. 과거 renderer 파일은 실제 참조 여부 확인 후 별도 정리하며, 이번에는 중복 미사용 import만 제거했다.

## 반영 상태

- develop에 기능별 한글 커밋으로 기록했다. 운영에는 추가 schema와 검증된2개기록만 반영했다. 전면 앱 배포·main 병합은 이 감사에서 하지 않는다.
- 이유: 이전 계산만 가진 사용자의 상세/AI 대기 비율이 높을 수 있다. 적격 기존 비교4,711건의 원본 보유·갱신 가능성·수요 순서를 정하고 점진 이행해야 한다. CI 통과와 전체 사용자의 데이터 이행 완료는 서로 다른 조건이다.
