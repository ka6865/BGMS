# 전적 목록 기절·생존 기본 기록 보강

> 후속 상태: 최종 리뷰에서 발견한 raw 조회 컬럼 오류와 재수집 NULL 덮어쓰기 문제를 수정했다. [수정 및 재검증 보고서](2026-09-08-release-fixes-verification.md)에 최신 결과를 기록했다.

2026-09-08 develop 로컬 구현. 연결된 BGMS DB에는 호환 가능한 nullable 컬럼 추가와 기존 기록 보완을 적용했다. 앱 커밋·푸시·운영 배포는 수행하지 않았다.

## 변경

- `pubg_player_matches`에 `knocks`, `survival_time`을 nullable integer로 추가했다. 생존 시간은 PUBG participant의 `timeSurvived`를 초 단위로 내림 저장한다. 실제 0을 보존하며 누락·음수·비정상 값은 NULL이다.
- 기본 경기 수집, 개별 분석 후 기본 기록 저장, R2 복원 스크립트가 두 필드를 저장한다. 이번 작업에서 R2 복원 스크립트는 실행하지 않았다.
- 기존 목록·요약 SELECT에 두 필드를 포함한다. 정상 목록 조회의 요청 개수는 추가하지 않았다. **후속 최종 리뷰에서 raw fallback에 추가한 `survival_time`은 실제 테이블에 없는 컬럼임을 확인했다. 이 경로의 조회 실패 및 누락 입력의 NULL 덮어쓰기 문제는 배포 전 수정이 필요하다.** [최종 리뷰](2026-09-08-final-predeploy-review.md)를 참조한다.
- 기존 `MatchData`의 숫자 자리표시자와 관측 여부를 구분하기 위해 기본 요약에 `basicStats`를 전달한다. 목록은 확인된 수치만 표시하고 없는 값에는 ‘일부 기본 기록이 저장되지 않은 경기입니다’라는 안내를 추가한다.
- 최근 20경기 요약도 기본 전적에서 확인된 기절 수를 합산한다. 기록 누락이 있는 합계를 0으로 추정하지 않는다. 어시스트 수집 범위는 그대로다.
- 상세 분석은 사용자가 펼칠 때 요청하는 기존 동작을 유지한다. AI·텔레메트리 계산식·요약 캐시 버전은 이번 변경으로 바꾸지 않았다. 직전 Gemini 응답 형식 실패는 별도 이슈다.

## DB 적용

마이그레이션: `supabase/migrations/20260908103306_player_match_basic_combat_stats.sql`. CLI로 파일을 생성하고 연결 DB에 적용한 실제 migration version에 맞춰 파일명을 정렬했다. 기존 인덱스·RLS·공개 정책 변경은 없다. 기존 앱은 새 nullable 필드를 사용하지 않아 계속 동작할 수 있다.

전체 기본 기록 35,872건 중 저장 분석과 플레이어·플랫폼·경기 ID 및 플레이어 이름이 일치하는 14,563건의 누락 필드를 보완했다. 기존 값은 덮어쓰지 않았고 삭제는 없었다. 재실행 가능한 SQL은 `scripts/backfill_player_match_basic_stats.sql`이다. PUBG 조회·원본 텔레메트리 다운로드·Gemini 호출 없이 저장 DB만 사용했다.

보완 직후 조회에서 14,563건에 두 값이 저장된 것을 확인했다. 나머지 21,309건은 이번 저장 분석 기반 보완으로 채워지지 않았다. 이를 0으로 변경하지 않으며 기존 기록이 전부 복원됐다고 해석하지 않는다. 새 수집/재수집부터 두 필드를 저장한다. 두 정수의 추가 공간은 행당 최대 8바이트 수준이지만 테이블 갱신의 WAL·dead tuple 등 실제 총 용량 증가는 별도로 측정하지 않았다.

- Steam KangHeeSung_ 목록 API 20건 중 18건에 기절·생존 값이 포함됐다. 2건은 NULL로 남았다.

- 새 브라우저에서 목록 20개, 펼쳐진 상세 0개, `/api/pubg/match?` 요청 0건 확인.
- 모바일 375×667, 390×844, 430×932에서 표시·줄바꿈·접힘 상태를 확인했다. 확인한 375/430 화면의 문서 가로 넘침은 없었다. 실제 휴대폰 검증은 아니다.
- 브라우저 콘솔 오류 조회에 오류가 없었다. 서버는 `http://localhost:3000`에서 유지한다.

## 코드 검증

관련 7파일 106테스트 통과. 프로덕션 빌드 및 TypeScript 통과. 변경 파일 ESLint 오류 0건이며 기존 persist 모듈의 미사용 함수 경고 3건이 있다.

첫 전체 테스트는 빌드와 동시 실행 중 3건 timeout 및 UI 타이밍 실패 2건이 있었다. 이후 로컬 디스크 부족으로 재실행도 실패해 이번 작업 폴더의 재생성 가능한 `.next/cache` 287MB를 정리하고 동시 worker 수를 2개로 제한해 재검증했다. 사용자 소스·전적 자료와 실행 중인 개발 서버의 `.next/dev`는 삭제하지 않았다.

최종 전체 Vitest: `npx vitest run --maxWorkers=2` → 210파일 통과/5파일 건너뜀, **2,561개 통과/76개 건너뜀**. 마지막 `git diff --check` 통과.
