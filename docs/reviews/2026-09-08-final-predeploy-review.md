- 기절·생존 nullable 컬럼 마이그레이션은 연결 BGMS DB에 이미 적용됐다. 기본 기록 35,872건 중 14,563건을 저장 분석으로 보완한 것은 이전 작업이며, 전체 기록 복원 완료는 아니다.

## 배포 전에 수정할 항목

### P1 — 개별 전적 목록: 존재하지 않는 DB 컬럼 때문에 원본 기록 조회 실패

위치: `app/api/pubg/matches-summary/route.ts:83`.

새 SELECT가 `match_stats_raw.survival_time`을 요청하지만, 실제 연결 DB의 information_schema 조회에서 이 컬럼은 없었다. 새 마이그레이션은 `pubg_player_matches`에만 두 컬럼을 추가한다.

처리된 분석과 기본 전적 테이블에 없고 raw 테이블에만 있는 경기에서 기존 정상 조회가 실패한다. 쿼리 오류를 검사하지 않아 최대 5건의 공식 API 재조회로 넘어가며, API에서 더 이상 받을 수 없거나 조회 상한을 넘긴 경기는 저장된 기록이 있어도 요약 응답에서 누락될 수 있다. 서버 호출도 불필요하게 늘어난다.

수정: raw SELECT에서 지원하지 않는 컬럼을 제거하고, 실제 스키마와 맞는 컬럼만 조회한다. DB 모킹이 존재하지 않는 컬럼도 허용해 놓친 사례이므로 컬럼 계약 검사를 추가한다.

### P2 — 개별 전적 저장·복원: 누락 응답이 기존 기절·생존 수치를 지움

위치: `lib/pubg/playerMatchesIngest.ts:180`, `lib/pubg-analysis/persistMatchAnalysis.ts:515`, `scripts/backfill_pubg_player_matches_from_r2.ts:104`; 공통 저장은 `lib/pubg/playerMatches.ts:59`.

API 또는 과거 저장 데이터에 DBNOs/timeSurvived가 없으면 새 저장 경로가 두 값을 명시적 NULL로 만든다. 동일 플레이어·플랫폼·경기에 일반 upsert를 하므로 기존에 관측한 정상 값도 NULL로 덮어쓴다. 누락 입력으로 실제 생성되는 upsert payload를 오프라인 재현했다. 운영 데이터에 이 손실이 이미 발생했다고 확인한 것은 아니다.

사용자는 재분석·복원 후 보이던 기절/생존 수치가 다시 미확인으로 바뀔 수 있다. 실제 0과 미관측을 구분한 개선도 유지되지 않는다.

수정: 유효한 관측값만 기존 값을 갱신하고, 누락 입력에서는 기존 값을 보존한다. 첫 저장의 미관측은 NULL, 관측한 0은 0으로 유지한다. 기존 값이 있는 행에 누락 응답을 재수집하는 회귀 사례를 검증한다.

### P2 — 최근 최대 10경기 AI 토론·개별 경기 AI: 정상적인 부정문을 잘못 수정

위치: `lib/pubg-analysis/aiSummaryJudgment.ts:49-62`.

직접 재현한 입력 `교전 참여 빈도를 높여야 하는 것은 아닙니다.`와 `교전 참여 빈도를 높여야 할 필요는 없습니다.` 모두 부적절한 조언으로 탐지되어 일반적인 교전 후 점검 문장으로 교체된다. 정규식이 `높여`까지만 소비하고 부정 예외가 남은 `야 하는 것은 아닙니다`를 처리하지 못한다. 앞서 고친 `교전 횟수를 늘려야 하는 것은 아닙니다.`는 정상 보존되지만 높여야 변형은 남아 있다.

사용자는 AI가 올바르게 작성한 측정 한계 설명을 잃고, 해당 문장이 카드 의견에 있으면 원문 기반 조언 검사 때문에 승자도 보류될 수 있다. 이 재현만으로 전체 결과가 반드시 캐시 실패한다고 주장하지 않는다.

수정: 동사 어미를 포함해 부정 범위를 검사하고, 위 두 문장 및 실제 권고 문장을 함께 회귀 검증한다. 생성 결과 정규화와 캐시 재조회에서도 의미를 보존하는지 확인한다.

개별 경기 AI에도 같은 유형의 새 예외가 있다. `lib/pubg-analysis/matchAiEvidence.ts:37-38`은 actionItems.desc의 `소생 소요 시간을 줄여야 한다는 뜻은 아닙니다.`를 실제 소생 시간 단축 권고처럼 처리해 다른 점검 문장으로 바꾼다. 해당 정책 함수로 직접 재현했다. 최근 10경기 토론과 별도 경로이므로 두 정제기를 각각 보강해야 한다.

최근 요약 캐시 버전은 v18이다. 배포 후 새 키로 최초 Gemini 생성이 필요할 수 있으며, 일괄 캐시 삭제나 전 사용자 모델 재호출을 시행한 것은 아니다.

## 별도로 남아 있는 실제 AI 오류

사용자가 확인한 `AI summary provider is temporarily unavailable`에 대해 로컬 서버 로그는 `No valid JSON extracted from AI response`였다. 현재 오류는 파싱 실패와 카드 계약 불일치를 같은 메시지로 묶어 실제 원인을 더 구분할 수 없다. 무료 티어 제한이나 429였다는 근거는 없다.

해당 실패 처리 구조는 main에도 있어 이번 차이로 새로 생긴 회귀로 분류하지 않는다. 실패 결과는 캐시하지 않지만 사용자에게 분석 결과를 못 주는 문제는 남는다. 형식 실패 원인 분류, 제한된 형식 재시도, 사용자 안내 개선은 아직 구현되지 않았다. 앞선 세 사용자 성공 검증이 이 간헐적 실패가 사라졌다는 뜻은 아니다.
