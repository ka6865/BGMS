## 이번에 수정한 내용

- 같은 요청의 사용량·오류 로그를 한 요청으로 합치고 실패 결과를 우선한다. 저장 비용과 토큰 합계는 보존한다. 요청 ID가 없는 레거시 로그는 합치지 않는다.
- 전역 관제와 회원별 요청/실패 집계에 같은 정규화를 적용한다. 평균 응답은 동일 요청 로그의 가장 긴 시간을 사용한다.
- 과거 unknown 로그를 메시지 기반으로 분류하고, 앞으로 기록되는 내용 검증 실패도 `validation`으로 분류한다.
- 상위 AI 사용자 목록을 24시간/7일 각 기간의 요청과 함께 계산한다.
- PUBG 429를 호출 제한으로 분류하고 주요 404 코드에 한국어 설명을 붙인다. 오류 총건수는 보존한다.
- 특정 오류 필터 결과가 비었을 때 최근 오류 영역에도 빈 상태를 표시한다.
- 비용을 저장된 추정값으로, AI 사용률을 활동 회원 대비 비율로 설명한다.

## 실제 오류 감소를 위한 후속 수정 우선순위

1. **모델별 비용 계산과 사용량 기록 수명주기**: 현재 `aiUsageTracker.ts`의 고정 단가를 모델별로 바꾸고, summary가 최종 결과 확정 전에 성공을 기록하는 흐름을 정리한다. 실패한 응답도 사용한 토큰은 비용으로 보존해야 한다. 이번 변경은 관리자 집계의 중복을 바로잡았으며 원본 로거의 두 줄 기록 구조는 유지한다.
2. **AI 검증 실패 진단**: 실패 규칙, 모델 이름, provider finish reason, 출력 길이, 요청 ID를 안전하게 기록한다. 현재 체크아웃에는 과거 `AI card interpretation did not pass validation`을 발생시키던 분기가 없어 당시 배포 버전과의 대조가 필요하다. 검증 조건을 낮추거나 실패를 성공으로 바꾸는 방식은 적용하지 않았다.
3. **매치 조회 중복 방지**: 현재 match route의 404 음성 캐시는 프로세스 내부 Map이므로 동시 요청과 서로 다른 서버 인스턴스 전체를 막지 못한다. 호출부에서 같은 플랫폼·매치에 대한 진행 중 요청을 공유하는지와 summary/detail 동시 조회를 먼저 재현한다. 404 이유가 확정되기 전에는 장기 공유 캐시로 확장하지 않는다.
4. **PUBG 429 및 scraper 참가자 불일치**: 전적 조회의 병렬 normal/ranked 요청과 갱신 요청 제한을 확인하고, scraper의 매치·닉네임 연결을 계정 ID와 대조한다.
