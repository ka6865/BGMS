# 세 명의 개별 경기·최근 10경기·스쿼드 AI 검증

2026-09-08 develop 로컬 기준. 직전 main 대비 리뷰의 두 결함과 실제 생성 응답에서 추가로 확인한 문제를 수정했다. 최종 프로덕션 빌드와 응답 검증을 통과했다. 커밋·푸시·PR·운영 배포는 이번 작업에서 수행하지 않았다.

## 대상과 실제 분석 범위

운영 DB의 저장 경기 분석 176건과 비교 기준 143건을 2026-09-08 18:41 KST에 읽었다. 현재 계산 버전과 경기 자격 검사를 통과한 기록을 실제 서비스 선택 함수에 전달했다. 개별 경기와 스쿼드는 착한맛·매운맛을 각각 검증했다. 최근 10경기 토론은 한 응답 안에 양쪽 코치 의견이 있다.

| Steam 닉네임 | 개별 경기 | 최근 최대 10경기 토론 | 스쿼드 분석 |
| --- | --- | --- | --- |
| KangHeeSung_ | 미라마 듀오 경쟁전, 7킬·피해량 846·3위 | 최근 10 → 점수 상위 5 → 듀오 경쟁전 4경기 | 동일 팀원 구성 5경기 중 5경기 |
| MiaeQ_Q | 미라마 듀오 경쟁전, 1킬·피해량 245·3위 | 최근 10 → 점수 상위 5 → 듀오 경쟁전 4경기 | 동일 팀원 구성 2경기 중 2경기 |
| What12_9oing_on | 태이고 스쿼드 일반전, 0킬·피해량 374·6위 | 최근 10 → 점수 상위 5 → 스쿼드 일반전 4경기 | 동일 팀원 구성 최근 10경기 중 점수 상위 5경기 |

무작위 대상은 저장된 Steam 유저 중 인벤토리 10건 이상인 237명을 섞고, 현재 유효 경기 10건 이상 및 스쿼드 기록이 있는 첫 대상을 선택했다. 첫 후보가 조건을 만족해 제외 대상은 없었다. PUBG 전체 유저에서 무작위 추출한 것은 아니다.

KangHeeSung_과 MiaeQ_Q의 개별 검증 경기는 같은 경기이며 저장 자료의 최신 유효 경기 시각은 9월 7일 01:26 KST다. What12_9oing_on은 9월 4일 02:00 KST다. PUBG의 현재 최신 전적 목록이나 원본 텔레메트리를 다시 내려받아 재계산한 검증은 아니다.

‘10경기’는 후보 범위다. 실제 비교는 선별 후 동일 모드·매치 유형으로 구성한 4경기에서 이뤄진다. 지표별 관측 경기 수도 따로 확인했다. 예를 들어 KangHeeSung_과 MiaeQ_Q의 백업 시간은 각각 4경기 중 성공 사례가 있는 1경기에서 확인되며, 이를 4경기 모두 측정한 시간으로 표시하지 않는다.

KangHeeSung_과 MiaeQ_Q의 스쿼드는 같은 팀원 구성이지만 각 유저의 저장 경기 범위가 달라 5경기와 2경기를 사용한다. 서로 다른 표본이므로 팀 합계도 달라지는 것이 맞다.

## 수정한 문제

| 적용 영역 | 발견한 문제 | 수정 후 |
| --- | --- | --- |
| 최근 10경기 토론 | ‘높은 집중력을 의미하지 않습니다’, ‘교전 횟수를 늘려야 하는 것은 아닙니다’처럼 정상적인 한계 설명도 삭제 | 확인된 부정·한계 표현을 보존하고 회귀 테스트 추가 |
| 최근 10경기 토론 | 카드 판정을 보류해도 상단 최종 의견에는 ‘착한맛 승’이 남음 | 보류·혼합 카드가 있으면 검증된 카드 의견·평가로 최종 의견을 다시 구성 |
| 최근 10경기 토론 | 실제 생성에서 평균 피해량을 ‘분포가 안정적으로 유지’, 결과 지표를 ‘집중력 유지’로 확대 해석 | 해당 추론을 제거하고, 근거 없는 의견만 남으면 해석을 거절하는 기존 정책 유지 |
| 스쿼드 분석 | 개인 조언을 정리하는 순서 때문에 첫 응답과 캐시 재조회 문구가 달라짐 | 공통 정리 후 개인 행동 근거를 검사해 최초·캐시 결과를 동일하게 유지 |
| 개별 경기 | What12_9oing_on의 1:1 승률 75%와 선제 공격률 60%를 ‘높은 집중력’으로 해석 | 해당 문장을 ‘관측된 1:1 교전 4회 중 3회 승리했습니다’로 정리 |
| 개별 경기 | KangHeeSung_의 복수 처치 시간에서 ‘소생 소요 시간 단축’을 권고 | 소생 시간 측정으로 해석하지 않고 적 제압 후 아군 상태·소생 가능 여부를 확인하는 조언으로 변경 |

`tradeLatencyMs`는 아군 기절부터 복수 처치까지의 시간이다. 소생 횟수는 있어도 소생 소요 시간은 측정하지 않으므로 두 의미를 혼동하지 않도록 했다. 발견된 표현에 대한 제한된 보강이며, 모든 자연어의 사실성을 자동으로 보증하는 구현은 아니다.

최근 요약 캐시 버전은 `2026-09-08.debate-verdict-consistency-v18`이다. 개별·스쿼드 변경은 기존 캐시를 읽을 때도 같은 정책을 적용한다. 운영 캐시 일괄 삭제, 저장 경기 재계산, 추가 DB 조회를 도입하지 않았다.

## 실행·검증 증거

- 실제 모델: `gemini-3.5-flash-lite`, 총 18회 호출. 최초 15회와 요약 문구 정책 보강 후 최근 10경기 토론 3회 재생성이다. 제공자 호출 오류는 없었다.
- 실제 사용량 합계: 입력 50,934 / 출력 9,130 / 전체 60,064 토큰. 이번 검증에서 관측한 사용량이며 비용 개선 수치가 아니다.
- 최종 개별·스쿼드 12개와 마지막 요약 3개, 총 15개 실제 응답을 최신 운영 라우트의 후처리에 다시 통과시켰다. 캡처 응답의 프롬프트·시스템 지시가 현재 요청과 같은지도 검증했다. 15/15 정상 최종 응답, 15/15 캐시 재조회 일치. 재생 검증은 추가 모델 호출 없이 수행했다.
- 최초 검사에서 개별 응답을 문자열로 기대한 테스트 오류와 메모리 캐시 mock의 체인 누락을 발견·수정했다. 이는 운영 API 오류로 집계하지 않았다. 별도로 실제 스쿼드 문구 재조회 차이를 수정했다. 최초 응답 전체가 처음부터 의미 검증을 통과했다고 해석하면 안 된다.
- 새 요약 제한 정책으로 최초 What12 요약의 근거 없는 단독 의견이 거절되는 것을 확인한 뒤 세 명의 요약을 실제 재생성했다. 최종 보고서는 이 마지막 응답을 사용한다.
- 전체 Vitest: 210파일 통과 / 5파일 건너뜀, 2,545테스트 통과 / 76개 건너뜀. 실제 호출 테스트는 기본 전체 실행에서는 opt-in으로 건너뛰고 별도로 실행했다.
- 최종 `npm run build`: 성공. TypeScript 빌드와 정적 페이지 98개 생성 성공. 별도 `tsc --noEmit`, 변경 코드·테스트 ESLint 및 `git diff --check` 통과.
- 실제 생성 자료: `tmp/three-user-validation/final/report.json`, `summary-final/report.json`. 최종 재생 결과: `verified/report.json`. 재현 테스트: `tests/three-user-ai-real.integration.test.ts`. 원본 프롬프트·경기 자료가 포함된 임시 파일은 공개 문서에 복사하지 않았다.

인증, 운영 DB 질의 실행, 캐시 저장 및 사용량 저장은 평가에서 메모리로 분리했다. 데이터 입력과 모델 생성은 실제이며 계산·선택·응답 라우트는 제품 코드를 사용했다. 운영 환경의 인증·DB 쓰기·네트워크 상태까지 확인한 배포 후 E2E 검사는 아니다. 이번 작업에서 브라우저 상호작용 검사를 새로 실행하지 않았다.
