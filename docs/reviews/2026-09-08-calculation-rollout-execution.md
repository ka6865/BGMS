# 과거 경기 계산 갱신과 기본 기록 보존

## 적용 범위

개발 경로의 develop에서 작업했다. 운영에는 검증된 기존 경기 2건의 재계산 결과만 적용했다. 코드 커밋·푸시·main 병합·배포 및 신규 마이그레이션 적용은 이번 작업에 포함하지 않았다.

- 단일 경기: identity가 맞고 population evidence가 있는 v73 구 계산 결과는 HTTP 200 `analysisAvailability: basic_only`로 공식 참가자 기록을 제공한다. 킬·피해량·순위·어시스트 등만 허용 목록으로 복사한다. 이전 점수, 전술 지표, 가공 피해량, AI 문장, 원인 장면과 canonical 버전 마커는 전달하지 않는다.
- 화면: 기본 경기 기록과 재계산 필요 안내, 2D 리플레이 진입을 제공한다. 기존 접힌 카드에 남은 전술 근거도 덮어 섞지 않는다.
- 스쿼드: 구 계산 경기도 함께한 팀 목록에서 유지한다. 최신 10경기 안의 계산 완료 경기만 전술 분석 후보로 사용한다. 모두 미완료라면 내 기본 경기 기록을 제공하고 AI 생성은 보류한다. 혼합 시 제외 경기 수를 알린다.
- AI: 구 계산 단일 경기와 기본 기록만 있는 스쿼드는 Gemini 호출 전에 차단한다. 최근 경기 요약도 basic-only fallback을 전술 입력으로 인정하지 않는다. 계산 완료 경기의 기존 코칭 경로는 유지한다.
- 랭킹: 공식 킬·피해량 조회에서 계산 버전 일괄 제한을 제거한다. human BR 모집단, 경기 유형 필터는 유지한다. 구 계산의 등급은 표시하지 않고, 점수 기반 티어 랭킹은 계속 계산 v2만 사용한다. 랭킹 서버 캐시 키도 갱신한다.
- 배틀: 같은 수의 최근 기록으로 기본 킬·피해량을 비교한다. 비교 구간에 구 계산이 포함되면 전술 지표와 등급을 보류한다. 미관측 값을 0으로 만들거나 무승부 수에 더하지 않는다.

v72와 잘못된 identity/모집단 등 다른 계약의 복구 규칙은 그대로다. 이 변경은 전 경기 자동 갱신이나 작업 큐를 뜻하지 않는다. 엄호 지표의 공개 평가와 종합 등급 보류 정책도 유지한다.

## 실제 운영 갱신

기존 로컬 원본 2경기는 MiaeQ_Q의 canonical 계산이 이미 v2였다. 이를 재작성하지 않았다. 신규 원본을 확보해 아래 기존 steam/KangHeeSung_ canonical과 benchmark를 갱신했다.

| 경기 | 기본 기록 | 내부 전술 점수 변경 | 결과 |
|---|---|---|---|
| 08c29ff1-4f08-4df0-a6d0-b3f8319e6064 | 3킬 / 피해 616.1317 / 2위 | 72.1 → 71.8 | calc2 저장·재조회 일치 |
| 61fb7fc0-5d36-4706-b0a8-a4297f5f7ba6 | 0킬 / 피해 120.90126 / 10위 | 25.9 → 29.0 | calc2 저장·재조회 일치 |

이는 내부 계산 변경 확인 값이며, 미측정 종합 등급을 공개해도 된다는 근거가 아니다.

공식 match 조회는 탐색 1회와 저장 대상 2회, 원본 telemetry 다운로드는 2회였다. 총 로컬 입력은 43,063,020바이트다. 원본/분석용 full projection/복원 후 주요 계산 차이는 두 경기 모두 없었다. 구 R2 지도 projection을 원본으로 사용하지 않았다. Gemini 호출·R2 쓰기·삭제는 0회다.

첫 RPC는 false를 반환했고 배치가 즉시 멈췄다. 조사 결과 prepare가 benchmark의 5개 열만 읽어 SQL의 전체 row snapshot 비교와 불일치했다. 당시 DB 값은 변경되지 않았다. `SELECT *`와 필수 snapshot 필드 사전 검증을 추가했다. 새 manifest의 fullResult/benchmark가 현재 DB와 일치함을 확인한 뒤 RPC 2회로 2경기(각 processed + benchmark)를 갱신했다. 저장 직후 목표 결과 전체 hash와 benchmark 필드를 대조했다.

같은 manifest를 새 checkpoint로 재실행했을 때 두 결과는 이미 목표와 같아 DB 조회만 수행하고 RPC 쓰기 0회로 끝났다. 배치 완료 수와 실제 write attempt 수는 구분한다.

보관된 기존 경기 전체가 갱신된 것은 아니다. KangHeeSung_ 76개 후보 점검 당시 준비된 2건 외에 canonical 누락 45건, benchmark 누락 5건, catalog 원본 미확인 22건, 이미 최신 2건이 있었다. 원본 미확인은 영구 소실을 뜻하지 않는다. 기존 canonical/benchmark가 없는 행은 이 갱신 도구로 새로 만들지 않는다.

## 확인

- 최종 전체 Vitest: 2,463 통과 / 59 제외. 배치 snapshot 검증·원본 다운로드 제한 회귀 테스트까지 포함한다.
- Next production build 및 TypeScript 통과.
- 실제 운영 DB를 읽는 로컬 API: 새로 갱신한 2경기, 기존 MiaeQ_Q v2 경기, 구 계산 KangHeeSung_ 경기 모두 HTTP 200. 구 계산 경기에는 기본 기록만 반환된다.
- 두 사용자 스쿼드 목록 HTTP 200. 실제 배틀 API도 기본 비교를 반환하고 구 계산 전술 지표 8개를 보류한다.
- 실제 Next 화면 + 고정 API 응답: 단일 경기/스쿼드 375×667, 390×844, 430×932, 768×1024, 1280×720. 상세 1회/스쿼드 목록·상세 각 1회 요청, AI 요청 0회, 가로 넘침 및 JS 오류 없음.
- 최신·구 계산이 섞인 실제 KangHeeSung_ 스쿼드 응답으로 5종 뷰포트에서 제외 경기 수 안내 확인.
- 실제 배틀 API 응답으로 모바일 3종/데스크톱 화면 확인. 랭킹도 같은 뷰포트에서 점검했다. 실기기 Safari 검증은 포함하지 않았다.
- 원본·manifest·checkpoint·실제 API 결과는 git 제외 tmp에 보관한다. 원본이나 서버 비밀키는 커밋하지 않는다.

배포 전 별도 잔여 항목: 관리자 기간 조회 경합 수정·가입/탈퇴 migration 운영 적용·새 AI 프롬프트 실제 소량 호출·최신 커밋 CI/배포 확인. 기존 배포 준비 검토에서 이 항목들은 여전히 미완료다.
