# 메타무기 패치 전 자료 보존·참고 집계 복구

## 범위와 결과

전적 개별/10경기/스쿼드 분석이 아니라 `/weapons`의 패치 전후 메타무기 리포트 변경이다. 사용자는 과거 표본을 보존하고 재검증이 불가능하면 기존 데이터를 사용하도록 요청했다.

현재 설정은 패치 42.3, 시작 2026-08-12 12:00 KST, 패치 전 14일이다. 현재 검증 표시가 없는 과거 표본이 strict 조회에서 제외되어 0개로 보였고, 수집 현황은 REST 1,000행 제한으로 530개만 계산되고 있었다.

실제 확인 결과:

| 종류 | 패치 전 참고 표본 | 패치 후 현재 검증 표본 |
|---|---:|---:|
| 전체(일반전+경쟁전) | 1,086 | 4,995 |
| 일반전 | 636 | 2,882 |
| 경쟁전 | 450 | 2,113 |

단위는 `(match_id, platform, player_id)`별 경기다. 패치 전 비교 기간 내 총 보관 1,123개 중 경기 유형 미확인 37개는 보관하되 비교에서 제외한다. 전체 패치 전 보관 자료는 기간 밖을 포함해 1,958개 무기 행 / 1,179개 플레이어 경기다.

## 원본 확인과 보존

- 1,123개 표본에 해당하는 1,037개 고유 경기 모두 DB에 과거 분석 결과와 master 경로가 남아 있다. 현재 provenance marker가 기록된 과거 분석은 0개다.
- master 경로는 모두 `telemetry-map/` v60이다. 실제 파일 3개를 읽어 지도 재생용 envelope임을 확인했다.
- 연결된 경로의 `_analyze.json` 원본 후보 1,037개를 R2 HEAD로 확인: 존재 0, 404 1,037, 조회 오류 0. 저장소의 알려지지 않은 모든 다른 경로를 전수 조사했다는 뜻은 아니다.
- 현재 연결된 근거만으로 현재 검증 완료 표본으로 올릴 수 없어, 기존 수치를 `legacy_reference`로 제공한다. 원본 수치나 provenance marker를 덮어쓰지 않았다.
- 과거 전체 1,958행을 `backups/weapon-meta/pre-42.3-79adb0b745738a80.json`에 압축 백업하고 다운로드 후 SHA-256 일치를 확인했다.
- 원문 SHA-256: `79adb0b745738a8074c4561a42190c6b3217917f231c61276c559082debea5ce`
- `backups/`는 기존 R2 삭제 가드 보호 대상이다. 핵심 테이블 백업 목록에도 `weapon_meta_match_samples`를 추가했다. 정기 실행에 이 변경이 반영되는 것은 코드 배포 이후다.

## 구현

- migration `20260909162204_weapon_meta_report_preserve_legacy.sql` 운영 DB 적용: read-only `get_weapon_meta_report` 추가. 기존 strict comparison RPC와 AI/benchmark gate는 유지한다.
- `baseline=auto`: 현재 검증된 pre 표본이 없을 때만 이전 기준 pre 자료 선택. `verified`와 `legacy`를 명시적으로 고를 수 있다. 두 자료를 같은 pre 집계에 합치지 않는다. post는 현재 검증 표본만 사용한다.
- DB 내부에서 전체 표본의 무기·일별·카테고리·수집 현황을 같은 statement snapshot으로 집계한다. REST 행 상한으로 일부 표본이 잘리는 경로를 없앴다.
- 이전 기준 참고 자료의 수치는 보여주되 검증 기준이 다른 전후 자료에 증감/상승/하락 판정을 붙이지 않는다.
- 빈 기간은 collecting/자료 없음으로 표시한다. 드문 무기의 채용률이 반올림되어 0.0%여도 raw active count가 있으면 피해 기록을 숨기지 않는다.
- 수집 완료는 플레이어 경기의 모든 무기 행에서 첫 1초/지속 명중/지속 교전 수가 모두 측정된 경우다. 기존 첫 1초 값만으로 완료 처리한 것과 다르다. 실제 전체 완료 수는 pre 780/1086, post 477/4995다. 이는 경기 성과 점수가 아니라 지표 보유 상태다.
- 공개 메타 응답만 60초 CDN 캐시 +120초 stale revalidation. 별도 Gemini/PUBG 호출은 없다.

## 검증

- 관련 Vitest 12개 파일, 47개 테스트 통과. 대상 ESLint 경고·오류 0, TypeScript 및 최종 production build 통과.
- 실제 DB rollback fixture `tests/fixtures/weapon-meta/report-rollback.sql`: 1,005개 표본 집계, 무기 중복 분모, 부분 측정, unknown 제외, legacy/verified 자동·명시 선택, 기존 strict RPC 불변, 일반 회원/비회원 실행 권한 차단 통과. 테스트 데이터는 rollback.
- 실제 로컬 API all/official/competitive 및 verified-only 요청 결과 대조. 전체 API 1회 측정 1.19초(일반화 가능한 부하 벤치마크는 아님).
- 실제 `/weapons` 화면에서 필터 전환 확인. 375×667, 390×844, 430×932, 1440×1000 가로 넘침 없음. 모바일 비교 표는 내부 가로 스크롤 가능(페이지 375px, 표 컨테이너 315px/콘텐츠 654px). 브라우저 JS 오류 없음.
- 독립 코드 리뷰 후 빈 기간/드문 무기 표시 경계를 보강하고 재검증했다.

## 적용 상태 / 후속

DB 함수와 1회 보존 백업은 적용됐다. 코드 변경은 develop 미커밋 상태이며 메인에 배포하지 않았다. 배포 전에는 공개 사이트의 기존 API·화면이 계속 사용된다. 현재 확인된 과거 원본이 없으므로 strict 재검증 완료로 승격한 표본은 0개다. 새로운 원본을 찾으면 소규모 재산출 후 근거를 확인해 현재 기준으로 전환해야 한다. 수치 없이 marker만 채우는 작업은 하지 않는다.
