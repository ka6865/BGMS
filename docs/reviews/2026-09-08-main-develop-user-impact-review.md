# main 대비 develop 코드 리뷰와 사용자 영향

> 후속 상태: 아래는 수정 전 리뷰 기록이다. 두 지적은 이후 수정했으며, 실제 세 명의 개별 경기·최근 10경기·스쿼드 응답 검증에서 추가 발견한 문제도 보강했다. 최신 범위와 빌드·검증 결과는 [세 명 검증 보고서](2026-09-08-three-user-ai-validation.md)를 참조한다. 후속 변경에는 개별·스쿼드 문구 정책도 포함되며 최근 요약 캐시 버전은 v18이다. 운영 배포는 하지 않았다.

## 비교 기준

2026-09-08 `git fetch origin` 후 최신 `origin/main`은 `0c03b0833c7b364ba1314932e9263c6203719f5f`이다. 로컬 develop HEAD도 동일하다. 원격 develop은 `3ed045f`이며 main과 트리 내용은 같다. 따라서 이번 기능 차이는 전부 로컬 미커밋 변경이다. 별도 체크아웃의 로컬 main은 오래돼 배포 비교 기준으로 사용하지 않았다.

보고서 작성 전 비교 범위는 수정된 추적 파일 14개와 작업 관련 신규 파일 8개다. 그중 제품 코드 7개, 테스트 9개, 문서 6개다. 사용자 소유 미추적 pnpm 파일 2개는 이번 기능 변경에서 제외했다. `git diff`만으로는 신규 `aiSummaryJudgment.ts`를 볼 수 없으므로 별도로 읽었다.

## 결론

최근 최대 10경기 AI 토론의 근거 표시와 불필요한 단정 방지는 개선됐다. 그러나 다음 두 건은 합치기 전에 수정할 것을 권한다. 운영 코드 수정은 하지 않고 재현·리뷰만 수행했다.

### [P2] 정상적인 부정·한계 설명을 오류 문장으로 삭제

위치: `lib/pubg-analysis/aiSummaryJudgment.ts:19-24`, `:53-56`.

- 입력: `평균 화력이 높아도 높은 집중력을 의미하지 않습니다.`
- 결과: 올바른 측정 한계 설명인데 ‘높은 집중력’ 패턴에 걸려 보류 문장으로 바뀐다. 이것이 한 코치의 유일한 의견이면 `opinionNeutral` 검사로 카드 해석 전체가 unavailable이 되고 `cacheable=false`가 된다.
- 입력: `교전 횟수를 늘려야 하는 것은 아닙니다.`
- 결과: 늘리라는 권고로 오인돼 일반적인 다음 교전 점검 문장으로 교체된다.

사용자 영향: 정상 응답인데도 ‘AI 해석을 표시할 수 없습니다’나 재시도가 필요해질 수 있다. 수치 근거는 유지된다. 부정문을 보존하는 예외가 `단정할 수 없다`, `뜻은 아니다` 일부 형태만 다루는 것이 원인이다.

권장 수정: 능력에 대한 부정적 단정과 측정 한계의 설명을 구분하고, 의미 부정·금지·인용 문장의 회귀 사례를 추가한다. 모든 ‘아니다’ 문장을 무조건 통과시키는 방식은 피한다.

### [P2] 카드의 승리 판정을 보류해도 상단 요약은 승리를 유지

위치: `lib/pubg-analysis/aiSummaryCards.ts:833`, `:843`.

- 입력 카드 의견: `평균 화력이 관측되었습니다. 탁월한 집중력을 보여줍니다.`
- 입력 최종 문장: `화력은 착한맛 승입니다.`
- 정리 결과: 집중력 문장은 제거되고 카드 winner는 null이 된다. 그러나 최종 문장에는 여전히 착한맛 승이 남고 `cacheable=true`다.

사용자 영향: 같은 결과 화면에 ‘판정 보류’와 ‘착한맛 승’이 함께 나오며 그 모순이 캐시에 남을 수 있다. 최종 문장 재구성 조건이 문장 자체 수정 또는 잘못된 draw 보정만 확인하고, 새로 추가한 추론·조언 보정에 따른 승자 보류를 포함하지 않는다.

권장 수정: 카드의 결론이 바뀌면 최종 문장도 검증된 카드 평가로 다시 구성하고, 생성→저장→캐시 재조회에서 같은 결론을 유지하는지 검사한다.

두 건 모두 독립 리뷰 후 주 에이전트가 별도로 재현했다. 재현기는 실제 API에서 사용하는 문구 정제·모드 검사를 같은 옵션으로 연결했다. 새 Gemini 응답을 받은 것은 아니다. 로컬 재현: `scratch/review-summary-boundaries.ts`, 출력: `/tmp/bgms-review-boundaries.log`.

## 사용자가 체감하는 차이

| 영역 | 현재 main | 현재 develop 변경 |
| --- | --- | --- |
| 토론 결론 | 생성 계약에서 착한맛/매운맛 중 승자를 요구. 근거 부족 시 서버 보류는 이미 존재 | 장단점이 함께 확인되면 ‘장단점 함께’, 결론이 부족하면 명시적 보류를 허용 |
| 불필요한 능력 평가 | 백업 시간·평균 화력에서 집중력·기동력·꾸준함을 확대 해석하는 알려진 표현이 남음 | 발견된 표현을 제거하고 관측 수치 중심으로 정리. 모든 자연어 오류를 검출하는 것은 아님 |
| 다음 경기 조언 | 낮은 솔로 킬 비중에서 혼자 교전을 늘리라는 조언 등이 통과할 수 있음 | 알려진 무조건적 교전 확대 권고를 상대 위치·퇴로·팀원 대응 여부를 확인하는 조언으로 변경 |
| 증거 경기 수 | 카드 선택 경기 수가 증거 행마다 동일하게 표시됨 | ‘선택된 4경기 중 3경기 기록 확인’처럼 지표별 관측 범위를 구분 |
| 부분 기록의 성공률 | 시도만 있거나 승·패 한쪽이 없는 기록을 0처럼 합산할 수 있음 | 주도권·1:1·솔로 비중은 필수 값이 함께 있는 경기만 합산. 실제 0은 유지 |
| 미측정 안내 | 일반적인 기록 없음 안내 | 일부 기록 누락, 복수 성공 사례 없음, 비율 계산 기회 없음의 이유를 더 구체적으로 표시 |

이전 과거 경기 스냅샷 평가에서 MiaeQ_Q의 듀오 4경기 중 대응 사격 속도는 3경기 관측이었다. 평균 3초는 유지되며 표시되는 근거 범위가 정확해진다. 이 값은 실시간 최신 전적을 다시 조회한 결과가 아니다.

주제·지표 ID 기반 카드 구성, 모드 혼합 비교 차단, 빈 증거 안내와 최근 20경기 요약 등 이미 main에 있는 기능은 이번 신규 차이로 계산하지 않는다. 이번 diff에는 개별 경기 분석, 스쿼드 시너지 API·종합 등급, 리플레이, 전적검색 API의 추가 변경이 없다. 최근 요약 공통 집계의 일부 비율은 같은 요약의 시각화·추세에도 영향을 준다.

## 서버·배포 영향

- 기존 경기 자료에서 관측 수를 세므로 추가 DB 조회·원본 텔레메트리 다운로드·전체 유저 갱신은 필요하지 않다.
- 최근 요약 캐시 버전이 v12→v17로 바뀐다. 배포 후 해당 새 키의 첫 요청은 다시 생성할 수 있어 초기 대기가 생길 수 있다. 운영 캐시를 일괄 삭제하는 구현은 아니다.
- 프롬프트 설명과 관측 수 필드가 추가돼 요청당 입력 길이는 증가한다. 비용 절감이나 응답 속도 향상을 측정한 변경이라고 주장하지 않는다.
- 새 라이브러리·테스트 파일을 포함한 커밋이 필요하다. 현재 원격 develop에는 이 미커밋 개선이 없다.

- 기존 테스트 통과와 별개로 위 두 문구 경계 사례가 재현됐다. 해당 두 사례는 아직 정식 회귀 테스트에 추가하거나 수정하지 않았다.
- 이번 리뷰에서 프로덕션 빌드·최신 프롬프트의 실제 Gemini 호출·PR CI/CD·배포 확인은 실행하지 않았다.
