# 전체 계산 갱신 및 배포 검증

## 범위

- **개별 경기 계산 데이터**: `platform + match_id + player_id` 단위 산식 결과. 실제 같은 경기를 여러 이용자가 조회하면 여러 행이다.
- **최근 10경기 AI 분석**: 최근 요청 후보에서 사용 가능한 최대 10경기를 선택하고 최대 5경기를 코칭 근거로 사용한다. 개별 행 재계산과 Gemini 요약 생성은 별개다.
- **스쿼드 분석**: 같은 파티의 최근 최대 10경기 중 현행 계산 결과를 사용한다. 전술 집계와 Gemini 코칭 호출은 별개다.
- **회원 증감**: 사이트 Auth 계정의 가입·탈퇴 기록이다. PUBG 닉네임 수와 구별한다.

## 배포 전 추가 수정과 검증

### 관리자 회원 증감

- 기간 변경 시 이전 요청 취소 및 응답 적용 전 취소 상태 확인. 카테고리 변경과 언마운트에도 취소한다.
- 선택 기간과 완료된 응답의 기간을 분리하여 7일 → 90일 전환 중 선택이 되돌아가지 않으며 이전 결과의 기간을 안내한다.
- 실제 Next 프로덕션 빌드 화면에서 인증·API 응답을 격리한 브라우저 검증: 375×667, 390×844, 430×932, 1280×800. 7일 응답을 1.5초 지연하고 90일 응답 뒤에 도착시켰을 때도 90일 상태 유지. 가로 넘침·페이지 오류 없음.
- 모바일 그래프 Y축의 음수 여백을 제거해 눈금 잘림 수정. 최종 화면 육안 확인.
- 운영 migration `user_lifecycle_events` 적용 성공. 수집 시작 2026-09-08 02:39:07 KST. 7일 RPC 결과 7행, anon/authenticated 실행 불가, service_role 실행 가능, Auth 트리거 활성 확인.
- 격리 PostgreSQL에서 KST 경계와 soft-delete → hard-delete 중복 집계 방지 및 기존 계산/복구 RPC 시나리오 통과. 운영 계정 생성·삭제는 하지 않았다.

### 실제 Gemini 검증

실제 MiaeQ_Q 원본 경기 2개의 raw/full/cache 복원 산술 일치 검증 후 운영 경로의 프롬프트·응답 정제를 호출했다. DB·인증·캐시 쓰기는 메모리로 격리했다.

| 기능 | 호출 결과 | 범위 |
| --- | --- | --- |
| 개별 경기 AI | 통과 | MiaeQ_Q 한 경기, 매운맛 |
| 최근 10경기 AI 기능 | 최초 실패 → 수정 후 통과 | 실제 입력 2경기, 3개 주제 카드 |
| 스쿼드 AI | 통과 | 동일 파티 실제 2경기, 매운맛, 미측정 종합 등급 null |

총 Gemini 호출 4회(실패 1회 포함), 입력 11,054 / 출력 2,533 토큰. 전체 유저 AI 문장 일괄 재생성은 하지 않았다.

최초 요약 실패 원인은 모델이 유효한 `evidenceIds` 하나를 반복한 것이었다. 저장된 실제 응답의 중복만 제거한 오프라인 재현에서 cacheable=false → true가 확인됐다. 공급자 참조 배열의 동일 ID 중복은 정규화하되, 다른 카드·문맥·존재하지 않는 ID는 계속 차단한다. 회귀 테스트 및 새 Gemini 호출 통과. 요약 캐시 버전은 `2026-09-08.debate-calculation2-v12`로 변경했다.

## 데이터 갱신 범위

전체 저장 재고는 개별 계산 14,397행 / 실제 12,207경기였다. 이는 갱신 성공 건수가 아니다. 2026-09-08 운영 조회의 유효 비교 표본 중 미갱신은 Kakao 567행, Steam 4,232행이며, 그중 최근 14일 표본은 각각 478행과 3,779행이었다. 동시 새 전적 유입으로 수치는 변한다.

공식 API의 [보존기간은 14일](https://documentation.pubg.com/en/making-requests.html)이다. 원본이 없는 기간 밖의 경기는 최신 계산 마커만 붙이지 않는다. 기본 전적을 유지하고 변경된 전술 수치·등급은 보류한다. [match와 telemetry 엔드포인트는 API 키 RPM 제한에서 제외](https://documentation.pubg.com/en/rate-limits.html)되지만 운영 갱신은 동시성·요청량·디스크 사용량을 제한한다.

최종 갱신 성공·원본 미확보·제외 집계와 배포 커밋/CI는 실행 완료 시 별도 기록한다.
