# Discord 전적 명령 응답 계약

대상은 `/연동`, `/연동해제`, `/전적`, `/방금판`, `/비교`와 영문 별칭(`link`, `unlink`, `stats`, `recent`, `compare`), 사용자 우클릭 메뉴 `전적 보기`, 닉네임 자동완성이다. 봇은 수익원이 아니라 사이트 유입 경로이므로 결과마다 웹 전적 페이지 링크 버튼을 붙인다. 음성 채널 봇과 운영 명령어 등록은 포함하지 않는다.

## 응답과 공개 범위

- `/연동`, `/연동해제`는 서명 검증과 상호작용 대상 검증 후 `type: 5`, `flags: 64`로 즉시 개인 defer하고, 성공·실패 모두 `@original` PATCH만으로 호출자에게만 표시한다. 공개 처리 표시나 follow-up을 만들지 않는다. 결과 PATCH가 HTTP 4xx로 거절되면 embed·버튼을 비운 실패 안내로 original을 한 번 더 갱신한다.
- `/전적`, `/방금판`, `/비교`, 우클릭 `전적 보기`는 `type: 5`, `data: {}`로 즉시 공개 defer한다. 조회 완료 전에는 전적이나 닉네임을 담지 않는다. 성공 결과는 채널 전체에 보이고, 빈 기록·비공개 차단·실패 안내는 호출자에게만 보인다. 명령 handler의 성공 표시는 `flags: 0`, 개인 안내는 `flags: 64`다. 빈 기록 안내에는 공개 확인을 통과한 대상의 웹 전적 페이지 링크 버튼을 붙이고, 비공개 차단·조회 오류에는 링크를 붙이지 않는다.
- 기존 `after` 흐름에서 명령을 처리하고 성공 결과는 `PATCH /webhooks/{application_id}/{token}/messages/@original`로 갱신한다. PATCH로 공개 여부를 바꿀 수 없으므로 flags를 보내지 않는다. 개인 안내는 먼저 공개 original을 개인 정보 없는 완료 표시로 갱신한 뒤, 별도 follow-up을 `flags: 64`로 보내고 공개 완료 표시를 삭제한다. defer 직후 follow-up을 바로 보내면 공개 original 갱신으로 취급되어 flags가 무시되므로 이 순서를 지킨다. 모든 메시지의 멘션은 비활성화한다.
- `/전적`과 `/방금판`은 비공개 목록 검사를 통과해야 저장 전적을 읽는다. 계정 ID는 웹 비공개 guard와 같이 `pubg_player_cache`의 로컬 ID를 우선하고, 로컬 ID가 없는 이름만 PUBG API로 조회한다. API 조회 결과(미발견 포함)는 같은 인스턴스에서 10분, 최대 500건 보관해 채널 반복 호출이 PUBG API 한도를 소모하지 않게 한다. 조회 실패는 보관하지 않으며 비공개 목록 검사는 매 명령마다 다시 수행한다. 확인 실패는 차단하며 비공개 대상에는 전적과 링크를 제공하지 않는다. 기존 검토 버튼의 서명 선택·승인자·채널·메시지·pending 상태 및 항목별 승인 gate는 유지한다.
- 명령 처리 제한은 15초, 각 Discord 요청 제한은 5초다. 공개 결과는 timeout·네트워크 오류·HTTP 5xx 때 같은 결과로 한 번 재시도해 기존 성공을 보존한다. 최초 공개 PATCH가 HTTP 4xx로 거절되면 개인 실패 안내로 전환한다. 개인 메시지 생성과 공개 완료 표시 삭제는 완료 PATCH가 확인된 뒤 병렬 처리한다. 공개 결과 거절 경로는 처리 15초 + 결과 PATCH 5초 + 완료 PATCH 5초 + 개인 안내/삭제 5초이므로 route의 `maxDuration=35`로 여유를 둔다. 명령 실행·연동 저장·개인 메시지 생성은 재시도하지 않는다. 토큰·오류 원문을 로그에 넣지 않으며 사용자에게 내부 오류 원문을 반환하지 않는다.
- Discord 장애로 공개 완료 PATCH를 확인하지 못하면 flags가 무시되는 경로를 피하기 위해 개인 안내를 보내지 않는다. 안내 또는 삭제가 실패하면 안내가 전달되지 않거나 개인 정보 없는 공개 처리 표시가 남을 수 있다. 공개 결과 두 PATCH가 모두 실패하면 결과 전달 여부도 확정할 수 없다. 명령 timeout은 진행 중인 연동 저장을 취소하지 않는다.

이 응답 방식은 [Discord 공식 interaction 계약](https://docs.discord.com/developers/interactions/receiving-and-responding)에 따른다.

## 전적과 경기

- `/전적`은 저장 시즌 캐시 우선이다. 웹 전적 API와 같이 `last_season_id`의 캐시가 있으면 그 시즌을, 없으면 다른 유효 시즌 캐시를 쓰고 `시즌 36`처럼 시즌 ID 끝 번호로 표시한다. 일반전·경쟁전에서 판수가 가장 많은 대표 모드 하나를 고르고 시즌 누적 판수를 표시한다. 캐시는 해당 인원수의 FPP/TPP 대표값만 보존하므로 시점을 추정하지 않는다.
- 일반전은 K/D, 경쟁전은 (킬 + 도움) / 사망의 KDA를 표시한다. 분모 최소값은 1이며 사망·패배 수가 미측정이면 비율도 미측정이다. 경쟁전 랭크는 경쟁전 성적을 선택했을 때 같은 모드의 랭크만 표시한다. 통계별 갱신 시각을 우선하고 이전 저장 통계 상태도 표시한다.
- 시즌 캐시가 없으면 최신 저장 경기 최대 20건의 실제 판수·모드·경기 유형·경기 시각 범위(Discord 타임스탬프)를 별도로 표시한다. 이 집계는 전체 플레이 이력이나 특정 시즌·일반전·경쟁전 통계가 아니다. 기록에 사망 수가 없어 K/D는 킬 / (판수 - 1위 판수)의 근사값이며 분모 최소값은 1이다.
- `/방금판`은 `pubg_player_matches`에서 `played_at` 내림차순으로 선택한 최신 저장 경기 한 건이다. 실제 방금 종료한 경기임을 단정하지 않는다. 경기 시각, 최초 기록 저장 시각(`created_at`), 사용 가능한 분석 갱신 시각(`updated_at`)을 각각 표시한다.
- 빈 기록과 DB 조회 오류를 구분한다. 경기 ID만 있는 캐시로 지도·순위·킬·딜을 만들지 않는다. 상세 분석이 없거나 identity가 맞지 않으면 지표는 미측정이다. 관측된 `0%`와 `0초`는 그대로 표시하고, 1:1 교전 승률은 소수 한 자리까지 반올림한다.
- `tradeLatencyMs`는 아군 기절 후 복수 처치까지의 평균 시간이며 초로 환산한다. 첫 백업 사격·소통 속도로 설명하지 않는다. 코칭 준비 여부는 상세 페이지에서 확인하도록 안내한다.
- embed 제목·설명의 닉네임은 `_ * ~ ` 등 Discord 마크다운 문자를 이스케이프한다. 링크 URL의 닉네임은 이스케이프하지 않고 URL 인코딩만 한다.
- 경기 링크는 실제 저장된 유효 ID로 `/stats/{platform}/{nickname}/matches/{matchId}`에 연결한다. 닉네임은 URL 인코딩하며 빈 ID·`latest`·`.`·`..`·경로 구분자는 거부한다.

## 자동완성·우클릭·비교

- 닉네임 옵션(`/연동`·`/전적`·`/방금판`의 `nickname`, `/비교`의 `nickname1`·`nickname2`)은 Discord 자동완성(interaction `type: 4`)을 사용한다. 3초 응답 제한 때문에 defer 없이 `type: 8` choices로 바로 응답한다. 2글자 이상일 때 `pubg_player_cache.lower_nickname` 접두어(LIKE 와일드카드 이스케이프)로 최대 10건을 찾고, 비공개 목록과 닉네임·계정 ID가 맞는 플레이어는 제외한다. DB 조회 제한은 1.5초이며 비공개 목록·DB 오류는 빈 목록으로 응답한다. PUBG API는 호출하지 않는다.
- 자동완성 선택값은 `플랫폼:닉네임`(예: `kakao:닉네임`)이다. PUBG 닉네임에는 `:`가 없으므로 직접 입력과 구분된다. 명시적 platform 옵션이 이 접두어보다 우선한다.
- 우클릭 `전적 보기`는 USER 명령(`data.type: 2`)이며 대상(`target_id`)이 직접 연동한 계정만 조회한다. 서버 별명으로 추정하지 않고, 연동이 없으면 그 사실만 호출자에게 안내한다. 성공 결과는 `/전적`과 같이 채널에 공개되므로, `/연동` 성공 안내에서 우클릭 공개 조회와 `/연동해제` 방법을 알린다. 슬래시 명령 이름과 USER 명령 이름은 서로 대체되지 않는다.
- `/비교`는 두 플레이어의 저장 시즌 캐시만 읽어 같은 경기 유형(`type`: 기본 일반전)·모드(`mode`: 기본 squad)의 판수·K/D(경쟁전은 KDA)·승률·평균 딜량·경쟁전 랭크·갱신 시각을 비교한다. 두 대상 모두 비공개 확인을 통과해야 하며 하나라도 비공개거나 확인에 실패하면 차단한다. 더 높은 값만 굵게 표시하고, 저장 시즌이 다르거나 이전 저장 통계가 포함되면 설명에 표시한다. 한쪽 기록만 있으면 공개 비교와 함께 빈 쪽에 웹 갱신을 안내하고, 둘 다 없으면 호출자에게만 보인다. 같은 플랫폼의 같은 닉네임은 거절한다. 결과에는 두 플레이어의 웹 전적 링크 버튼을 붙인다.

## 연동 관리

- `/연동`은 저장 전에 닉네임이 실제 PUBG 계정인지 확인한다. `pubg_player_cache`에 같은 플랫폼·소문자 닉네임이 있으면 그 표기를 쓰고, 없으면 PUBG API(`resolvePubgPlayerIdentity`)로 확인해 API가 반환한 정확한 대소문자 표기로 저장한다. API 결과는 비공개 확인과 같은 인스턴스 보관(10분, 최대 500건)을 공유한다.
- 미발견 닉네임은 저장하지 않는다. DB 조회 오류·PUBG API 장애·한도 초과처럼 확인할 수 없는 경우도 연동을 막고 다시 시도하도록 안내한다. 지원하지 않는 플랫폼은 조회 전에 거절한다.
- 연동 시 계정 소유 여부는 확인하지 않는다. 다른 사람의 닉네임도 연동할 수 있으며, 연동은 해당 Discord 사용자의 기본 조회 대상만 바꾼다.
- `/연동해제`는 호출자의 `discord_user_links` 행을 삭제하고 해제한 닉네임·플랫폼을 표시한다. 연동이 없으면 그 사실만 안내한다.

## 플랫폼과 등록

지원 선택지는 `steam`, `kakao`다. 명시적 platform 옵션이 연동 플랫폼보다 우선한다. 닉네임 우선순위는 직접 입력 → 연동 계정 → 서버 별명/사용자명이다. 닉네임 직접 입력 또는 별명 fallback에서 플랫폼을 지정하지 않으면 `steam`을 사용한다.

### Discord 앱 구분

BGMS에는 이름이 같은("BGMS") Discord 앱이 두 개 있다.

| 용도 | Application ID | 값 위치 |
| --- | --- | --- |
| 슬래시 명령·자동완성·우클릭 메뉴 | `1539746108199407696` | Interactions Endpoint `https://bgms.kr/api/discord/interactions`, 서명 키는 `DISCORD_PUBLIC_KEY`. 등록용 ID·토큰은 로컬 `.env.local`의 `DISCORD_COMMAND_APPLICATION_ID`·`DISCORD_COMMAND_BOT_TOKEN`에만 둔다. |
| 커뮤니티 검토·웹훅·방 생성 | `1490545661702307840` | Vercel `DISCORD_BOT_TOKEN`. Interactions Endpoint와 명령 없음. |

명령 앱의 ID·토큰은 런타임에 쓰지 않아 Vercel·GitHub에 없다. Vercel의 `DISCORD_BOT_TOKEN`으로 명령을 등록하지 않는다.

### 명령 등록

`npx tsx --env-file=.env.local scripts/register_discord_commands.ts`로 실행한다. 스크립트는 `DISCORD_COMMAND_*`를 우선 읽고, PUT 전에 토큰의 앱 ID가 지정한 ID와 같은지 확인하며 다르면 등록하지 않는다. PUT은 앱의 전역 명령 전체를 덮어쓴다.

2026-10-15에 명령 앱에 6개 명령(`/연동`, `/연동해제`, `/전적`, `/방금판`, `/비교`, 우클릭 `전적 보기`)을 등록했다. 등록 전에는 2026-08-20 등록분(`연동`, `전적`, `방금판`)이 있었다.

공개 응답 정책은 애플리케이션 코드에서 적용하며 명령 등록 설명의 변경과 별개다. 커뮤니티 승인 버튼은 기존처럼 ephemeral로 defer한다.

검증은 Supabase·PUBG·Discord를 mock으로 대체한 Discord 회귀 테스트, `npm run verify:core`, `npm run verify:community`, `npm run verify:analysis`를 사용한다. 실제 Discord 전송·운영 DB 쓰기·Gemini 호출·모바일 및 실제 Discord 화면 검증은 포함하지 않는다.
