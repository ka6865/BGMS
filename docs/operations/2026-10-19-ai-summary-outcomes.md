# 최근 AI 요약의 최종 결과 기록

`/api/pubg/ai-summary`는 Gemini 토큰 사용량 수신 시점에 성공을 기록하지 않고 최종 검증·응답 완료 시 요청당 한 번 `ai_usage_logs`를 기록한다. insert가 반환하는 Promise를 Next.js `after`에 연결하여 응답 종료 후에도 저장 작업의 수명을 유지한다. 저장 실패는 서버 오류 로그에 남으며 DB 장애·프로세스 강제 종료까지 보장하는 영구 큐는 아니다.

## 상태와 집계

- `success`: 전체 완료 또는 유효한 캐시 응답.
- `partial`: 검증된 카드가 있어 응답을 제공했으나 전체 완료 조건을 충족하지 못함. `error_code=validation`, `error_message`에는 `positioning:conclusion` 같은 탈락 사유를 기록한다. 부분 결과는 캐시하지 않는다.
- `error`: 최종 실패. 확인된 모델명·입출력 토큰은 실패여도 보존한다.

관리자 집계의 `successRequests`와 성공률은 사용 가능한 응답(`success`와 `partial`)을 포함한다. `partialRequests`는 그중 부분 완료 건수이다. 전체 완료 건수는 `successRequests - partialRequests`, 전체 실패율은 `failedRequests / totalRequests`다. 동일 `request_id`의 과거 성공·실패 중복 행은 기존처럼 한 요청으로 정규화하고 비용을 합산한다. 사용자별 관리자 집계도 같은 성공 판정을 사용한다.

사용자가 응답 스트림을 취소한 경우에는 기존 정책대로 AI 실패로 기록하지 않는다. 인증·비공개·만료·분석 준비 전 거절 등 AI 이전 응답을 모두 포함하는 HTTP 요청 통계가 아니다. 캐시 응답은 포함되므로 순수 생성 실패율을 계산할 때는 `model_name=gemini-cache`를 별도로 제외해야 한다. 이전 로그의 누락 건은 이 변경으로 소급 복원되지 않는다.

## 검증 진단

사용자에게 보내는 NDJSON 오류 계약은 유지한다. DB에서는 아래 원인을 분리한다.

- `parse`: JSON 문법 오류. 길이와 `finishReason`을 기록한다.
- `schema`: JSON은 해석되나 필수 구조가 잘못됨. `top_level_fields`, `debate_issues_count`, `action_items`, `schema_version`, `issue_object`, `topic_id`, `duplicate_topic`, `topic_set`, `evidence_ids`, `invalid_root_or_catalog`로 조건을 구분한다.
- `validation`: 구조 검증 후 해석 근거가 탈락함. 기존 카드별 탈락 사유를 기록한다.

운영 사용량 로그에 생성 원문이나 프롬프트를 추가하지 않는다. 비용은 모델별 표준 유료 단가 기반 추정치이며 청구서 금액과 동일함을 보장하지 않는다. 응답 시작 전 실패한 모델 시도의 사용량은 확인되지 않을 수 있다.

## 문장 품질과 비교 계약

- 카드 근거의 `userNumericValue`, `benchmarkNumericValue`는 반올림 전 비교값이다. 표시는 비율 소수점 1자리, 그 외 2자리로 유지한다. 비율은 분자·분모에서 계산하고, 벤치마크는 기존 표본수 조건을 통과한 원시값을 사용한다. 원시값과 표시값·분자·분모가 모순되는 카드는 검증에서 거절한다. 원시값이 없는 이전 형식도 읽을 수 있다.
- `reason`은 서버가 계산한 비교, `evaluation`은 실제 지표별 관측 경기 수와 해석 한계를 설명한다. `finalVerdict`는 승자와 관계없이 세 카드 모두의 비교 결과와 관측 범위를 반영한다. 한 카드의 높은 지표로 다른 카드의 낮은 지표를 지우지 않는다.
- 순한 코치의 사실 설명과 칭호도 서버에서 작성한다. 비교 가능한 지표는 비교 문장으로, 비교 자료가 없는 지표는 관측값과 판단 한계로 표시한다. AI의 표현을 사실로 채택하기 위해 금지 문구 목록에 의존하지 않는다. 코치 의견이 교정되면 원문에 대한 승자 판정을 그대로 이월하지 않는다.
- 평균·합계만으로 경기별 일관성, 심리, 사용 목적, 피해량 분배 능력을 단정하는 확인된 표현은 문장 단위로 제거한다. 사실 문장은 보존하고, 코치 의견 전체가 이러한 표현으로 제거되면 서버 비교 또는 주제별 점검 문장으로 복구한다. 임의의 빈 의견, 잘못된 근거 ID, 다른 모드 참조는 기존처럼 거절한다. 교정된 의견에 근거 없는 승리를 부여하지 않는다.
- 코치 역할은 관측 사실 설명과 다음 경기의 상황별 점검으로 구분한다. 매운 코치와 행동 제안에는 다음 상황과 확인·점검 명령을 포함한 문장만 채택한다. 비교 반복, 확인된 원인 단정, 연막·교전 횟수를 무조건 늘리라는 조언은 제거하거나 주제별 점검 문장으로 바꾼다. 원문보다 표현 다양성이 줄어들 수 있다. 이 규칙은 발견된 오류를 방어하며 모든 자연어 추론의 정확성을 보장하지 않는다.
- 캐시 버전은 `2026-10-19.card-grounded-quality-v20`으로 올려 이전 비교·문장이 다시 제공되지 않도록 한다. DB migration은 없다.

## 리뷰 후 관제·행동 제안 수정

- `successRequests`와 `successRate`는 기존처럼 부분 완료를 포함한 응답 제공 건수·비율이다. 관리자 화면에서는 이를 ‘응답 제공률’로 표시하고, 완전 성공(`successRequests - partialRequests`)·부분 완료·실패 건수를 구분한다. 회원 목록과 상세에도 부분 완료 건수를 표시한다.
- `errorsByReason`/`recentErrors` 및 회원별 오류 목록은 실패와 부분 완료를 모두 포함한다. 최근 사례의 `status`로 두 상태를 구분하고, 부분 완료의 검증 탈락 사유를 숨기지 않는다.
- ‘확인해 보십시오’, ‘점검해 보십시오’도 조건부 점검 문장으로 허용한다. 행동 제안에는 주제·근거 ID가 없으므로 카드 순서로 주제를 추측하지 않는다. 부적합한 제안은 제외하고 `action_items` 사유로 부분 완료 처리한다. 검증된 카드와 다른 정상 제안은 유지하며 부분 결과는 캐시하지 않는다.
- 수정 전 행동 제안이 캐시에서 재사용되지 않도록 캐시 버전을 `2026-10-19.card-grounded-quality-v21`로 올렸다.

## 2026-10-20 사용자 취소 사용량 보존

- 모델 응답을 선택한 뒤 응답 스트림을 취소하거나 요청의 AbortSignal이 중단된 경우 `cancelled` 상태를 요청당 한 번 기록한다. 이미 받은 모델명·입출력 토큰과 비용을 보존하며, 취소를 정상 성공이나 모델 실패로 기록하지 않는다.
- 취소 직후 SDK 사용량 Promise가 확정되는 경우를 위해 `after`에 연결한 저장 작업에서 최대 1초만 대기한다. 거절되거나 기한 내 확정되지 않은 토큰은 기존 확인값(없으면 0)을 저장한다. 1초 뒤 새로 도착한 사용량을 소급 보정하지 않으며, provider가 보고하지 않은 비용까지 보장하지 않는다.

### 표시 자릿수·저장 정밀도·근거 없는 문장

- **표시 자릿수**: 근거 값은 `Number(값.toFixed(2))`로 만들어 끝의 0이 지워졌다(1.0968 → "1.1", 내 값 "0.28"). 내 값과 비교 평균이 함께 있으면 같은 자릿수로 맞춘다(0.28 vs 1.10, 25.0% vs 14.3%). 한쪽만 있으면 기존처럼 끝의 0을 지운다.
- **저장 정밀도**: `global_benchmarks.isolation_index`, `pressure_index`가 정수 반올림으로 저장됐다(0.33 → 0). 2026-09-04 이전 `safeInteger` 변환을 이어받은 것이며 컬럼은 `double precision`이다. 새로 저장하는 행부터 소수 둘째 자리로 저장한다. 기존 행은 고치지 않는다. 최근 10일 행 기준 반올림 전후 평균 차이는 고립 지수 듀오 0.928/0.933·스쿼드 1.599/1.585, 압박 지수 듀오 3.427/3.455·스쿼드 3.330/3.335로 작아서 정수·소수 행이 섞인 평균도 그대로 쓴다.
- **측정하지 않는 사격 지표**: 화력이 평균보다 높은 카드에서 매운 코치가 "명중률과 탄약 관리를 점검"을 썼다. 프롬프트 금지 예시에 명중률·탄약이 없었고, 문장 검사(`aiSummaryJudgment.ts`)는 과거 사례 목록 방식이었다. 명중·적중 비율, 에임·조준, 반동, 탄약·장전, 헤드샷 언급을 검사 목록과 프롬프트에 추가했다. 해당 문장은 지우고, 매운 코치 의견이 비면 서버 주제 점검으로 대신한다. 행동 제안은 그 항목만 뺀다. 프롬프트에는 비교가 모두 평균 이상이거나 방향 없는 지표뿐인 카드에서 매운 코치가 보완점을 만들지 않도록 추가했다.
- **양호한 지표의 행동 제안**: 모델 행동 제안은 문장 형식만 맞으면 그대로 채택됐다. 이제 제안 문장이 다루는 카드 주제를 찾고, 다루는 주제가 모두 "비교 결과 보완점이 없는 카드"(모두 평균 이상이거나 방향 없는 지표뿐)일 때 약점을 전제한 표현(보완·개선·높이기·늘리기·줄이기 등)이면 뺀다. "유지되는지 확인"처럼 점검만 하는 제안은 남긴다. 처음에는 보완점 없는 카드의 제안을 모두 뺐으나, MiaeQ_Q처럼 성적이 좋은 사용자에게 행동 제안이 0개가 되어 완화했다. 남는 제안도 보완점도 없으면 서버가 가장 앞선 강점 지표에 "다음 경기에서도 같은 기록이 이어지는지 확인해 보세요."를 하나 둔다.
- **생존 운영 주제**: 주제 선택이 생존 운영(평균 사망 페이즈)을 사용자 관측 주제로만 분류해, 비교 평균(계산 2~5 합산, 듀오 경쟁전 A- 94경기·B 104경기)이 있는데도 비교 자료 없는 유틸리티 활용이 3번째 카드를 차지했다. 생존 운영도 사망 페이즈 비교 평균이 30경기 이상이면 비교 주제 후보로 두고, 차이를 페이즈 범위(0~9)로 나눠 순위를 매긴다.
- **행동 제안 표시**: 최근 요약 화면(`components/stat/RecentAISummary.tsx`)은 2026-05-15(`696e983b`) 개편 뒤 행동 제안을 응답에서 읽기만 하고 표시하지 않았다. 종합 평가 아래에 "다음 경기 점검 과제" 목록(`components/stat/SummaryActionItems.tsx`)으로 다시 표시한다. 모델이 보낸 icon 문자열은 쓰지 않고 같은 아이콘을 쓰며, 빈 항목은 빼고 최대 3개만 보인다. 항목이 없으면 목록도, 종합 평가의 "아래 행동 제안은 다음 경기의 점검 과제입니다." 문장도 내지 않는다.
- **다른 모드 이름 검사 범위**: 상단 문장 검사(`top_level_mode`)가 모델의 칭호 설명·종합 평가까지 보고, 다른 모드 이름(예: 주력 모드가 듀오인데 "스쿼드")이 있으면 결과 전체를 부분 완료로 만들었다. 두 문장은 서버 문장으로 바꾸므로 버릴 문장 때문에 캐시·완료가 막혔다(2026-10-30 운영 1건·로컬 1건). 이제 최종 결과에 남는 모델 문장만 본다. 칭호에 다른 모드가 있으면 기본 칭호("AI 전술 분석")를 쓰고, 행동 제안은 기존처럼 그 항목만 뺀다. 결과는 완료로 캐시한다. 카드 의견의 다른 모드 검사는 그대로다.
- **보완점 카드의 행동 제안**: 모델 제안이 하나라도 남으면 서버의 보완 지표 점검을 쓰지 않아, KangHeeSung_ 요약(화력·생존 운영 보완)의 행동 제안이 포지셔닝 1개뿐이었다. 이제 모델 제안이 다루지 않은 보완점 카드에는 서버 점검을 함께 둔다. 순서는 보완점 카드를 다루는 모델 제안, 다루지 않은 보완점의 서버 점검, 나머지 모델 제안이며 최대 3개다.
- 요약 캐시 버전은 `2026-10-30.action-coverage-v32`다. 검증 중 로컬 서버가 운영 DB에 v27~v31 캐시를 남겼으므로 모두 재사용하지 않는다.
