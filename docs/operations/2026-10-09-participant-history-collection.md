# 같은 경기 참가자의 기본 전적 수집

공식 경기 응답을 한 번 조회할 때 유효한 사람 참가자의 기본 전적을 함께 저장한다. 추가 PUBG 조회, 참가자별 텔레메트리 복사, 참가자 전체의 AI·성과 분석은 수행하지 않는다. 개인 캐시의 갱신 시각은 실제 조회한 계정에만 갱신한다.

공식 경기 ID·플랫폼·계정·닉네임과 관측한 날짜·모드·맵·킬·피해량·순위를 검증한다. 봇, 중복 계정 또는 닉네임, 필수 값이 없는 참가자는 제외한다. 비공개 목록은 경기당 한 번 읽고 계정 ID 우선 및 기존 닉네임·all 플랫폼 규칙을 적용한다. 비공개 확인이 실패하면 쓰지 않는다. 조회 대상의 기록이 DB에 저장되지 않으면 수집 성공으로 처리하지 않는다.

공식 참가자 저장은 service role 전용 `upsert_pubg_participant_matches`로 경기당 최대 100명·128KiB 입력을 원자 처리한다. 계정 충돌이나 한 행의 DB 오류가 나면 전체 참가자 쓰기를 취소한다. 같은 경기의 재시도가 일부 저장된 대상을 완료로 오인하는 것을 막는다. 누락된 기절·생존 시간은 기존 관측값을 지우지 않으며, 실제 0은 그대로 저장한다. 기존 복구 writer의 일반 upsert 계약은 유지한다.

`pubg_player_matches.retention_scope`는 플랫폼·계정·경기별 보존 분류다.

| 값 | 의미 | 만료 정리 조건 |
| --- | --- | --- |
| `legacy` | 기존 writer 또는 과거 미분류 기록 | 기존 성과 요약 검증 필수 |
| `basic_only` | 공식 기본 전적 수집 | 개인 분석·성과·지도·작업·benchmark 참조가 없고 기본 전적 및 원본 관측값이 일치 |
| `detail` | 개인 상세 분석 | 기존 성과 요약·checksum 검증 필수 |

새 컬럼의 기본값은 `legacy`이며 기존 자료를 분석 결과의 부재만으로 `basic_only`로 바꾸지 않는다. DB trigger는 conflict upsert에서도 `detail`을 낮추지 않고 `legacy`를 `basic_only`로 낮추지 않는다. 실제 개인 자료와 작업 참조는 표시보다 우선한다. 이 분류는 상세 분석 성공 여부를 대신하지 않으며 기존 성과 상태·요약을 함께 확인한다. 전적 목록 및 개별 경기 GET에는 `retention_scope`가 포함된다.

기본 수집만 확인된 참가자에게 만료 정리를 위한 성과 재계산을 강제하지 않는다. 공유 원본에 다른 참가자의 분석이 연결되면 그 성과가 모두 보존되어야 한다. 개인 객체는 항상 개인 성과 근거를 요구한다. 준비 후 분류·참조가 바뀌면 현재 DB 검증 및 삭제 직전 재조회에서 중단한다. 14일 정책·활성 작업 보호·암호화 백업·ETag·SHA-256 및 삭제 후 부재 검증을 유지한다.

전역 archive 후보와 미보존 성과의 범위는 참가자 행 제한 전에 같은 플랫폼·경기를 묶는다. 경기별 가장 이른 기본 전적 시각을 cursor 순서에 사용하며, 실제 삭제는 모든 참가자의 날짜와 기록을 다시 검증한다. 성과 작업 seed의 최근 7일·활성 연동 profile·대기열 상한은 유지한다.

조회는 cursor 이후의 최소 시각 행을 인덱스로 읽고 중복 제거 후 LIMIT을 적용한다. cursor 이전 전체 이력을 매 배치 집계하지 않는다. `(played_at,platform,match_id,player_id)`와 `(platform,match_id,played_at)` 인덱스가 순차 후보 조회와 경기별 시각 대조를 지원한다.

과거 복구 packet의 기본 전적에 `retention_scope`가 없을 때만 `legacy`로 보완한다. 명시된 값·나머지 스냅샷·기존 요약의 checksum 및 고정 기본 전적 증거는 변경하지 않는다. 운영 적용 전 진행 중인 정리 배치가 끝났는지 확인하고, 새 manifest를 작성해 정리를 재개한다. 컬럼 삭제 rollback은 과거 복구 계약을 다시 깨뜨리므로 실행하지 않는다.
