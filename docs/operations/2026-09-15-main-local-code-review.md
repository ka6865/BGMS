상대 페이지에서 확인하는 것은 경기 원본의 계정 ID다. 신고 완료 알림의 별표 닉네임을 복원하거나 신고 대상과 임의로 연결하지 않는다. 관심 등록은 개인 관찰 목록 등록이며 PUBG 신고 제출이 아니다. 공식 제재가 관측되어도 제재 사유나 내 신고 때문에 제재되었는지는 이 데이터로 확인할 수 없다.

임시 제재도 상태로 구분하지만 모든 임시 제재를 빠짐없이 알 수는 없다. 정상 상태의 기본 재확인은 24시간 뒤, 임시 제재를 이미 확인했다면 6시간 뒤, 영구 제재는 7일 뒤다. 관측 사이에 시작하고 해제된 짧은 제재는 놓칠 수 있다. 워커 실행 주기와 개별 계정의 재확인 주기는 다르다.

상대 목록은 최근 90일 저장 경기 중 10경기씩 조회한다. 캐시가 없는 상대 통계는 첫 카드만 자동 갱신하며 나머지는 기존 캐시 또는 직접 확인 버튼을 사용한다. 전체 리스트의 티어·평딜이 항상 즉시 채워지는 구조는 아니다. 관심 대상은 기본 30일 추적하며 연장 동작이 있고, 사용자별 활성 대상 50명·대상별 활성 경기 10개 제한이 있다.

성과 계산은 GitHub Actions의 별도 자식 프로세스로 실행하며 Gemini 코칭을 호출하지 않는다. V8 힙 상한은 512MB, 자식 계산 제한은 110초다. 512MB는 전체 프로세스 메모리의 절대 상한이 아니다. 성과 계산의 목표 실행 예산은 4분이며 워크플로 전체 제한은 별도다.

세 가지 비용은 여전히 관리해야 한다.

- 랭킹 화면은 보이는 동안 매분 서버 액션 세 개를 요청하지만, 서버는 필터별 결과를 60초 공유 캐시로 합친다. 같은 필터를 보는 사용자가 늘어도 각 사용자마다 집계 RPC 세 개가 그대로 증가하지 않는다. 캐시 미스 시 비공개 설정 조회와 집계 RPC가 실행되며 관리자 비공개 변경은 해당 태그를 즉시 만료한다.
- 시간당 cron은 하루 최대 24회 실행한다. 계산은 하루 30회 claim 제한을 별도로 적용한다.
- 하루 30회에는 실패·재시도 claim도 포함된다. 유입량이 처리량을 초과하면 적체가 생기고 7일이 지난 작업은 제외될 수 있다. 모든 사용자에게 즉시 자동 산정을 보장하는 용량은 아니다.

현재 일반 전적 검색·제재 워커·상대 통계의 공식 API 한도는 하나의 전역 예산으로 완전히 통합되어 있지 않다. 상대 통계의 분당 2회 제한은 새 기능의 추가 요청 제한이다. 전체 서비스에 API 한도 문제가 없다는 보장은 아니므로 실제 키의 사용량과 함께 봐야 한다.

기본 경기 기록과 발견 기록은 계속 쌓이고, 이번 변경에서 모든 데이터에 대한 전체 보존 정책이 추가된 것은 아니다. 운영 DB 실제 용량·쿼리 계획·동시 사용자 부하를 이번 리뷰에서 측정하지 않았다.

**배포 호환성과 적용 순서**

SQL은 추가 위주라 기존 코드와 병행할 여지가 있지만, 새 코드는 새 RPC와 컬럼을 사용한다. 코드만 먼저 배포하면 랭킹 RPC가 없어 랭킹 조회가 실패하고 새 컬럼 저장도 실패할 수 있다. 상대/제재 기능 역시 준비되지 않은 저장소 오류를 표시한다.

권장 순서는 다섯 마이그레이션의 적용 여부 확인 및 반영 → 제한된 조회 검증 → 코드 배포 → 전적 보관 워커 → 제재 관찰 워커 → 성과 계산 워커 순차 활성화다. 워커들은 저장소 변수로 기본 비활성화하도록 구성되어 있다. 롤백 시에는 우선 워커를 끄고 이전 코드를 돌리는 방식이 추가 데이터까지 즉시 삭제하는 것보다 단순하다.

운영 연결의 최초 읽기 전용 확인에서는 `get_pubg_rankings` RPC가 `PGRST202`로 없었다. 이후 코드 배포보다 먼저 신규 마이그레이션 5개를 적용했고, 핵심 테이블·RPC 존재와 랭킹 30행 반환을 확인했다. 저장소 활성화 변수 값은 변경하지 않았다.

**검증 범위와 결론**

최종 준비에서 원격 main과 로컬 기반 소스 트리 동일성을 다시 확인했다. 일회용 PostgreSQL 17에서 신규 마이그레이션 5개와 RPC 시나리오가 통과했고, 개인정보 과거 별칭 제외 시나리오도 포함했다.

최종 변경 기준 집중 테스트 177개, TypeScript 검사, Next.js 프로덕션 빌드가 통과했다. ESLint는 오류 0개와 기존 경고 44개를 보고했다. 이전 검증에는 분석 618개와 전체 단위 테스트 2,912개 통과 기록, 4개 뷰포트 확인도 있다.

자동 작업은 마이그레이션과 기본 조회를 확인한 뒤 하나씩 활성화한다. 랭킹 화면의 주기 조회 부하는 운영 지표를 보면서 조정한다.
