# 기존 계산 보존과 신규 계산 적용 계획

사용자 승인: 기존 계산 결과는 보존하고 앞으로 새로 분석하는 경기만 계산 3으로 저장한다. 전체 재계산·버전 재라벨·데이터 삭제는 하지 않는다. 부모가 구현하고 Luna가 읽기 전용 리뷰한다.

## 계약

- 신규 계산 writer는 3을 유지한다. 조회는 명시적으로 2와 3만 허용하고 1·미확인·문자열·미래 버전은 거부한다.
- 기존의 identity·결과 73·모집단 근거·보존 기간·권한 검증을 유지한다. 조회 때문에 계산 2를 갱신하지 않는다.
- 계산 2와 3에서 동일한 기본 점수·티어·benchmark 지표를 함께 사용한다. 변경된 캐리 점수는 저장된 경기 결과를 그대로 사용한다.
- 단일 경기 AI 캐시 키는 해당 경기의 실제 계산 버전으로 만든다. 최근 요약·스쿼드 캐시는 선택한 경기의 버전 근거를 포함한다.
- 랭킹은 DB에서 중복 경기와 비공개 대상 제외 후 TOP 30을 선정한다. 계산 버전별 TOP 30을 클라이언트에서 섞지 않는다.
- 기존 자료를 읽기 위한 지원과 신규 쓰기 버전을 구분한다. 저장 하향 방지와 재계산 CAS 보호를 유지한다.

- [x] benchmark 조회·battle·성과 캐시·랭킹과 DB 보존 함수를 수정하고 혼합 표본·중복 경기·버전별 AI 캐시를 검증한다.
- [x] 운영 문서를 갱신하고 core·analysis·admin·전체 unit·격리 migration·빌드 검증 후 Luna 최종 리뷰를 받는다.
- [ ] 운영 함수 정의와 migration 이력을 대조한다. 배포 조건을 만족하면 기존 승인 범위에서 main 반영·배포하고 기존/신규 자료 조회를 확인한다.
