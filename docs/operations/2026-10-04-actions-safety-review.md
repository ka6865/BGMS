# Actions·Discord 운영 점검 및 R2 절감 검토

2026-10-04 KST 기준. 9개 워크플로와 연결된 수집·백업·알림 코드를 검토했다. 운영 정리, Discord 테스트 발송, R2 삭제는 실행하지 않았다.

## 최근 3일 알림 근거

`agent_runs`의 `admin-agent-monitor` 실행 요약에서 다음 기록을 확인했다. 시각은 KST다.

| 시각 | 기존 API 오류 집계 | 기존 운영 점검 상태 | 발송 기록 |
| --- | ---: | --- | --- |
| 10월 1일 07:26 | 55 | critical / blocked / 0점 | sent=true, 메시지 영수증 없음 |
| 10월 2일 07:53 | 33 | critical / blocked / 0점 | sent=true, 메시지 영수증 없음 |
| 10월 3일 07:24 | 29 | critical / blocked / 0점 | sent=true, 메시지 영수증 없음 |

이는 운영 API 집계 결과이며 GitHub CI 실패를 뜻하지 않는다. 기존 기록에는 발송 영수증이 없으므로 실제 Discord 수신 성공까지 증명하지 못한다. 원문 메시지 자체의 보관 기록도 아니다.

확인한 정상 대기 응답은 `/api/pubg/match`, `source=user`의 `404 PUBG_MATCH_NOT_FOUND`, `409 PUBG_MATCH_ANALYSIS_IN_PROGRESS`다. 이 정확한 조합만 일반 운영 오류에서 제외하고, 다른 404/409 및 실제 5xx·429는 유지한다.

## 적용 범위

- Actions: 읽기 권한, 검증한 전체 SHA 고정, checkout 자격 증명 미보존, 작업별 시간 제한, 실패 알림에 고객센터 첨부 정리 포함.
- 백업: 정렬된 페이지 조회, 제한 초과와 부분 실패 표시, 부분 복구 파일 보존, 불완전 백업 시 실패 종료. 관련 유지보수 삭제는 백업 성공 후 실행한다.
- 수집: PUBG key가 없으면 큐 작업을 점유하기 전에 중단. 자기장 추출은 최대 150회 시도·5분 예산·개별 요청 제한을 적용하고, 기존 데이터 조회/업로드 실패를 드러낸다.
- 알림: 중간 보고와 전체 완료 구분, 멘션 차단, 제한 시간, HTTP 결과 및 메시지 ID 확인. monitor 알림 발송 실패는 HTTP 502로 표시하면서 실행 요약을 보존한다.
- 랭커·답글: 후보 부족과 품질 보류는 정상 미발행/보류. 원본 다운로드·AI 제공자·DB 오류는 실제 실패로 유지한다.
- PR: 격리 PostgreSQL 마이그레이션 검증 및 운영 의존성 보안 검사를 추가한다. 운영 자격 증명을 검증 작업에 주입하지 않는다.
- 의존성: Next.js 계열 16.3.8 및 호환 패치 업데이트. 운영 의존성 감사 0건. 개발 도구의 `braces` 계열 미해결 권고는 남아 있으며, 이를 없애려고 Next.js를 구버전으로 내리지 않았다. Dependabot은 월별 patch/minor PR만 제안한다.

플레이어 `invalid_shape` 오류는 이번 읽기 전용 표본에서 재현되지 않았다. 검증을 느슨하게 바꾸지 않고 필드 구조 실패 사유만 로그에 추가했다. 실제 오류 재발 시 사유를 확인해야 하며, 모든 전적 조회 오류가 해결되었다고 간주하지 않는다.

## R2 절감 우선순위

10월 2일 보존된 운영 로그의 R2 사용량은 14.01GB다. 경로별 비중은 측정되지 않아 실제 확보 가능한 용량을 단정할 수 없다. 신규 JSON 업로드에는 이미 gzip이 적용되어 있다.

1. 기존 비압축 JSON을 작은 표본으로 재압축하고 동일 원문 읽기·감소 바이트·실패 복원을 검증한다. 기존 `recompress_r2_json.ts`를 활용한다. 코드에 기재된 텔레메트리 압축 효과 약 94%는 전체 버킷의 절감률이 아니다.
2. 경로별 크기·압축 여부를 제한된 측정으로 확인한다. 전체 사용량이나 잘린 조회만 보고 삭제 규모를 추정하지 않는다.
3. 최근 백업의 완전성과 복원 가능성을 확인한 뒤 30일 초과 백업 정책을 별도로 검토한다. 현재 30일 상수는 자동 만료 정책과 연결되지 않고 `backups/`는 삭제 가드로 보호된다.
4. DB·등록부 참조가 없는 분석/리플레이 객체는 기존 dry-run의 대상·바이트·재검증 근거를 확인한 뒤에만 정리 범위를 정한다.

PUBG 원본은 최근 14일 범위를 넘기면 다시 확보하지 못할 수 있다. 사용자 전적과 연결된 오래된 텔레메트리, 보호 백업을 일괄 삭제하는 방안은 적용하지 않았다. 이번 R2 작업은 절감안 검토까지이며 실제 사용량을 줄인 작업은 아니다.
