# LoL 검색 편의·집계 상태·경기 흐름

## 최근 검색과 즐겨찾기

- 공개·관리자 전적 검색에서 성공한 계정만 최근 검색에 기록한다. 대소문자는 같은 Riot ID로 취급하며 최근 10개를 유지한다.
- 현재 검색한 계정의 즐겨찾기 추가·해제, 목록 재검색, 개별 삭제, 최근 기록 비우기를 제공한다. 즐겨찾기는 최대 20개다.
- 저장 위치는 해당 브라우저의 `localStorage`, 키는 `bgms:lol-search-history:v1`이다. `{ recent: string[], favorites: string[] }`만 저장하며 서버 계정·DB와 동기화하지 않는다.
- 브라우저 저장소를 지우면 목록도 사라진다. 저장소 차단·손상·용량 부족 때는 실패를 안내하고 전적 검색은 유지한다.
- 기존 `bgms:lol-loaded:` 경기 개수 복원용 `sessionStorage`와는 별개다.

## 집계 시각과 수집 범위

- 챔피언 통계의 마지막 집계 시각은 서버에서 선택된 패치·큐·티어의 `lol_stat_totals.updated_at`을 조회한다. 경기 원문을 추가 조회하거나 보관하지 않는다.
- 해당 메타데이터 조회에 실패하면 시각을 확인할 수 없음을 표시하고 이미 조회한 통계는 유지한다. 브라우저가 요청한 시각을 집계 시각으로 표시하지 않는다.
- 랭킹·장인은 기존 공개 게시본의 `observedAt`을 사용한다. KST 기준 시각을 보여 주며 24시간 이상 지난 집계는 오래된 집계임을 안내한다. 수집기 중단 여부를 단정하지 않는다.
- 장인 진행률은 게시본의 `coverage`이며 대상 계정 중 확인한 비율이다. 누적 경기 수집에는 확정된 목표가 없으므로 챔피언 통계에 완료율을 만들지 않는다.
- 스키마·RPC·RLS 변경과 운영 데이터 쓰기는 없다. 마지막 집계 시각 조회는 기존 서버 service role 경로에서만 수행한다.

## 경기 흐름

경기 상세의 **빌드·흐름** 탭에서 소환사를 선택하고 누적 골드·CS 지표와 시점을 바꿔 볼 수 있다. 기존 빌드 응답에 가공 시계열만 추가하므로 그래프 조작에 별도 API 호출이 없다. 필드 의미·결측·캐시는 [빌드 탭 계약](2026-10-26-lol-match-build.md)을 따른다.

## 검증 범위

관련 단위 테스트와 기존 공개·개발·챔피언·랭킹 브라우저 fixture를 사용한다. 모바일 뷰포트 `375×667`, `390×844`, `430×932`, 데스크톱 `1440×900`에서 검증한다. 운영 DB·실제 Riot 게임·실기기 검증과 구분한다.
