# 2026-10-05 전적 보관·수집·알림 점검

## 변경 목적

- Bluezone 수집은 검증된 공통 보관 자료를 먼저 사용하고, 없으면 DB에 연결된 같은 경기의 이전 분석 파일을 읽는다. `lite.json` 연결은 인접 `lite_analyze.json`으로 해석한다. 과거 개인 분석 파일을 전체 경기 공통 원본으로 승격하지 않는다.
- DB/R2/상위 API 오류가 발생한 실행은 기존 Bluezone 파일을 덮어쓰지 않는다. HTTP 429는 즉시 중단한다. 변경 없는 실행 및 `--dry-run --limit 3`은 저장하지 않는다. 실패 원인은 허용된 코드로 남기고 알림은 실패 단계의 실제 출력만 분류한다.
- 전적 수집 workflow는 실행 전후 상태별 건수, 오래된 대기 작업, 마지막 저장 시각, 만료된 작업 잠금을 기록한다. 사전 관측 실패가 수집 자체를 건너뛰게 하지 않으며 관측 오류는 workflow 실패로 남긴다.
- `PUBG Archive Verification`은 main에서만 수동 실행한다. 같은 경기의 공개 계정 두 명을 선택하고 공통 자료로 각각 다시 계산한 지도 내용과 운영 API 조회 내용을 비교한다. 공통 객체 본문이 A/B 조회 후에도 변하지 않는지, 해당 공통 객체와 개인 지도/분석 파일 다섯 개의 실제 저장 바이트 증가량을 측정한다.
- `prime_shared=true`는 공식 경기/텔레메트리의 식별자를 검증한 후 공통 객체 최대 한 개를 조건부 생성한다. 기존 객체를 덮어쓰지 않는다. 운영 조회에서 개인 지도 캐시가 생성될 수 있다. 버킷 전체 증가량이나 전체 서비스 절감률을 의미하지 않는다.
- 기존 사본 비교 CLI는 과거 인벤토리/DB 참조/전체 본문 해시 증거를 대조한다. 삭제 명령을 제공하지 않으며, 현재 본문과 복구·재계산 증거가 없는 대상을 삭제 가능으로 표시하지 않는다.

## 실제 확인한 범위

2026-10-05 한국 시간 오전의 읽기 점검:

- 28일 지난 보관 경기 세 건의 상세 API, 지도 API, 실제 R2 지도 다운로드가 모두 HTTP 200이었다. 지도 본문 식별자와 요청 경기·플랫폼·계정 공개 키가 세 건 모두 일치했다.
- 수집 상태는 pending 36,547 / retry 242 / running 0 / saved 25,340 / unavailable 3,463이었다. 즉시 실행 가능한 작업 36,562개, 만료된 running 잠금 0개였다. 마지막 저장 후 38분이므로 2시간 무진행 경고는 발생하지 않았으나, 24시간 이상 대기 경고는 발생했다. 작업 건수는 고유 경기 수와 다르며 전체 해소를 의미하지 않는다.
- 기존 후보 쌍 6,277개를 이전 감사 증거로 대조했다. 현재 참조 중인 지도 4,335개, 과거 전체 바이트 해시가 일치한 쌍 20개였다. 공통 자료 전환 증명 0개, 삭제 적격 0개다. 운영 R2 삭제·이전 개인 자료의 공통 원본 전환은 하지 않았다.
- #215는 최신 main 반영 후 clean install을 수행하는 GitHub CI에서 unit 3,362개, 마이그레이션, 운영 의존성 취약점 검사를 통과했다. Preview에서 375/390/430/1440 너비의 정상 조회·저장 실패 fixture 총 8개가 통과했다. 운영 OAuth 로그인을 증명하는 테스트는 아니다.

## 검증 및 운영 순서

관련 회귀 테스트는 원본 무결성·다른 계정/경기 배제·일부 수집 실패 시 기존 파일 유지·텔레메트리 429 중단·동일 개수지만 내용이 다른 재계산 결과 거절·알림의 코드 출력 오분류 방지를 확인한다. 로컬 최초 clean install 후 unit 3,381개가 통과했고, 리뷰 보완 뒤 관련 회귀 테스트를 재검증한다. 최종 통합 clean install 및 unit은 PR CI에서 확인한다.

PR CI와 리뷰 통과 후 main에 병합하고, 수동 archive verification을 제한 실행해 A/B 실제 재계산·조회와 저장 바이트를 확인한다. 검증 집계 artifact의 보관 기간은 7일이며 본문·계정·객체 키·서명 URL을 포함하지 않는다. 실제 공통 자료 검증이 끝나도 이전 사본 삭제는 개별 참조·현재 본문·복구 근거가 충족된 대상부터만 진행한다.
