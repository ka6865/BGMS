# 모바일 공유 서버 변경 통합 검토

기준: 웹 main `b3995dce`, 모바일 서버 후보 `4862f259`. 원래 모바일 작업 폴더와 미커밋 의존성 파일은 보존하고, 별도 `codex/mobile-web-integration` 작업 폴더에서 변경을 재검토했다.

## 전적과 수집

- 웹 기본 검색은 저장된 전적을 우선한다. 명시적 `refresh=auto`는 완료된 전적의 15분 경과 여부를 확인한다. 부분 조회·저장 실패는 완료 시각을 올리지 않는다.
- 최근 표시 20경기, 기존 요약 보완의 요청당 5경기, 명시적 계정 수집의 요청당 3경기는 서로 다른 범위다. 전체 발견 경기 ID와 수집 대기열은 별도로 유지하며 기존 전역 자동 수집은 보존한다.
- 새 계정 수집 API는 비공개 확인·계정 확인·쿨다운·작업 점유·저장·진행 확인에 같은 12초 취소 신호를 적용한다. API 키가 없으면 점유하기 전에 실패한다.
- 계정별 작업 점유는 새 마이그레이션으로 30초로 줄인다. 전역 수집의 15분 점유와 최대 1,000경기 제한은 유지한다. 이미 실행 중인 작업의 점유 시각을 일괄 수정하지 않는다.
- 경기와 계정 ID, 실제 통계·맵·시각을 확인한다. 닉네임만 같은 과거 기록을 일괄 계정 결합하지 않는다. 요약 복구 성공은 저장된 행을 재확인한다. 불완전한 기록은 목록 ID를 유지하면서 가짜 통계 요약을 표시하지 않는다.
- 저장·발견 목록 기록 실패가 HTTP 200 응답에 포함되어도 웹에 안내한다. 같은 플레이어의 캐시 조회는 이 안내를 지우지 않으며 명시적인 저장·목록 기록 성공 응답으로 해제한다.

## 게시판과 인증

모바일 글·댓글 작성, 수정, 삭제, 추천은 기존 회원·소유자·revision·사진 참조 검증을 사용한다. 기존 웹 신고 요청의 숫자 대상 ID 형식을 유지하고, 비공개 또는 없는 대상을 거절하며 DB 실패를 드러낸다. 명시적으로 제공된 Bearer가 유효하지 않으면 다른 쿠키 사용자로 쓰기를 실행하지 않는다.

추천 표시와 집계는 새 service-role 전용 RPC의 한 트랜잭션에서 기록한다. 응답 유실 후 재시도는 중복 추천으로 반환하고 카운터를 다시 올리지 않는다. 기존 웹 추천 RPC는 변경하지 않는다.

## 운영 DB 이력

모바일 담당자가 먼저 적용한 두 변경은 다음 운영 이력과 파일명·내용을 맞췄다.

- `20261003200626_mobile_scoped_match_collection`
- `20261003200721_unique_scoped_pubg_discovery_rpc`

이 두 SQL은 재적용하지 않았다. 격리 DB 검증과 재리뷰 후 다음 전진 마이그레이션만 추가 적용하고 실제 운영 버전으로 파일명을 맞췄다.

- `20261004050604_pubg_scoped_collection_short_lease`
- `20261004050621_mobile_board_like_atomic`

운영 함수 정의와 실행 권한을 다시 읽어 scoped 30초·global 15분, SECURITY INVOKER·빈 search_path·service_role 전용을 확인했다. 테이블·RLS 공개 권한, 저장된 경기, 운영 게시글은 삭제하거나 되돌리지 않았다.

## 검증 범위

공유 node_modules 연결 대신 이 작업 폴더에서 lockfile로 `npm ci`를 수행했다. 가짜 자격 증명의 단위 테스트 3,312개가 통과했고 84개는 외부 통합/브라우저 등 opt-in 검사로 건너뛰었다. 일회용 PostgreSQL의 28개 마이그레이션과 RPC 시나리오, 추천 service_role 실제 호출을 검증했다. 정적 검사 오류 0건·기존 경고 44건, 운영 의존성 감사 0건이다. 모바일 안내는 375×667, 390×844, 430×932 및 데스크톱 1440×900의 실제 브라우저에서 문구·줄바꿈·가로 넘침 검사를 모두 통과했다. 스크린샷 캡처가 멈춰 이미지 저장은 검증 근거로 사용하지 않았다.

Next 16.3.8의 개발 허용 호스트 설정을 포트가 없는 호스트명으로 수정했다. 브라우저의 애니메이션 프레임 대기 대신 간격을 둔 문구 확인을 사용하고, 기존 검증 도구에 저장 전적 GET 응답을 추가했다.

실제 OAuth 회원 글쓰기·이미지 업로드는 운영 데이터 쓰기로 검증하지 않는다. PUBG 보존 기간 밖의 경기 복구나 모든 기존 오류의 해결을 보장하는 변경은 아니다. GitHub 필수 검증과 Vercel Preview 빌드를 통과한 커밋만 병합한다.
