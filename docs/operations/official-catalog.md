# 공식 도감 저장·탐색 계약

공식 원문은 [무기](https://pubg.com/ko/game-info/weapons/etc)와 [탈것](https://pubg.com/ko/game-info/vehicles/land)에서 읽는다. 각 페이지의 정적 Nuxt 데이터에 포함된 전체 상위 분류와 항목을 해석하며 외부 스크립트는 실행하지 않는다.

## 저장 자료

`official_game_catalog.items`의 각 `OfficialItem`은 기존 `key`, `name`, `updated`, `ammunition`, `specs`, `official` 필드를 유지한다. 상위 분류의 `key`와 `name`이 모두 있으면 `category: { key, name }`을 함께 저장한다. `official`에는 해당 항목 원문을 보존하며 상위 분류를 원문 안에 임의로 추가하지 않는다.

분류 필드는 선택 사항이다. 과거 저장 자료에 분류가 없거나 불완전하면 UI는 **분류 미확인**으로 표시한다. 이름·탄약·제원으로 분류를 추정하지 않는다. 무기의 탄약이 비어 있으면 필터에서 **탄약 미표기**로 표시한다. 무기 종류와 탈것 분류의 선택지는 저장된 공식 분류에서 생성한다.

기존 JSON 저장 구조와 컬럼을 그대로 사용하므로 새 DB migration은 필요하지 않다. 기존 운영 자료의 누락된 상위 분류는 자동 복구하지 않는다. 구현 반영 후 관리자가 기존 비교·공개 경로에서 공식 원문을 다시 불러와 검토하고 공개해야 새 분류가 저장된다. 이 작업에서는 운영 자료를 게시하거나 변경하지 않는다.

관리자 공개 API의 권한 검사·원문 fingerprint 재확인·감사 로그는 유지한다. 분류도 fingerprint 대상인 파싱 결과에 포함된다. 이전 화면에서 받아 둔 fingerprint는 새 원문 비교 결과와 다를 수 있으므로 다시 불러와 확인한다.

## 날짜와 계산 자료

- `OfficialItem.updated`: 공식 항목 자체의 수정일. 공식 원문 값에 `마지막 업데이트:` 접두어가 들어 있으므로 화면은 이 접두어를 떼고 `공식 항목 수정일:` 라벨 뒤에 날짜만 표시한다.
- `official_game_catalog.fetched_at`: BGMS가 해당 공식 자료를 수집한 시점. UI는 한국시간으로 표시하며 누락·잘못된 값은 미확인으로 처리한다.
- 시뮬레이터의 BGMS 패치 적용 버전: 별도 내부 무기·부착물 자료의 적용 상태이며 공식 항목 수정일·수집일과 서로 대체할 수 없다.

## 선택 전달과 모바일 복귀

`OfficialCatalog`는 선택적으로 `onConfigureWeapon(item: OfficialItem)`, `onItemsLoaded(items: OfficialItem[])`, `onLoadError()`, `onToggleCompare(item)`, `comparedKeys`, `compareFull`을 받는다. 조회가 실패하면 `onLoadError`를 호출한다. 성공한 조회에서만 전체 공식 항목을 `onItemsLoaded`에 전달하며 검색·필터로 줄어든 목록을 전달하지 않는다. 이 콜백은 호출부에서 안정적인 함수 참조(예: React 상태 setter)를 전달한다. 상세의 **이 무기로 파츠 설정**은 현재 공식 항목을 원문 포함 그대로 전달한다. 내부 무기 ID 연결과 호환 검증, 연결 실패 안내는 호출부가 담당한다. 탈것과 콜백이 없는 화면에는 해당 버튼을 표시하지 않는다.

모바일은 목록과 상세를 전환한다. 상세를 연 동안 목록 DOM을 유지하고 **목록으로 돌아가기**에서 검색·필터·선택, 목록 내부 스크롤, 문서 스크롤, 선택 버튼 포커스를 복원한다. 데스크톱은 목록과 상세를 나란히 표시한다. 상위 탭 전환 뒤에도 상태를 보존하려면 호출부에서 이 컴포넌트를 계속 마운트해 두어야 한다. `CatalogTabs`는 탈것 도감을 탭을 처음 열 때 마운트해 무기 화면 진입마다 탈것 조회가 나가지 않게 하고, 이후에는 마운트를 유지한다.

## 무기 연결과 호환·계산

`lib/weapons/simulator.ts`의 명시적 공식 key → 기존 BGMS ID 연결을 우선한다. 매핑된 무기가 내부 조회에 없으면 대체 무기를 선택하지 않는다. 미등록 key는 양끝 공백과 대소문자만 무시한 정확한 이름이 유일하게 일치할 때만 연결한다. 제거된 내부 무기는 기존 조회 조건으로 제외된다. 신규 ID/공식 key를 추가할 때는 기존 R2 무기 매핑과 함께 확인한다.

장착 후보는 현재 공식 항목의 `official.addOnGroup.categories[].addOns[].name`과 슬롯이 일치해야 한다. 내부 표시명이 다른 기존 파츠는 `ATTACHMENT_IDENTITIES`에서 DB ID를 공식 식별명·슬롯에 연결한다. 예를 들어 `ar_compensator`의 `AR 보정기`는 `보정기(AR)`, `ar_eqd_magazine`의 `대용량 퀵드로우 탄창`은 AR 계열 탄창으로 연결하며 다른 계열에는 허용하지 않는다. 연결된 ID의 슬롯이 다르면 거부하고, 탄창 종류 계산에도 같은 식별명을 사용한다. 미등록 ID는 기존 이름 매칭을 유지한다.

공백과 확인된 AR·SR·SMG 계열의 묶음 표기 및 중량형·접이식 개머리판의 공식 수식어만 정규화한다. 다른 괄호 정보는 버리지 않고 구분한다. 총구·탄창 계열은 구분하며, 식별할 수 없는 파츠와 공식 목록이 없는 무기는 허용하지 않는다. 공식 도감 조회 상태(`loading`·`error`·`ready`)를 시뮬레이터에 넘겨 장착을 막은 사유를 구분해 안내한다. 공식 목록에는 있지만 대응하는 BGMS 파츠가 없는 부착물(`getMissingOfficialParts`)은 장착 불가와 별도로 "BGMS 파츠 자료 없음"으로 표시한다. 장착 핸들러와 계산에서도 같은 호환 검증을 적용하므로 과거 선택이 남아 있어도 무효 파츠는 수치에 반영되지 않는다. 실제 게임의 추가 부착물이 공식 도감에 누락되어 있으면 후보에서 제외될 수 있다.

탄창 용량은 무기 종류별 기본값이나 일괄 `+10`으로 추정하지 않는다. 현재 수치가 확인된 M416만 [공식 15.1 패치 노트](https://pubg.com/en/news/1727)를 근거로 기본·퀵드로우 30발, 대용량 42발, 대용량 퀵드로우 40발을 구분한다. 화면에 이 확인 기준을 표시하며 현재 게임 실측으로 표현하지 않는다. 다른 무기는 **공식 수치 미확인**으로 표시하고 용량 막대를 그리지 않는다. 공식 근거를 추가 확보하면 무기·탄창 종류별 용량과 출처를 함께 갱신한다.

반동·재장전은 게임 재현값이 아닌 BGMS 상대 지표다. 미장착 100에 호환 파츠 DB 보정값을 단순 합산하고 반동은 30, 재장전은 40에서 하한 처리한다. 차이는 하한 적용 후 값에서 100을 뺀 값이며, 비정상 숫자는 합산하지 않는다. 자세·연사·조준경 효과를 재현하지 않는다. 기본 무기 수치의 `patch_version`/`patch_applied_at`을 공식 수정일·수집일과 구분해 표시하고, 파츠 보정 자체의 적용 버전은 미확인으로 명시한다.

시뮬레이터 안의 BGMS 수치 카드·정렬·표 보기 기능은 **다른 무기 선택·BGMS 수치 보기**에 접어 두고 유지한다. 선택하면 문서 맨 위가 아니라 파츠 조작 영역으로 이동하며 키보드 포커스도 옮긴다. 상위 도감 탭과 시뮬레이터 접기를 왕복해도 마운트 상태를 유지한다.

## 무기 비교

도감 상세의 **비교에 추가**와 시뮬레이터의 **현재 구성 비교에 추가**는 같은 비교표(`components/game-data/WeaponCompare.tsx`)에 최대 4개까지 모은다. 같은 항목을 다시 누르면 뺀다. 상태는 `CatalogTabs`에만 있고 저장하지 않는다.

- 도감 항목(key `official:<공식 key>`): 공식 `specs`의 발 당 데미지·초 당 데미지(DPS)·연사속도·안정성·유효사거리·탄속과 탄약.
- 시뮬레이터 구성(key `build:<BGMS ID>:<정렬한 파츠 ID>`): 위 공식 값(연결된 공식 항목이 있을 때)에 장착 파츠, BGMS 데미지·초속, 반동·재장전 상대 지표, 탄창 용량을 더한다.
- 행마다 두 값 이상이 숫자일 때만 유리한 값을 강조한다. 모든 값이 비어 있는 행은 숨긴다.

## 시뮬레이터 수치의 검증 가능성

2026-11-16 운영 DB 읽기 조회 기준이다.

| 수치 | 공식 근거 | 검증 방법 |
| --- | --- | --- |
| 무기 기본 데미지 (`weapons.damage`) | 공식 도감 `발 당 데미지` | 가능. 다만 공식 값은 막대 표시라 100에서 잘리므로 100은 비교하지 않는다(`getOfficialDamage`). 시뮬레이터는 두 값이 다르면 경고를 표시한다. |
| 탄속 (`weapons.bullet_speed`, m/s) | 공식 `탄속`은 0~100 상대 막대 | 단위가 달라 직접 검증 불가. 순서 비교 정도만 가능하다. |
| 연사속도·안정성·유효사거리·DPS | 공식 0~100 상대 막대 | BGMS에 대응 수치가 없다. 비교표에 공식 값 그대로 표시한다. |
| 파츠 반동·재장전 보정 (`attachments.*`) | 공식 도감에 수치가 없다 | 불가. 22개 파츠 모두 출처·`patch_notes`가 비어 있고 값이 5·10 단위 정수다. 공식 패치 노트에 개별 변경이 나올 때만 부분 확인 가능하다. |
| 장착 가능 여부 | 공식 `addOnGroup` | 가능. 이 문서의 호환 규칙으로 판정한다. |
| 탄창 용량 | 공식 도감에 없음 | 공식 패치 노트로만 확인 가능(현재 M416 15.1). |

2026-11-16 대조에서 BGMS 기본 데미지가 공식 발 당 데미지와 다른 활성 무기 15개(M416·AKM·베릴 M762·미니14·Mk12·SKS·SLR·Mk14·드라구노프·VSS·M249·MG3·UMP·토미 건·JS9)를 공식 값으로 보정했다. 기존 패치 제안 경로를 그대로 사용했다: 제안 `5d0c2a6e-7b1f-4c3e-9a51-20261116a481`(라벨 `공식 도감 대조 (2026-11-16)`, 근거 `official_game_catalog` 해시)에 승인된 `update` 변경을 넣고 `apply_weapon_patch_proposal`로 적용해 `weapon_patch_apply_log`에 전후 스냅샷 15건이 남았다. 되돌릴 때는 이 로그로 기존 롤백 RPC를 사용한다. 보정 후 공식 값과 비교 가능한 33개 무기가 모두 일치한다. 샷건·AWM·링스 AMR은 공식 값이 100 상한이라 비교 대상이 아니다.

공식 도감에 없는 DP-28·QBU·PP-19 비존·모신 나강은 업데이트 42.1 제안(2026-08-02)으로 이미 소프트 삭제(`removed_at`)되어 앱 조회에서 제외된다. 남은 활성 항목 중 공식 무기 도감에 없는 것은 `folded_shield`(접이식 방패, 유형 Deployable)뿐이다.

## 로컬 검증

집중 검증은 `tests/official-catalog.test.ts`, `tests/official-catalog-ui.test.ts`, `tests/official-catalog-route.test.ts`, `tests/weapons-simulator.test.ts`, `tests/weapons-selection-ui.test.ts`, `tests/weapon-compare-ui.test.ts`와 기존 패치 버전·메타 UI 테스트를 함께 실행한다.

`tests/fixtures/catalog/simulator-attachments.json`은 2026-11-16 공개 조회로 확인한 활성 파츠 22개의 ID·표시명·슬롯·보정값이다. 계산·UI·브라우저 검사가 이 fixture를 공유해 실제 저장명과 공식 표기의 차이를 검증한다. M416의 다섯 슬롯, 총구·탄창 장착과 보정, SR 조준경·SMG 탄창 제한을 확인한다. fixture 갱신에는 공개 게임 데이터만 사용하고 인증 정보는 포함하지 않는다.

```bash
RUN_WEAPONS_BROWSER_SMOKE=true npx vitest run tests/weapons-browser-smoke.test.ts
```

브라우저 검사는 기존 `startOwnedStatsDevServer`를 재사용하여 실제 Next 페이지를 띄운다. 로컬 Supabase 응답 fixture와 격리 Chromium에서 375×667, 390×844, 430×932, 1440×1000을 검사하며 운영 API 요청과 DB 쓰기는 허용하지 않는다. 자신이 만든 서버만 종료하고 기존 Next lock은 삭제하지 않는다. 스크린샷은 Git 제외 경로 `tmp/weapons-browser-qa/`에 저장한다. 실제 모바일 앱·실기기·운영 데이터 검증을 대체하지 않는다.
