# 전적 재시도 점검과 R2 재압축

사용자 지시에 따라 전적 대기열 점검·제한된 추가 수집과 R2 측정·표본 재압축을 진행한다. 코드 작업은 `codex/discovery-r2-ops` 작업 폴더에서 수행하고, 기존 메인 `.env.local`은 읽기만 한다.

## 전적 점검

첫 운영 조회(2026-10-04 14:34 UTC)에서 미처리 38,009건, 재시도 196건(404 195건·네트워크 1건), 저장 완료 22,320건, 수집 불가 2,939건을 확인했다. 만료된 실행 점유나 인증·호출 한도 오류는 발견되지 않았다. 미처리 중 같은 platform/account/match와 유효한 필수 경기값이 이미 저장된 기록은 5,853건이었다. 이는 경기 삭제나 닉네임 기반 계정 결합 없이 기존 worker의 저장 확인 경로로 처리한다.

메인 환경 정보를 읽어 기존 worker를 최대 1,000건과 120건으로 두 번 실행했다. 합계 1,120건에서 신규 저장 558건, 기존 저장 확인 272건, 재시도 177건, 반복 404 수집 불가 113건을 처리했고 429는 없었다. 이 집계는 두 수동 실행의 처리 결과이며 전체 고유 경기 수·현재 잔여 큐를 뜻하지 않는다.

같은 시간 정기 실행 `37210373210`도 독립적으로 1,000건을 처리해 신규 저장 668건·기존 저장 확인 83건·재시도 172건·수집 불가 77건으로 성공했다. 수동 실행에 포함하지 않는다.

재시도 196건의 최초 발견 시각을 포함하는 범위(`first_seen_at <= 2026-09-19T20:47:00Z`)를 다시 조회해 재시도·실행 중 기록이 남지 않은 것을 확인했다. 반복 404의 수집 불가 판정은 실제 재조회 결과이며 모든 경기 복구를 뜻하지 않는다. 새로 발견되거나 이번 실행에서 처음 404를 받은 기록은 기존 6시간 대기 후 재확인 정책을 유지한다.

## R2 실행 방식

메인 `.env.local`에는 R2 관련 이름의 변수가 없었다. 운영 Vercel에는 네 가지 R2 변수가 sensitive로 등록돼 있어 로컬 값 추출 대신 기존 GitHub Secrets를 사용하는 수동 전용 `R2 JSON Maintenance` workflow를 추가한다. main의 검증 완료 코드에서만 실행하고 예약 발동·Discord 발송·삭제는 추가하지 않는다.

1. 최대 목록 페이지·시간을 제한한 경로별 객체 수·바이트 측정. 일부 조회는 `truncated`와 이어서 조회할 위치를 표시한다.
2. 비압축 JSON 표본 최대 20건을 읽어 실제 gzip 절감 바이트를 계산한다. 이미 압축된 객체·보호 경로·잘못된 JSON·큰 객체는 구분한다.
3. 원문과 HTTP 메타데이터를 로컬 복구 파일로 보관한다. Actions 적용은 보호 경로 `backups/r2-recompression/`에 암호화된 복구 사본을 조건부로 생성하고 실제 사본의 ETag·암호문을 다시 확인한 다음에만 원본 교체를 시작한다. 원본 ETag가 그대로인 경우에만 압축본으로 교체한다.
4. 교체본의 ETag와 압축 해제한 원문 바이트를 확인한다. 실패 복원도 교체본 ETag를 조건으로 사용해 다른 쓰기를 덮어쓰지 않는다.

R2의 `If-Match` 및 `start-after` 지원은 [Cloudflare 공식 S3 호환 문서](https://developers.cloudflare.com/r2/api/s3/api/)에서 확인했다. 원문 복구 파일은 공개 저장소 artifact에 평문으로 올리지 않는다. 로컬 파일도 tar.gz로 묶어 접근 자격 증명과 별도인 `R2_RECOVERY_ARCHIVE_KEY`로 AES-256-GCM 암호화한 파일만 7일 보관한다. 독립 복구 키는 GitHub Secret과 메인 폴더의 gitignored `.env.r2-recovery.local`(0600)에 보관하므로 R2 접근 키 교체와 무관하게 기존 archive를 열 수 있다. 복구 키 자체를 변경할 때는 이전 키가 필요한 archive를 먼저 안전하게 보존한다.

R2에 미리 보관한 암호화 복구 객체는 원본·메타데이터를 담은 gzip JSON이다. 같은 archive helper로 복호화하고 압축을 풀어 `originalBase64`와 원본 SHA-256을 대조한다. 복구 사본은 목록으로 추적하고 보호 경로에 유지한다. 저장 절감 보고는 `savedBytes`(원본 압축의 감소)에서 `recoveryBytes`(새 복구 객체 바이트)를 뺀 `netSavedBytes`를 사용한다. 원본 교체나 검증이 실패해 남은 복구 객체도 차감 대상이다.

복구 archive는 당시 독립 복구 키를 환경에 설정한 상태에서 다음 명령으로 복호화한다. 명령 인자나 로그에는 secret을 넣지 않는다.

```sh
node --env-file=.env.r2-recovery.local --import tsx scripts/r2_recovery_archive.ts open r2-recovery.enc r2-recovery.tar.gz
```

복호화된 원문은 현재 객체의 ETag와 확인한 복구 대상에 한해 사용한다. 보관 파일을 무조건 덮어쓰는 복원 작업은 실행하지 않는다.

## 검증과 운영 결과

로컬 집중 검증 38개와 전체 단위 테스트 3,329개가 통과했다(기존 제외 84개). `verify:core`는 오류 0개·기존 경고 44개였고 새 workflow의 actionlint 검사도 통과했다. 독립 코드 리뷰에서 암호화 복구 사본의 선행 저장·검증과 조건부 교체 경로를 확인했으며 남은 P1/P2 차단 사항은 없었다.

운영 R2 측정·표본 적용은 필수 PR CI가 통과하고 main에 병합된 뒤 수동 workflow로 실행한다. 각 실행의 집계·이어보기 위치는 Actions summary와 `r2-report.json` artifact에 보존한다. 경로별 측정이 끝나기 전 전체 버킷의 확보 용량을 추정하지 않는다.
