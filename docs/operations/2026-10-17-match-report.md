# 경기 흐름·경기 전체 판정과 최근 세션 — 2026-10-17

## 목적

경기 상세에 "어떻게 죽었고, 교전마다 결과가 어땠는지"를 보여 준다. 사망 유형·교전 결과·킬 트리·세션 묶기를 우리 텔레메트리로 계산할 수 있는 기준으로 정의했다.

## 저장 위치와 버전

- 분석 엔진이 `MatchReportCollector`(`lib/pubg-analysis/matchReport.ts`)로 이벤트 패스를 함께 관찰해 결과의 선택 필드 `matchReport`에 넣는다(`MATCH_REPORT_VERSION` 1).
- 개인 판정(착지·교전·사망·자기장·회복)은 내 사망 전 이벤트로 끝난다. 킬 트리·보급은 라이트 모드의 전멸 후 컷오프와 무관하게 모든 이벤트에서 모은다.
- `RESULT_VERSION`, `ANALYSIS_CALCULATION_VERSION`, `TELEMETRY_VERSION`은 올리지 않았다. 새로 분석하는 경기부터 채워지고, 예전 결과는 섹션을 숨긴다. 버전을 올리면 14일이 지난 경기는 텔레메트리가 없어 다시 계산할 수 없다.
- 실제 경기 두 판에서 리포트 크기는 17~18KB였다(대부분 킬 목록과 팀 순위).

## 판정 기준

| 항목 | 기준 |
| --- | --- |
| 착지 | 내 첫 `LogParachuteLanding` 기준 300m·600m 안에 처음 착지한 다른 팀 선수 수 |
| 교전 | 우리 팀과 적 팀 사이 전투 피해(자기장·출혈·낙하·익사 제외)·기절·처치를 30초 공백으로 나눈 묶음. 리플레이 "다음 교전"과 같은 `FIGHT_GAP_MS` |
| 교전 결과 | 적만 쓰러짐 = 승리, 양쪽 = 맞교환, 우리만 = 패배, 아무도 안 쓰러짐 = 이탈. 쓰러짐은 기절·처치를 선수별 한 번으로 센다 |
| 사망 유형 | 아래 순서로 첫 조건을 쓴다 |
| 자기장 | 새 흰 원(`poisonGasWarningRadius` 변경)이 정해질 때 내 마지막 위치가 원 밖이면 떨어진 거리(m) |
| 회복 | 내 체력 관측(위치·`LogHeal`)의 상승 합. 소생·리콜·재배치 직후 상승은 뺀다. 치료·부스트 횟수는 `LogItemUse`의 `subCategory`(Heal/Boost) |
| 교전 중 치료 | 교전의 첫 피해와 마지막 피해 사이에 쓴 치료 아이템 |

사망 유형 순서:

1. 자기장: 처치 피해 원인이 자기장
2. 출혈사: 기절 뒤 출혈 피해로 사망
3. 써드파티: 사망 전 60초 안에 우리 팀과 싸운 적 팀이 2팀 이상
4. 이동 중 잡힘: 마지막 교전 시작 전 30초에 150m 넘게 이동했거나 차량 안
5. 기습 당함: 킬러 팀이 먼저 쐈고 우리 팀이 킬러 팀에 준 피해가 100 미만
6. 고립: 사망 순간 가장 가까운 생존 팀원(최근 30초 위치)이 100m 초과
7. 정면 교전 패배: 위에 해당하지 않음

## 버전 3 판정 수정 (2026-10-18)

`MATCH_REPORT_VERSION` 3부터 아래처럼 계산한다. 버전 2 이하로 저장된 결과는 다시 계산하지 않으며, 아래 세 경우에 사망 유형·회복량이 다를 수 있다.

- 사망 유형의 고립 판정에 쓰는 팀원 거리를 사망 순간에 저장한다. 이전에는 경기 끝의 팀원 위치·사망 상태를 써서, 내가 죽은 뒤 팀원이 이동하거나 죽으면 판정이 바뀌었다.
- 리콜·재배치로 체력이 다시 생긴 구간을 회복량에서 뺀다. 이전에는 사망 후 리콜로 생긴 체력이 회복으로 집계됐다.
- 복귀 참가자는 단일 `character`·`recalledPlayer`와 `characters`·`recalledPlayers` 배열(중첩 `character` 포함)에서 읽는다. `LogPlayerRecallShip`, `LogPlayerCreate`와 재배치 이벤트 이름 변형도 엔진과 같은 복귀 경로로 처리한다.
- 사망 유형과 교전 중 치료 수는 전체 교전으로 계산하고, 화면의 교전 목록만 20개로 줄인다. 이전에는 20개로 먼저 잘라 21번째 이후 교전에서 죽으면 마지막 교전을 찾지 못했다.

## 버전 2 추가 항목 (2026-10-17)

`MATCH_REPORT_VERSION` 2부터 아래 필드가 있다. 버전 1 결과에는 없으므로 화면은 필드가 있을 때만 그린다.

| 필드 | 기준 |
| --- | --- |
| `versus` | 내가 낸 처치(`LogPlayerKillV2.killer`)·기절(`LogPlayerMakeGroggy`)·전투 피해를 상대가 봇(`accountId`가 `ai.`)인지로 나눈다 |
| `damageTaken.sources` | 내가 살아 있는 동안 받은 피해를 공격자별(공격자가 없으면 원인별)로 합친 상위 8개와 가장 많이 맞은 무기 |
| `damageTaken.hits` | 받은 피해 기록 최대 60건(시각·공격자·무기·부위·피해) |
| `myKills` | 내 처치마다 상대 무기(`victimWeapon`의 인스턴스 번호 제거), 상대 최종 팀 순위, 부위, 거리, 벽 관통, 그 상대를 기절시킨 쪽 |
| `kills[].diedKnocked` | 마무리 피해가 `Damage_DBNO`(기절 출혈·팀 전멸)인 사망. PUBG는 이 처치를 기절시킨 선수에게 준다 |

사람 팀 기준 순위는 화면에서 계산한다. 우리 팀보다 높은 순위에 봇만 있는 팀이 있을 때만 그 수를 빼서 보여 준다.

킬 트리에서 들여쓴 선수는 바로 위 선수가 처치한 상대다. 기절한 채 팀 전멸로 죽은 선수는 이미 죽은 상대의 처치로 기록될 수 있어 "기절 후 사망"을 함께 표시한다.

실제 우승 경기에서 `versus.human`이 공식 기록(처치 4·기절 2·피해 598)과 같았고, 받은 피해 합이 `heal.damageTaken`(233)과 같았다.

## 텔레메트리 한계

- 분석용 텔레메트리 계약은 보급 상자 내용물(`itemPackage.items`)과 `LogItemPickupFromCarepackage`, `LogHeal.healAmount`를 담지 않는다. 그래서 보급은 종류·페이즈·시각만 보여 주고, 회복량은 체력 관측 상승으로 계산한다. 계약을 넓히면 분석 캐시 형식이 바뀌므로 이번에는 손대지 않았다.
- 킬 트리는 마지막 처치 기준이다. 부활 뒤 다시 죽은 선수는 마지막 처치만 쓰고, 순환으로 루트가 끊긴 처치자는 별도 루트로 붙인다.

## 최근 세션

`lib/stats/recentSessionOverview.ts`는 최근 20경기 요약과 같은 경기 집합을 시작 시각순으로 정렬하고, 앞 경기와 60분 넘게 벌어지면 새 세션으로 나눈다. 가장 최근 세션의 경기 수·우승·킬·평균 피해·최고 순위·경기별 킬과 그 세션에서 2판 이상 함께한 팀원을 데스크톱 왼쪽 열에 보여 준다.

## 리플레이

- 2D 리플레이에 보급 상자 착지 위치를 그린다(착지 뒤 계속 표시, 20초 동안 이름표).
- 스페이스 재생/정지, 좌우 방향키 5초, Shift+방향키 30초 이동. 입력 칸과 포커스된 버튼에서는 기본 동작을 막지 않는다.
- 따라가기를 켰을 때 쓰는 두 설정(`lib/replay/replayCamera.ts`)
  - 인지 범위(기본 꺼짐): 따라가는 선수에게서 150m 밖이고 최근 20초 안에 우리 팀과 교전하지 않은 적을 25% 투명도로 그리고 이름을 숨긴다. 시야·차폐 정보가 텔레메트리에 없어 거리로 추정한 표시이며 범례에 "추정"으로 적는다.
  - 자동 줌(기본 켜짐): 최근 4초 이동 속도로 화면 폭에 담을 거리를 정한다(멈춤 300m, 도보 최대 550m, 차량 최대 2km). 정수 줌 차이가 0.75 이상일 때만 바꾸고, 바꾼 뒤 1.5초는 유지한다. 휠·핀치·더블클릭·줌 버튼으로 직접 줌하면 꺼진다.
- "링크" 버튼은 현재 주소에 `t`(초)를 붙여 복사한다.
- 사용법 창(`components/map/telemetry/ReplayHelpDialog.tsx`): `?` 키, 넓은 화면의 재생 줄 `?` 버튼, 좁은 화면의 설정 안 "사용법" 버튼으로 연다. 재생·따라가기·지도 표시·데이터 한계를 설명하고, 숫자(이동 초, 인지 거리, 교전 리드인)는 코드 상수에서 읽는다. 처음 연 사람에게는 재생 패널 맨 위에 안내 줄을 10초 동안 보여 주고, 열거나 본 뒤에는 브라우저에 `bgms.replay.helpSeen`을 남겨 다시 띄우지 않는다. 경기 흐름의 교전 줄 "리플레이"도 같은 `t`로 교전 3초 전부터 연다.
