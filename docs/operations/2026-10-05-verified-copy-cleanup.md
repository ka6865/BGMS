## 현재 사본 검증

`verify_legacy_match_copies.ts`는 기존 감사에서 바이트 SHA가 같았던 20쌍만 다시 GET한다. 각 본문은 32MiB, 전체 읽기는 128MiB, 작업은 180초로 제한한다. S3 GET의 실제 ETag·바이트와 DB의 현재 계정·경기·관측 스탯을 대조한다. root v60/v61 analyze 파일만 받으며, 보호 prefix의 자료와 개인별 최신 지도는 대상에 넣지 않는다.

같은 본문이라고 다음 조건을 생략하지 않는다.

- 공식 `LogMatchDefinition`의 경기·플랫폼이 일치하고 원본 이벤트에 각 계정·닉네임 연결이 있어야 한다.
- 기존 DB 기록이 두 계정과 유일하게 연결돼야 하며, 시각·맵·킬·대미지·순위는 실제 관측값이어야 한다.
- 원본 파일 또는 인접 지도 키가 master·registry에 남아 있거나 활성 lease가 있으면 제외한다.
- 검증된 전체 공통 source envelope가 이미 있어야 한다. 기존 개인 이벤트 배열을 전체 공식 경기 자료로 승격하지 않는다.
- 보존할 이벤트와 공통 원본의 전체 허용 이벤트가 동일해야 한다. 두 계정의 지도 재계산과 실제 운영 조회 내용이 같아야 하며 상세 API도 같은 경기·닉네임이어야 한다.

결과에는 차단 사유 집계만 공개한다. 원본 키·계정·ETag·본문 해시는 private 파일에만 남기고 artifact는 기존 recovery secret으로 암호화한다. 대상 목록은 repository secret `R2_LEGACY_COPY_TARGETS`에 보관한다. 운영 credentials를 로컬 보고서나 PR에 넣지 않는다.

## 한 쌍만 적용하는 순서

workflow는 main 수동 실행만 지원하고 기본값은 verify다. apply는 20쌍 중 한 쌍을 선택하며, 앞선 verify에서 나온 plan hash가 같아야 한다. 모든 조건을 현재 상태로 다시 검증한다.

적격 한 쌍은 정확한 원본 바이트를 보호 경로 `telemetry-source/legacy-corpus/v1/<sha>.json`에 조건부 생성하고, 두 기존 키와 두 DB 전적 레코드를 연결한 암호화 alias를 별도 보호 경로에 보관한다. 기존 키의 암호화 alias도 동일 manifest여서 두 기존 파일명에서 복구 연결을 잃지 않는다. 둘 다 실제로 다시 읽고 인증·원본 SHA·식별·복구 레코드를 확인한다. 공통 원본과 canonical alias를 조건부 생성하며, 원래 사본 두 개는 뒤의 조건부 대체 단계에서만 바꾼다.

`restore_legacy_player_matches.ts --alias-key ...`의 기본 dry-run이 두 DB 레코드를 그대로 확인해야 진행한다. 원본 바이트와 alias가 durable R2에 있고 암호화 복구 journal도 로컬 및 보호된 원격 backups 경로에서 readback한 뒤 DB 참조·lease·원본 ETag/SHA를 다시 조회한다. 기존 root 두 사본은 `If-Match` 조건부 PUT으로 작은 암호화 alias로 대체하고, 각 쓰기의 실제 readback을 확인한 뒤 두 계정의 조회·재계산과 alias 소비를 재검증한다. 원본 키가 바뀌면 412로 중단하며, 별도 DeleteObjects 요청은 하지 않는다. 삭제된 객체 수는 항상 0이고 실제로 작아진 객체 수와 순절감 바이트를 보고한다. 보호 corpus·alias는 일반 정리 가드로 삭제할 수 없다.

alias 복구의 `--apply`는 없는 DB 레코드만 ignore-duplicates로 삽입하고 실제 저장을 다시 확인한다. 기존 레코드와 충돌하면 덮어쓰지 않는다. 원래 R2 backfill에는 이 alias 경로를 추가하고, 없는 시각·맵·플랫폼·0킬·99등을 만들던 기본값을 제거했다. raw 배열을 기본 경기 레코드로 오인하지 않는다.

리뷰에서 확인한 무조건 삭제의 경합 위험 때문에 삭제를 조건부 alias 대체로 변경했다. 조건부 PUT은 파일 버전 변경을 원자적으로 거절하지만 DB 참조와 같은 트랜잭션은 아니다. 기존 버전 root만 제한하고 즉시 재조회·활성 lease 배제·키와 복구 연결 유지·보호 원본 보관으로 위험을 줄인다. 새로운 writer가 추가되면 이 범위와 쓰기 규약부터 재검토해야 한다. 검증 실패 또는 적격 0이면 사본을 보존하며, 용량이 줄었다고 보고하지 않는다.

## 검증

전체 단위 테스트 3,403 pass/86 skip, 분석 테스트 634 pass, core 오류 0/기존 경고 43. 새 runner의 조건 변경·참조 추가·복구 읽기 실패·부분 조건부 대체와 집계 테스트 19개를 확인했다. 독립 리뷰의 두 P1 및 한 P2는 조건부 대체·부분 집계·원격 journal 보존으로 수정했고, 남은 alias 자동 소비 P2도 기존 backfill에 추가했다. CI에서 최종 설치·정적·전체 단위·격리 migration·의존성 감사를 재확인한다. Actions 예약 간격은 설정상 20분이지만 실제 최근 실행 간격은 수 시간이어서 manual 성공을 예약 문제 해결로 간주하지 않는다.

실제 20쌍의 현재 GET 결과와 순절감량은 수동 verify 실행 이후 이 문서에 추가한다.
