# 랭킹 자동 계산 및 만난 상대 운영

## 구현 범위

- 킬·피해량 랭킹은 최근 7일 `pubg_player_matches` 기본 기록에서 집계한다. 상세 페이지를 열 필요가 없다. 경기 시각으로 기간을 자르며 Steam/Kakao 및 계정 식별자를 구분한다.
- BGMS 성과는 기존 상세 분석 또는 별도 계산 작업의 현재 버전 결과를 사용한다. 모든 PUBG 플레이어를 수집하는 랭킹이 아니라 BGMS에 확보된 경기 기준이다.
- 자동 계산 대상은 최근 7일 활동한 연결 프로필의 최근 7일 적격 경기다. 단순 검색된 모든 계정이 대상은 아니다.
- 전적 헤더의 ‘만난 상대’에서 나를 기절시킨 상대, 나를 죽인 상대, 개인 관심 목록을 구분한다. 최근 90일 저장 경기, 페이지당 10경기를 사용한다.
- 텔레메트리 계정 ID로 상대를 식별한다. 가려진 신고 알림 닉네임과 추측으로 연결하지 않는다. 관심 등록은 신고 접수나 부정행위 확정을 의미하지 않는다.
- 상대 공식 경쟁전 티어 및 해당 경기 모드의 시즌 평균 피해량을 표시한다. BGMS 성과 등급과 공식 티어는 다른 값이다. 없는 기록은 0으로 추정하지 않는다.

## 반영 순서

로컬 코드와 SQL만 준비된 상태이며 운영 반영은 별도다.

1. 기존 `20260911100000_pubg_match_discovery.sql`, `20260911110000_pubg_ban_watch.sql` 의존성을 적용한다.
2. `20260913090000_pubg_rankings_and_performance.sql`, `20260913100000_pubg_encounter_page.sql`, `20260915090000_pubg_release_hardening.sql`을 적용한다.
3. 새 컬럼을 사용하는 코드를 배포한다. 코드 선배포 시 전적 저장이 실패할 수 있으므로 DB가 먼저다.
4. 기본 조회 및 권한을 확인한 뒤 자동 작업을 선택적으로 활성화한다.

새 테이블은 서비스 역할 전용이다. 기존 전적·벤치마크 테이블을 삭제하지 않는다. `pubg_player_matches`에 nullable 식별·적격성 컬럼을 추가한다. 운영 데이터 전체에 대한 사전 성능 측정이나 실제 마이그레이션 실행은 아직 하지 않았다.

## 부하 제한

`pubg-performance.yml`은 `PUBG_PERFORMANCE_ENABLED` 저장소 변수와 실행 환경 값이 true일 때만 동작한다. 기본 1시간 주기이며 GitHub 일정 지연이 가능하다.

- 전역 동시 계산 1개, 실행당 최대 3경기·4분, 하루 최대 30회 claim.
- 계산 자식 프로세스 V8 힙 상한 512MB, 경기당 110초. 프로세스 전체 RSS 상한을 보장하는 값은 아니다.
- 대기·재시도·실행 큐 합계 300개, 한 번에 최대 50개 추가.
- 실패는 재시도하되 최대 3회, 오래되거나 버전이 달라진 작업은 제외한다.
- AI 코칭 요청을 하지 않는다. 기존 계산 엔진을 재사용한다.
- 실행마다 90일 지난 성과 및 종료 작업을 각 500행까지 정리한다.

랭킹 화면이 보이는 동안의 60초 재조회는 같은 필터 결과를 서버에서 60초 공유하므로 사용자 수만큼 DB 집계를 반복하지 않는다.

상대 정보는 모드별 시즌 캐시를 6시간 재사용한다. 추가 공식 API 요청은 전역 분당 2회이며 시즌 조회도 이 한도에 포함한다. 다른 기존 기능의 요청량까지 통합 제어하는 한도는 아니다. 요청 제한 시 재시도 시각을 표시한다.

상대 추출은 완료된 빈 결과도 캐시한다. 전역 추출 lease 1개와 사용자 요청 제한을 적용한다. 개인 관심 목록의 증거와 일시적인 상대 캐시는 별개다. `pubg-encounter-cache.yml`은 `PUBG_ENCOUNTER_CACHE_ENABLED=true`일 때만 실행하며 상대 캐시 90일, 프로필 캐시 30일 이후 각 500행까지 정리한다.

## 제재 확인 범위

공식 계정 상태의 임시·영구 제재를 구분하며 마지막 확인 시간을 표시한다. 임시 제재는 해제 전에 조회하지 못하면 놓칠 수 있다. 제재 사유·기간·사용자의 신고와의 인과관계는 공식 상태만으로 확인할 수 없다. 세부 제재 워커 운영은 `pubg-tracking.md`를 참고한다.

최종 전적 검색·헤더·목록 및 특정 경기 API 회귀 검증: 13개 파일 74개 테스트 통과. 특정 경기 화면은 페이지 순회 없이 한 경기만 읽고, 일반 전적과 동일한 상세 분석·과거 기록 안내를 사용한다. 헤더의 기존 제재 팝오버 테스트는 만난 상대 링크·클랜 팝오버 동작 테스트로 갱신했다.
