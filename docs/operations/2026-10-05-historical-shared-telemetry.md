# 과거 경기 조회와 경기별 공통 이벤트 저장

사용자가 승인한 범위는 저장된 과거 경기를 실제로 조회할 수 있게 하고, 같은 경기의 공통 이벤트를 플레이어마다 중복 저장하지 않는 것이다. 개인별 분석 결과와 지도, 비공개 플레이어 차단, 정확한 경기·플랫폼·계정 검증을 유지한다.

## 구현 결과

1. 지도는 해당 경기·플랫폼·닉네임에 연결된 DB 계정을 확인하고 비공개 검사를 통과한 뒤, 같은 계정·모드의 준비된 지도 캐시를 먼저 읽는다. 등록부 버전과 경로 및 파일 내부 식별자가 모두 맞아야 URL을 발급한다.
2. 서버 전용 `telemetry-source/v1/{platform}/{matchId}.json`에 공식 경기 정보·참가자·팀과 full 이벤트 projection을 함께 저장한다. 이벤트 계약 버전은 지도/점수 버전과 분리하고, checksum을 검증한다. 이 파일은 브라우저에 직접 제공하지 않는다.
3. 두 요청이 동시에 최초 저장해도 `IfNoneMatch: "*"`로 같은 파일을 덮어쓰지 않는다. 저장 경로는 정리 가드에서 보호한다. 기존 `_analyze.json`은 읽기 호환을 유지하고 새 사용자별 이벤트 파일은 생성하지 않는다.
4. 공통 기록이 있으면 상세 분석과 지도 생성 모두 공식 경기 메타데이터와 이벤트를 재사용한다. 기존 일반 요청·관리자 강제 재조회·벤치마크 복구의 권한 경계를 유지한다.
5. 저장 자료 없는 경기에는 기존 외부 조회를 사용한다. 불완전한 과거 이벤트로 공식 스탯·팀·시각을 만들어내지 않는다. 이미 보관된 기본 전적은 PUBG 404만으로 없어지지 않게 한다. 이전 404의 임시 캐시보다 DB 결과와 공통 자료를 먼저 확인한다.
6. `MatchCard`와 `ExpandedMatchDetails`의 14일 초과 경기 조회 제한을 제거했다. 펼칠 때만 상세 API를 호출하고, 성공 후 접었다 다시 펼치면 재사용한다. 날짜 안내는 보관 자료가 있으면 상세 기록·리플레이를 제공한다는 문구로 바꿨다. 3D 지원 여부는 맵 기능을 기준으로 판단한다.

## 리뷰와 최적화

독립 리뷰에서 나온 다음 문제를 수정하고 재리뷰했다.

- 기존 개인 `_analyze.json`의 `projection: full` 표시만으로 전체 이벤트 보존을 증명할 수 없다. 이 파일은 해당 플레이어의 읽기 호환으로만 사용하며, 공식 자산과 경기·플랫폼·계정 증거를 검증한 새 원본에서만 공통 자료를 만든다.
- 구형 분석 결과의 최상위 `accountId`/`playerId`도 과거 계정 조회에 사용한다. 중첩 계정과 충돌하면 잘못된 지도 URL을 발급하지 않는다.
- 공통 자료의 R2 읽기가 실패해도 외부 조회 경로를 계속 사용할 수 있다. PUBG 404와 보관된 기본 결과가 함께 있으면 공식 기본 스탯만 제공한다. 구형 점수·AI 문구는 이 응답에 섞지 않는다.
- 화면의 날짜 제한도 제거해 API 개선이 실제 상세 화면에 반영되도록 했다.
- 공통 자료의 보관 실패는 경기·플랫폼·경로를 포함한 경고 로그로 남긴다. 검증된 이벤트로 진행 중인 개인 분석과 지도 생성은 계속한다. 이 경우 공통 자료가 보관되었다고 간주하지 않으며, 자동 재시도 큐는 이번 변경에 포함하지 않았다.

새 공통 자료는 필드 검증 후 체크섬을 한 번만 계산한다. 허용 이벤트 집합을 재사용하며, 지도 후보는 최신 준비 버전부터 최대 8개를 검사하고 첫 유효 결과에서 끝낸다. 이벤트 투영은 저장 경계에서도 유지해 계약 밖의 필드가 보존되지 않게 한다. 같은 경기 동시 요청은 조건부 생성으로 한 공통 객체에 수렴한다. 동시 첫 요청의 외부 다운로드 자체를 하나로 묶는 별도 분산 잠금은 추가하지 않았다.

회귀 검증은 외부 API가 404여도 저장된 지도를 조회하는 흐름, 공통 기록만으로 개인별 분석과 지도를 생성하는 흐름, 다른 계정·플랫폼·모드·경기/잘못된 파일 경로/미래 버전/비공개 요청의 차단, A/B 요청의 원본 공유 및 개인 결과 분리, 부분적인 개인 이벤트 파일의 승격 방지, 기존 recovery/circuit-breaker 동작을 포함한다. 14일 초과 경기 펼침과 상세 재사용도 검증한다.

## 운영 적용 범위

이번 변경은 신규 저장 구조와 기존 자료의 읽기 경로를 개선한다. 기존 R2 파일의 일괄 이동·삭제, 운영 DB 마이그레이션과 수집 작업은 수행하지 않는다. 이미 저장한 개인별 파일은 새 공통 자료가 검증된 뒤 별도 정리 단계에서 다룬다.

과거 지도는 DB에 계정 연결과 준비 상태가 있고, 파일 식별자·경로·모드가 검증되는 경우에 제공한다. 새 공통 자료는 공식 참가자 스탯·팀·시각까지 포함하므로 PUBG 조회 없이 재분석할 수 있다. 기존 배열만 있고 공식 경기 정보가 남지 않은 자료까지 모두 복구되었다고 판단하면 안 된다. 유효한 기본 전적만 남은 경우에는 기본 기록을 제공한다. 기존 개인별 지도와 분석 결과 및 AI 코칭의 계정별 저장은 유지한다.

로컬 검사에는 공유 `node_modules`를 사용했다. 모바일 브라우저 검사는 가짜 자격 증명과 fixture API를 사용하며 실제 PUBG·R2·Supabase 운영 요청을 보내지 않는다. 실제 iOS Safari·Android 기기와 운영 자료 검증은 후속 단계다.

## 로컬 검증 결과

- 전체 단위 검증: 297개 파일, 3,362개 테스트 통과, opt-in 등 86개 건너뜀.
- 과거 경기 브라우저 검증: 375×667, 390×844, 430×932, 1440×900에서 13·15·91일 경기 상세 조회 및 접기/다시 펼치기 재사용 확인. 네 사례 모두 통과했고 페이지 오류와 가로 넘침이 없었다. 저장한 화면도 확인했다.
- 정적 검사: 린트 오류 0개, 기존 경고 43개, TypeScript 검사 통과.
- 첫 브라우저 시도는 공유 의존성 symlink의 Turbopack 제한과 Webpack 첫 컴파일 대기로 실패했다. 설치된 Next 가이드의 `--webpack` 모드로 전환하고 컴파일 후 재검증했다. 전체 테스트·첫 컴파일을 동시에 실행했을 때 발생한 두 시간 관련 실패는 부하를 줄인 후 해당 파일과 전체 검증을 다시 실행해 통과했다. 테스트의 시간 제한을 늘리거나 실패 검사를 제거하지 않았다.
- 독립 리뷰 두 차례와 지적 사항 수정 후 재리뷰 완료. 운영 DB/R2 직접 쓰기·삭제와 일괄 자료 전환은 실행하지 않았다.

## 후속 작업

1. 배포 후 14일 초과 경기의 기본 기록·등록된 지도 조회와 같은 경기 A/B의 공통 자료 재사용을 소수 사례로 확인한다. 자료가 없는 경기의 안내와 비공개 차단도 함께 확인한다.
2. 공통 원본 생성 수·재사용 수, 외부 API 호출 수와 주간·월별 저장 증가량을 측정한다. 신규 저장 중복이 얼마나 줄었는지 확인한 뒤 추가 최적화를 정한다.
3. 기존 사본의 전환 후보를 dry-run으로 계산한다. 경기·플랫폼·공식 메타데이터·전체 이벤트 보존 근거·이벤트 해시·참가 계정 연결을 모두 대조한다. 개인용 `full` 표시나 이름이 같은 파일만으로 전환하지 않는다.
4. 공통 자료로 실제 조회·재계산 가능한 것이 확인된 경기부터 기존 중복·구버전 사본을 작은 묶음으로 정리한다. 유일 자료와 검증 불가 자료는 보존한다.
5. 새 객체의 기본 gzip 압축은 유지한다. 기존 미압축·낮은 압축 자료의 재압축 절감량을 측정한 뒤 적용한다. 보존 기간은 제공할 과거 조회 기간과 실제 이용량·비용을 근거로 별도로 정한다.
