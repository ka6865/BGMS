# 최근 경기 입력과 코칭 근거 검증 보강

## 확인한 문제와 수정

- Steam `MiaeQ_Q`에서 전적 목록은 10월 26일 경기를 표시했으나 AI는 프로필 캐시의 10월 5일 이전 경기 ID를 사용했다. 수동 전적 갱신 뒤 요약 생성은 성공했다. 이 관측만으로 최초 실패의 HTTP 원인을 확정하지는 않는다.
- `useStatsPageController.recentMatchIds`는 전체 전적 첫 페이지의 경기 ID를 보존한다. 첫 응답 전에는 AI를 마운트하지 않고, 페이지 이동과 모드 필터는 이 목록을 바꾸지 않는다. 최초 이력 조회 중 선택한 필터는 전체 목록을 확보한 뒤 적용한다. 이력이 비었거나 조회가 실패하면 기존 프로필 경기 ID를 사용한다.
- AI 입력과 최근 20경기 요약은 이 목록을 함께 사용한다. 상세 제공 기간 만료와 canonical 분석 미준비는 일반 네트워크 오류와 구분해 안내한다.
- 단판·요약 칭호에서 전선·돌파·돌입·진입 추론을 차단한다. 단판 칭호의 침착한·냉철한 수식어도 제거한다. 단판 기여 근거에 피해량과 1:1 교전 승리를 포함해 양수 기록을 성과 전무로 표현하지 않게 한다. 개별 처치 0회 사실은 보존한다.
- `isEarlyElimination`을 점수와 단판 프롬프트·후처리에서 공유한다. 기준은 생존 600초 미만 또는 실제 사망하면서 3페이즈 이하이다. 관측값이 부족하면 분류를 보류한다. 점수 산식 자체는 변경하지 않았다.

## 캐시와 영향 범위

- DB schema, 엔진 계산 버전, 결과 버전, AI 캐시 키는 변경하지 않는다.
- 단판 캐시 hit에도 `applyMatchAiEvidencePolicy`, 요약 v2 캐시 hit에도 `normalizeSummaryCardFinal`이 재적용되므로 기존 응답의 칭호와 해당 문장도 보정된다.
- 첫 반격 150ms 미만 제외, 비교 모집단 변경, 운영 데이터 재계산·삭제는 포함하지 않는다.

## 재검증 기준

- 프로필의 오래된 ID와 저장 이력의 최신 ID가 다를 때 최신 이력만 AI에 전달한다. 첫 응답 대기·필터 변경 경합·페이지 이동·플레이어 변경의 소유권을 검증한다.
- 피해/교전 승리/기절이 있는 성과 전무 문장, 돌파·진입 칭호, 600초·3페이즈 경계와 생존자, 캐시 재처리의 멱등성을 확인한다.
- 실제 Steam `MiaeQ_Q` 론도 26위 경기로 매운맛·다정한맛 Gemini를 호출했다. 피해 106, 팀 피해 비중 67%, 소생 1/2회, 생존 224초를 원본과 대조했다. 기존 v22 요약의 칭호 재정규화와 생존 평균 3.2 대 4.26, 유틸리티·포지셔닝 판정 보류도 확인했다. 전체 요약을 신규 Gemini 호출한 검증과 구분한다.
- UI는 fixture 하네스에서 375x667, 390x844, 430x932, 1440x900의 만료/미준비 오류·부분 성공 상태를 확인한다. 네이티브 모바일 실기기 검증은 포함하지 않는다.
