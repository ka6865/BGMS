# 롤 검색 저장 성능과 검색창 개선 계획

사용자 요청: 검색 시 DB 시간 초과를 수정하고 즐겨찾기·최근 검색·닉네임 추천을 배그 전적 검색창과 같은 흐름으로 제공한다. 기존 격리 워크트리에서 구현하고 로컬·운영 검증 후 main에 머지한다. 사용자의 마지막 지시로 앱 배포는 제외한다.

## 설계

- 저장 함수 계약, 트랜잭션, RLS 및 경기 중복 집계 방지를 유지한다. 계정별 요약은 참가자 인덱스로 경기부터 좁히고 JSON을 읽는다. 통계 히스토그램은 표본을 구간별로 한 번 집계한다. 운영 실제 요청에서 집계 시간 초과가 남아 검색 저장 성공 뒤 경기별 별도 RPC로 집계한다. 중단된 집계는 기존 원문과 처리표의 차집합으로 찾아 3시간 정기 작업에서 재처리한다. 제한 시간 증가와 새 큐 테이블은 도입하지 않는다.
- 검색창 포커스 시 즐겨찾기 우선·최근 검색 중복 제외 목록, 행별 별표와 삭제 버튼. 두 글자 이상에서 300ms 디바운스로 저장된 KR 계정만 추천한다. 게임 이름과 태그를 함께 보여주고 선택 시 기존 전적 URL로 이동한다. Riot API 자동완성 호출 없음.
- 추천 계약: GET /api/lol/suggest?q=... → { suggestions: [{ gameName, tagLine }] }, 최대 8개. 관리자도 같은 공개 계정 이름 조회를 쓴다. PUUID와 비밀 필드 제외, prefix 및 태그 리터럴 검색, 쿼리 길이 제한, 실패 시 검색 자체는 유지한다.
- 키보드 방향키·Enter·Escape, 한글 조합 중 Enter, 늦은 응답·요청 취소, 저장소 실패, 모바일 넘침을 점검한다. 기존 localStorage 키와 기록 한도는 유지한다.
