# 코칭 판단 보강 1차 실행 계획

설계: `docs/specs/20260907-ai-coaching-quality-growth.md`. 사용자가 실행을 승인한 첫 구현 단위만 다룬다. 모델 교체, 계산식·등급 변경, 운영 DB 쓰기, 배포는 포함하지 않는다.

1. `tests/ai-coaching-judgment.test.ts`에 실제 실패 표현과 정상 조언을 고정한다. 원본 응답의 비난이 순한 부족 판정으로 바뀌는 사례, 연막 구출 결과에서 사용 의도를 단정하는 사례, 소수점·JSON·메타데이터 보존과 재적용을 검사한다.
2. `aiCoachingQuality.ts`의 근거 없는 비난 치환을 문장 단위 판단 보류로 바꾼다. 다른 정상 문장과 구조화된 메타데이터는 유지한다. `backupCoaching.ts`에서도 같은 정책을 먼저 적용해 원래의 비난이 순한 단정으로 숨지 않도록 한다.
3. 개인·팀 프롬프트에서 근거 없는 비난의 대체 문구로 협업 부족을 권장하는 지시를 제거한다. 관측 사실과 일반 연습을 구별하게 한다. 요약 카드에서 새 보류 문장만 남은 의견은 승자를 만들지 않는다.
4. 기존 회귀 테스트의 근거 없는 치환 기대값을 새 정책에 맞추고, fresh/cache API 응답과 요약 카드 경계를 검증한다. 기존 실제 Gemini 감사 도구를 재사용하며 이번 변경 검증에 외부 API 호출을 필수로 추가하지 않는다.
5. 관련 Vitest와 변경 파일 ESLint, 타입 점검을 실행하고 결과를 설계 문서에 남긴다. 두 서브 에이전트 변경은 별도로 리뷰해 미해결 사항과 완료 상태를 구분한다.

장기 모델 비교·비용 계측·토론 결론 계약 확장은 설계 문서의 후속 단계로 유지한다. 이 첫 변경으로 자연어 전체의 의미를 검증했다고 주장하지 않는다.
