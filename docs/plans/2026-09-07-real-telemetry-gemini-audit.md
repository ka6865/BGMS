## 실제 Gemini에서 발견한 후처리/프롬프트 오류

처음 호출은 개인 6개 성공, 요약 1개 검증 실패, 스쿼드 2개는 benchmark 부재로 호출 전 실패했다. HTTP 성공인 개인 응답에도 다음 오류가 있었다.

- 총 투척 12회를 피해형 투척으로 혼동 → 사실 필드의 투척 수/적중률을 canonical 값과 대조.
- 고립도 0.36인데 ‘고립형’, 비교 표본이 없는데 ‘상위권보다 느림’ → 관측 지표와 비교값 가용성으로 보정.
- 후방 대기/숨기/소극적 의도와 연막 구출 0회→연막을 아꼈다는 단정 → 프롬프트의 모순된 지시 제거, 확인된 실패 문장 패턴 보류.
- 비교 표본이 없는 내 기록의 서술까지 지워져 요약 검증 실패 → 관측된 해당 카드 지표의 숫자 없는 설명 허용. 비교 주장·임의 숫자·다른 지표는 계속 제한.
- 스쿼드 benchmark 0건 또는 표본 부족 → 내 관측 기록은 제공, 비교값/의존 점수/종합 등급은 null. 실제 DB 오류와 canonical tier 오류는 계속 차단.
- 백업 비교값 null에서 원인 장면이 기본 12초를 비교 기준으로 사용하지 않도록 명시적 null 전파.
- 실제 MiaeQ_Q의 기절 비중 21%를 킬 기여도 21%로 옮겨 쓴 응답 → 해당 선수·지표별 비중과 대조. 킬 비중은 36%. 새 응답과 캐시 읽기에 같은 보정 적용.

마지막 전체 호출은 개인 6개/요약 1개/스쿼드 2개 **9개 모두 정상 응답**했다. 최신 회원별 비중 보정은 별도 스쿼드 호출과 오답 문장 회귀로 확인했다. 이는 JSON/경로 정상과 재현된 오답 보강의 결과이며 자유 문장의 의미를 전부 검증한 것은 아니다. 배지/역할 분류·‘안전 소생’·위치 해석 등 기존 휴리스틱의 이름도 관측 사실과 계속 맞춰야 한다.

## 배포 전에 남은 필수 작업

1. **개인/스쿼드 범위 분리**: `squadAnalysis`는 요청자의 `isolationData.isolationIndex`와 `tradeStats.tradeLatencyMs`를 팀 평균처럼 사용한다. 현재 0.66/5.596초는 MiaeQ_Q 기준이며 팀 전체 값으로 검증한 것이 아니다. 개인 기절 분모와 팀 소생 분자가 섞이는 경로도 함께 정리해야 한다. 한 경기 원본에서 팀 전체 기절→가해자 처치/소생을 중복 없이 산출하고, 합계·관측 수·scope·version을 별도 계약으로 저장한다. 팀 거리 지표는 개인 평균을 복제하지 말고 팀 단위 정의를 먼저 검증하며, 미관측이면 보류한다.
2. **계산 버전 이행**: 이번 신규 결과는 calculationVersion=2, 단일 AI 프롬프트 키는 `.calc2`. 기존 processed 결과/public v61 지도 캐시는 자동으로 수정되지 않는다. benchmark 저장·집계·조회에 같은 계산 버전 조건이 필요하다. 구형 v73 결과와 신형 계산 결과의 혼합을 허용한 채 main에 올리지 않는다.
3. **제한된 재계산**: v72→v73 복구 RPC와 결과 identity 계약을 보존하며 보관 원본이 있는 최근 요청 경기만 처리한다. 원본이 없는 기록은 해당 비교/코칭을 보류한다. 일괄 Gemini 재생성은 하지 않는다.
4. **집중사격 보정**: 기존 실험 window 3/5/8초는 유지. 두 경기만으로 엄호 능력/종합 등급을 해제하지 않는다.

계산식 수정과 문장 보정은 추가 운영 Gemini 호출이나 DB 조회를 요구하지 않는다. 이번 감사의 공급자 호출은 검증용이며 일반 단위 테스트/CI에서는 실행되지 않는다. 비교값이 없을 때 스쿼드 부분 코칭을 허용하므로 기존에 거절되던 사용자 요청에서 실제 호출이 발생할 수는 있다.
