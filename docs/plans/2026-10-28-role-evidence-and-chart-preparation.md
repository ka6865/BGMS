# 칭호 근거·기준 분포·삼각형 점수 개선 준비안

상태: 구현 전 준비안. 2026-10-28 사용자 요청인 “전부 개선할 준비”의 범위·의존성·검증 조건을 정리한다. 제품 코드, 운영 데이터, PR, 배포는 변경하지 않는다.

기준: 하위 워크트리 `ka6865/coaching-reference-recalibration`, 커밋 `969daf714c99b3ade4d57b220c220e73acabeee5`. 이 브랜치의 동작을 현재 운영 배포와 동일하다고 단정하지 않는다. 구현 시작 시 main·관련 PR의 실제 상태와 차이를 다시 확인한다.

## 목표와 접근

개인 행동이 정확히 귀속되고 관측된 근거에 맞는 칭호를 부여한다. 근거 부족·경계 상태·균형형을 구분하고, 모드에 맞는 기준 분포를 사용하며, 삼각형은 영역별 배점 대비 달성률을 표시한다.

- 화면 문구만 고치면 중복 구조·타인 협공이 점수에 남는다.
- 모든 점수 배점까지 함께 재설계하면 오류 교정의 효과와 정책 변경의 효과를 구분하기 어렵다.
- 권장: 기존 배점과 경기 선택 규칙을 유지하면서 원본 귀속 → 관측 계약 → 칭호 → 기준 분포 → 화면 순으로 수정한다. 삼각형은 별도 작업 단위로 검증할 수 있다.

여기서 배점 유지가 산출 점수 불변을 의미하지는 않는다. 압박 등 공통 입력을 바로잡으면 경기 점수·순위·상위 5경기·잠재 티어가 바뀔 수 있다. 표시 비율만 바꾸는 삼각형 작업은 원점수·티어를 바꾸지 않는다.

## 분석 대상과 표시 계약

- 최근 분석: 실제 최근 유효 최대 10경기에서 점수 상위 최대 5경기를 고르는 기존 selector와 retention을 사용한다. 상위 5경기만 고정한 비교와 수정된 점수로 다시 고른 비교를 모두 남긴다.
- 대표 칭호: 최근 요약의 선정 경기 기반이다. 단경기 AI 코칭에 13종 대표 칭호를 새로 도입하지 않는다. 공통 엔진 입력 수정이 단경기 결과·점수·코칭 근거에 주는 영향은 회귀 검증한다.
- 잠재 티어와 삼각형: 솔로·팀 배점이 섞이지 않도록 현재 `tierScope`·`tierMatchCount`와 같은 모집단을 사용한다. 실제 사용 경기 수를 그래프에도 전달한다.
- `SpiderChart` 길이: 팀은 전투/40, 전술/35, 생존/25; 솔로는 전투/50, 전술/15, 생존/35. 숫자는 `32/40`처럼 원점수와 만점을 표시하고 축은 0~100%이다. 달성률은 백분위나 다른 플레이어 대비 상위 비율이 아니다.
- `tierScope`가 없거나 점수 관측이 불완전한 구형 응답은 배점을 추측하거나 0으로 채워 완성 도형을 만들지 않는다. 원점수를 표시하고 완성 도형은 보류하는 호환 처리를 정의한다.

## 단계 1 — 원본 귀속과 관측 계약

- [ ] 구조는 `rescueCount/rescueOpportunityCount`의 사건별 성공·기회 정의를 사용한다. 자가 소생·본인이 끝까지 기절한 사건·중복 Revive·내 연막＋내 소생을 구분한다. 구버전의 두 합계를 단순히 더하거나 100으로 잘라 대체하지 않는다.
- [ ] 협공은 동일 적에 대한 본인과 팀원의 유효 피해가 기존 1초 창에 함께 있는 경우로 한정한다. 이벤트 순서 양쪽·중복 이벤트·팀원끼리 공격·다른 팀 공격·아군 피해·피해 0을 검증한다. 카운트 단위는 기존 타격 횟수이며 교전 수로 몰래 바꾸지 않는다.
- [ ] 거리 지표는 이미 있는 `distanceDamageUpright/maxHitDistUpright`를 우선 재사용한다. 양의 유효 무기 피해·서 있는 적·유효 좌표 조건을 집계 관측 수와 함께 연결한다. 최대 거리 기본 0만으로 관측을 인정하지 않는다.
- [ ] 압박의 피해 0·기절 대상·비무기 이벤트 경계를 정리한다. 공통 점수 입력까지 바뀌는 항목은 계산 버전 변경과 실제 점수 차이 보고를 포함한다. 위치 관측이 없는 자기장 경계 횟수를 실제 0으로 간주하지 않는다.
- [ ] 합계와 분모는 같은 유효 관측 경기 집합을 사용한다. 누락 경기를 전체 경기 수로 나눠 0처럼 희석하지 않는다. 초반 피해 최소 300 조건은 반올림한 경기 평균이 아닌 원합계로 검사한다.

주요 파일: `AnalysisEngine.ts`, `types.ts`, `handlers/*`, `summaryAggregate.ts`. 기존 구조 장부와 관측 수 필드를 재사용하며 역할마다 별도 수집기를 만들지 않는다.

- [ ] 기존 `RoleInfo`를 최소한으로 확장해 판정 상태·사유·역할별 근거량을 연결한다. 표시 설명만 추가하고 평가 파이프라인을 이중 구현하지 않는다.
- [ ] 상태는 역할 확정 / 균형형 / 칭호 미확정 / 근거 수집 중으로 구분한다. 기회 없는 역할 하나 때문에 전체 판정을 보류하지 않는다. 충분한 다른 근거가 있으면 해당 역할을 판단한다.
- [ ] 균형형은 관측 범위가 충분하고 역할 점수의 치우침이 작을 때만 허용한다. 모든 점수가 85 미만이라는 조건만으로 결정하지 않는다.
- [ ] 기본 85 문턱은 우선 유지하고 원정밀도로 판정한다. 비교 가능한 역할 범위·최소 행동 기회·경계 간격의 수치는 개발 자료에서 결정한 뒤 최종 확인 전에 고정한다. 이번 준비안에 근거 없는 수치를 확정하지 않는다.
- [ ] 보조 역할은 기존 필드를 재사용해 설명한다. 대표·보조 역할이 바뀌는 경우와 조합 칭호 문구만 바뀌는 경우를 따로 집계한다. 근거가 충분한 두 역할을 단지 비슷하다는 이유만으로 모두 숨기지 않는다.

## 단계 3 — 기준 분포와 안정성

- [ ] 지표 정의별 관측 조건을 먼저 확정하고 지표 CDF·역할 복합 CDF를 함께 새로 만든다. 기존 후보는 비교 자료로만 보존하며 수정된 지표에 재사용하지 않는다.
- [ ] raw mode, TPP/FPP, 일반/경쟁, 솔로/팀을 구분한다. 혼합 best5를 우세 모드 하나의 분포에 그대로 넣지 않는다. 초기에는 비교가 안 되는 칭호를 미확정으로 두고 실제 관측 근거는 표시하는 보수적 처리를 권장한다.
- [ ] 기존 학습50계정·개발 holdout20계정 가드를 낮추지 않는다. 역할별 기회 관측 수·계정 집중도·칭호 부여율·보류 사유·지표 누락률을 함께 보고한다.
- [ ] 참조 모집단 bootstrap 100회와 개별 계정 일치율 80% 기준을 기존 안정성 비교로 유지한다. 이것은 행동 해석의 정확도나 정답률을 뜻하지 않는다.
- [ ] 경기 창 안정성을 별도로 검증한다. 원래 10경기 중 한 경기씩 제외한 뒤 상위5를 재선정하는 최대10회, 인접 최근 경기 창 비교를 가능한 자료에 수행한다. 의도적인 실제 플레이 변화와 작은 경계 변동을 구분한다.
- [ ] `KangHeeSung_`, `MiaeQ_Q`를 학습에서 제외하고 변경 전후 지표·점수·대표/보조 역할·선정 경기·변경 사유를 공개한다. 특정 계정에 원하는 칭호가 나오도록 문턱을 맞추지 않는다.
- [ ] 기존 확인 자료는 이미 이번 오류 탐색에 사용했다. 수정안의 최종 확인은 새로운 계정과 개발 경기 비중복 자료를 별도 고정한다. 이전 확인을 미열람 독립 검증이라고 재표현하지 않는다.
- [ ] 전체 원본이 보존돼 있지는 않다. 기존 private 보관본·manifest·checksum을 우선 확인하고, 수정된 이벤트 지표를 복원할 원본이 없으면 재확보하거나 누락으로 제외한다. 기존 계산 스냅샷만으로 수정된 지표를 만들어내지 않는다.
- [ ] benchmark는 정의·모집단이 바뀐 지표와 티어 셀만 재검증한다. 칭호는 계정 단위, benchmark는 player-match 단위임을 유지한다. 변경 영향이 없는 반격 기준 후보까지 이유 없이 다시 튜닝하지 않는다.
- [ ] `benchmarkLookup.ts`의 지표별 계산 버전 호환 조건도 함께 고친다. 새 압박·개인 귀속 지표를 구버전 평균과 비교하지 않는다. 새 점수로 티어 셀이 이동한 경우 그 셀의 비교 모집단도 다시 확인한다.

주요 파일: `referenceCalibration.ts`, `roleReference.ts`, `scripts/calibrate_coaching_reference.ts`, `scripts/validate_coaching_expansion.ts` 및 실제 기존 수집 CLI. 실제 파일명·인자는 구현 전 확인한다.

## 단계 5 — 버전·재생·적용 준비

- [ ] `constants.ts`, `cacheIdentity.ts`, `ai-summary/route.ts`, 단경기/스쿼드 캐시 reader에서 변경 필드의 버전 소비 경로를 확인한다. 계산 버전·결과 스키마·모집단 근거·칭호 기준·AI 요약 캐시를 같은 버전으로 취급하지 않는다.
- [ ] 원본 재계산이 필요한 변경은 계산 버전 상향과 canonical 재생 경로를 정의한다. 구형 결과를 새 값으로 표시하거나 기존 캐시 hit으로 우회하지 않는다. 새 판정 상태와 reference 변경도 캐시 identity에 반영한다.

- [ ] 배포 전 로컬 재생 결과로 점수 차이·상위5 교체·칭호 이동·보류 증가를 보고한다. 일부 역할이 불충분하면 해당 역할만 보류하고 다른 검증된 영역을 사용할 수 있도록 한다.
- [ ] 엔진·칭호·후보 분포·삼각형은 리뷰 가능한 작업 단위로 나누되, 검증되지 않은 분포와 호출부를 중간 운영 상태로 배포하지 않는다. 준비안 작성은 PR 변경·병합·운영 재계산·분포 활성화를 수행하지 않는다.
