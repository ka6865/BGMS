# 롤 검색 편의·집계 상태·경기 흐름 구현 계획

목표: 승인된 후속 작업 2·3·4를 기존 롤 서비스에 구현한다. 기존 인게임 인라인 변경은 PR #425로 별도 통합한다.

## 공통 기준

- 기존 Next.js·React·Tailwind 구조와 컴포넌트를 재사용하고 의존성을 추가하지 않는다.
- 공개·관리자 가드와 기존 전적 저장·호출 제한 계약을 유지한다.
- 운영 데이터 쓰기나 migration 없이 구현한다. 수집 상태는 이미 저장된 집계·게시본에서 읽는다.
- 모바일 375×667·390×844·430×932 및 데스크톱에서 기존 fixture로 동작·넘침을 확인한다.

## 2. 최근 검색·즐겨찾기

- `components/lol/LolSearchPanel.tsx`와 검색 보조 컴포넌트, `lib/lol/searchHistory.ts`를 연결한다.
- 성공한 검색만 최근 목록에 저장하고 Riot ID 대소문자 중복을 제거한다. 최근 10개, 즐겨찾기 20개 이내로 제한한다.
- 목록에서 재검색·항목 삭제·최근 목록 비우기, 현재 계정 즐겨찾기 추가·해제를 제공한다. 브라우저 저장소 보관임을 안내한다.
- 손상·차단·용량 부족 저장소에서도 전적 검색은 정상 동작하며 저장 실패를 알린다.
- 단위 테스트와 `tests/lol-public-browser.test.ts`로 성공 기록, 중복, 새로고침, 삭제, 즐겨찾기와 실패 경계를 확인한다.

## 3. 통계·랭킹의 집계 시각과 수집 범위

- `lib/lol/championStats.server.ts`에서 선택한 패치·티어의 `lol_stat_totals.updated_at`을 서버 전용으로 읽는다. 전체 경기 테이블을 훑지 않는다.
- 챔피언 목록·상세에 마지막 집계 시각(KST), 표본 수와 시각 확인 불가를 표시한다. 부가 시각 조회 실패로 기존 통계를 숨기지 않는다.
- 랭킹·장인은 기존 `observedAt`을 사용하고, 장인은 검증된 `coverage`로 진행률을 보여 준다. 누적 수집인 챔피언 통계에는 가상 완료율을 만들지 않는다.
- 24시간 이상 지난 집계는 그 사실을 안내하며 수집기 중단이라고 단정하지 않는다. 없는 시각과 잘못된 날짜를 최신으로 표시하지 않는다.
- 범위: 챔피언 통계 서버·페이지·목록/상세, 랭킹·장인 UI와 관련 단위/브라우저 fixture. 스키마 변경 없음.

## 4. 경기별 골드·CS 그래프

- `lib/lol/matchBuild.ts`의 기존 Match-V5 타임라인 가공 결과에 참가자별 시각·누적 골드·CS(라인+정글) 시계열을 추가한다.
- `components/lol/LolMatchBuild.tsx`의 기존 소환사 선택·조회 상태를 재사용해 빌드 화면에 경기 흐름을 표시한다. 별도 Riot 요청이나 DB 원문 저장을 추가하지 않는다.
- 골드/CS 전환, 같은 팀의 참가자 선택, 시점 선택과 실제 값 표시를 제공한다. 프레임 누락·잘못된 값은 0으로 꾸미지 않고 결측으로 처리하며 그래프 선을 끊는다.
- 캐시 키를 `build:v2:{matchId}`로 올리고 문서·fixture·응답 검사를 함께 갱신한다. 기존 가공 DTO를 제외한 전적 캐시 키는 유지한다.
- `tests/lol-match-build.test.ts`, 그래프 상태 테스트, 기존 롤 개발 브라우저 fixture로 수치·경계·모바일 및 요청 재사용을 확인한다.

## 검증 및 진행 기록

- 기능별 집중 테스트 → `npm run verify:core` → `npm run verify:lol` → 관련 브라우저 fixture → 전체 단위 검사.
- 운영 DB·실제 Riot 호출·실기기는 별도 검증이며 이번 fixture 검증으로 대체했다고 보고하지 않는다.
- 구현은 파일 소유 범위를 나누어 진행한다. 검색 편의 담당은 검색 UI·검색 테스트, 집계 상태 담당은 통계/랭킹 UI·서버·해당 테스트, 통합 담당은 타임라인·그래프·개발 브라우저 테스트를 맡는다.
