# 스쿼드 미측정 지표 처리 및 엄호 집계 보강 계획

작성: 2026-09-07. 부분 코칭·캐시 개선은 PR #187로 배포했다. 아래 집중사격 집계는 develop에서 구현·검증 중이며 후보 기준은 확정된 평가 산식이 아니다.

## 현재 확인한 원인

- AnalysisEngine은 totalCoverAttempts/totalCoverSuccess를 0으로 초기화하지만 이벤트 처리에서 증가시키지 않는다. 따라서 현재 생산 경로의 coverRate=null, coverRateSampleCount=0은 엄호를 하지 않았다는 증거가 아니다.
- steam MiaeQ_Q의 배포 응답에는 함께한 2경기, 고립도 5.6, 백업 5,596ms, 소생 3회, 전멸 기여 9회가 있다. 엄호율·화력 집중 점수·종합 등급만 null이다. 종합 등급을 AI의 필수 조건으로 검사하면서 409가 발생했다.
- 스쿼드 그룹 목록과 선택 그룹 상세는 별도 요청이다. 이전 UI는 탭 재진입 시 둘 다 반복 요청했다.

## 지금 적용할 정책

1. 미측정은 0점으로 대체하지 않는다. 필수 점수가 하나라도 없으면 종합 등급을 보류한다. 부분 점수의 가중치를 다시 분배해서 등급을 만들지 않는다.
2. AI는 서버가 재산출한 관측 지표로만 코칭한다. 등급 null은 AI 결과와 캐시 응답에도 서버에서 강제한다. 미측정 지표 관련 평가 문장은 후처리에서 보류 문구로 치환한다. 문장 필터는 의미 전체를 검증하는 장치가 아니므로 실데이터 품질 감사도 계속 필요하다.
3. 엄호가 null인 현재 화면에는 아직 집계하지 않는 지표임을 설명한다. 근거가 확인되지 않은 ‘권장 기준 30%’ 표시는 제거한다.
4. 전적페이지 수명 안에서 목록·상세 GET의 진행 중 요청을 공유하고 성공 응답을 60초 재사용한다. 최대 16개, 요청 제한 시간 20초. 오류는 저장하지 않는다. 선수 전적 결과가 갱신되거나 로그인 사용자가 바뀌면 새 캐시를 사용한다. 브라우저 영구 저장이나 사용자 간 서버 메모리 공유는 하지 않는다.
5. 최초 목록 1회 + 선택 상세 1회는 유지한다. AI 요청에서는 보안과 최신 근거 검증을 위해 서버 재조회도 유지한다. 반복 탭 전환의 GET 비용은 줄지만 실제 운영 비용 절감률은 별도 측정해야 한다.

## 영구 규칙과 한시 상태의 구분

**‘미측정이면 등급 보류’는 영구 규칙으로 유지한다.** 집계 구현 후에도 로그 누락, 대상 교전 없음, 표본 부족이 남기 때문이다.

현재 ‘엄호 집계 미지원’은 한시 상태다. 후속 구현에서 다음 상태를 명시적으로 저장·전달한다.

| 상태 | 의미 | 화면/등급 |
|---|---|---|
| unsupported | 해당 분석 버전에 집계 구현이 없음 | 집계 준비 중, 등급 보류 |
| missing | 필수 이벤트·팀 식별 등 근거 누락 | 측정 불가, 등급 보류 |
| no_opportunity | 관측 조건을 충족한 교전이 0건 | 대상 교전 없음, 등급 보류 |
| observed | 분모가 양수이고 집계 조건 충족 | 실제 비율·분자/분모 표시; 등급은 표본/비교 기준 검증 후 활성화 |

측정된 0%는 observed에서 분모>0, 분자=0일 때만 가능하다. 이를 팀원을 돕지 않았다는 의도로 해석하지 않는다.

## 실제 구현 후보: 동일 적 집중사격 참여

텔레메트리로 사격 의도, 시야 차단, 적 견제 효과, 안전 확보를 직접 확인할 수 없다. 최초 구현은 ‘엄호 성공률’이라는 포괄적인 이름 대신 **동일 적 집중사격 참여율**로 한정하는 방안을 우선 검토한다.

- 입력: LogPlayerTakeDamage, 기절/사망 및 팀 구성 이벤트. 이름보다 accountId와 팀 ID로 식별하고, 시간순 이벤트를 사용한다.
- 후보 분모: 시작 시 생존 팀원이 2명 이상인 유효 적 교전 구간. 실제 합류가 가능했다는 뜻은 아니다. 대상 적에 대한 연속 피해를 하나의 구간으로 묶는 시간 기준을 표본으로 검증한다.
- 후보 분자: 해당 구간에서 서로 다른 아군 2명 이상이 같은 적에게 유효 피해를 준 구간. 3/5/8초 창을 비교해 과도한 인정과 누락을 확인하고 기준을 확정한다. 임의의 5초 기준을 곧바로 정답으로 배포하지 않는다.
- 제외/분리: 자해·팀킬, 환경 피해, 양수 아닌 피해, 기절 후 마무리만 있는 참여, 불명확한 공격자·팀·시간. 봇 포함 여부와 매치 유형은 비교 모집단과 동일하게 맞춘다.
- 중복 방지: match+platform별 원본과 원본 이벤트 식별 순서를 보존한다. 같은 매치를 여러 플레이어 분석에서 읽어도 스쿼드 집계에는 한 번만 반영한다. 단지 시간/피해량이 같다는 이유로 정상 다중 명중을 제거하지 않는다.
- 개인과 팀 구분: 개인 참여율을 팀 엄호율로 합산하지 않는다. 스쿼드 교전 구간을 기준으로 집계하고 필요하면 개인 기여를 별도 표시한다.
- 여러 경기 합산: 경기별 비율의 단순 평균 대신 전체 분자 합 / 분모 합. 미측정 경기는 0회로 섞지 않으며, 제외 경기와 관측 경기 수를 표시한다.

현재 squadAnalysis의 0.30 고정 화력 집중 점수 기준은 이 구현의 검증된 비교 기준이 아니다. 실제 집계와 함께 같은 모드·매치 유형·분석 버전의 비교 표본을 준비하고 점수 보정을 검증해야 한다. **집계 코드만 완성됐다고 종합 등급을 자동으로 해제하지 않는다.**

## 구현 순서와 비용 통제

1. 대표 실제 경기에서 원본 이벤트와 원인 장면을 대조하여 교전 구간/명중 판정의 정답 표본을 만든다. 자동 테스트에는 가명화한 최소 이벤트만 저장한다.
2. 독립 순수 집계 함수와 계약을 구현한다. numerator, denominator, status, measurementVersion, 제외 사유를 저장하고 기존 소비자의 0~100과 0~1 단위를 명시적으로 변환한다.
3. AnalysisEngine에 연결한다. 같은 매치 텔레메트리를 다시 다운로드하지 않고 기존 분석 실행의 이벤트를 활용한다. 순차 처리와 제한된 시간 창으로 이벤트 전체의 이중 순회를 피한다.
4. RESULT_VERSION 또는 지표 버전으로 구버전 결과를 구분한다. 보관된 원본이 있는 최근 요청 경기부터 제한된 동시성으로 재분석하고, 원본 없는 과거 기록은 보류한다. 전체 기록 일괄 재분석은 하지 않는다.
5. 같은 버전·모집단의 benchmark를 생성하고 충분한 표본/안정성을 검증한다. 신뢰 가능한 기준 전에는 관측 비율과 건수만 공개하고 화력 집중 점수·종합 등급은 보류한다.
6. 새 지표를 AI 입력으로 사용하기 시작할 때 버전/관측 상태를 canonical AI 캐시 해시에 포함한다. 현재 실험값은 AI에 전달하지 않는다. AI 캐시는 사용자 요청 시 생성하며 기존 결과를 일괄 재생성하지 않는다.
7. 제한된 표본에서 시작해 미측정률, 중복률, 처리 시간, 원본 읽기량, 오류율을 확인한 후 확대한다.

## 검증 및 해제 조건

- 미지원/누락/교전 없음/측정된 0%/100%를 구분한다.
- 시간 경계 직전·직후, 이벤트 순서 변경, 적 변경, 동일 팀 다중 명중, 기절 후 마무리, 부활 후 재교전, 팀킬·환경 피해를 검증한다.
- 선수·플랫폼·매치·팀 identity 혼합과 같은 매치의 중복 반영을 차단한다.
- 실데이터 원인 장면에서 분자/분모를 설명할 수 있어야 한다. 기존 개인 지표와 스쿼드 복구 지표를 바꾸지 않아야 한다.
- 관측/비교 표본의 품질 검증, 점수 보정, 나머지 필수 점수 관측을 모두 충족할 때만 해당 응답의 종합 등급을 활성화한다.
- 이번 UI 캐시는 재방문, 진행 중 재방문, 만료, 전적 새로고침, 사용자/팀 전환, 실패 후 재시도를 테스트한다. AI는 부분 근거 200+등급 null, 근거 전무 409, 공급자 장애 503/504, 취소 및 캐시 반환을 검증한다.


## develop 관측 집계 구현 및 검증 기록

- `SquadFocusFireCollector`를 기존 AnalysisEngine 이벤트 순회에 연결했다. 추가 텔레메트리 요청·DB 조회는 없고, 다음 정상 분석 결과의 `fullResult.squadFocusFire`에 저장된다. squad/squad-fpp만 지원한다.
- 버전 1은 **동일 적 총기 집중사격 관측**이다. 각 적의 첫 유효 명중에서 고정 5초 구간을 시작한다. 이후 명중으로 창을 연장하지 않는다. 구간 내 서로 다른 아군 2명 이상 명중 시 분자 1건, 해당 구간은 분모 1건이다. 두 명 이상이 생존·비기절인 팀 상태에서 시작하며, 거리·시야·합류 가능성을 증명하지 않는다.
- 양수 총기 피해만 포함한다. 아군·자해·봇·투척물·환경·기절 후 마무리는 제외한다. 기절 이벤트 직전 체력 0으로 기록된 최종 명중은 포함한다. 부활 후에는 새 구간을 연다. 타임스탬프 역전, 필수 전투/생명주기 식별 누락, 시작·종료 누락, 확인하지 못한 리콜 생명주기는 부분 합계를 공개하지 않고 missing 처리한다.
- `numerator/denominator/rate/status/version/windowMs/calibration/issues`를 함께 보관한다. rate 단위는 0~100%, calibration은 항상 pending이다. 대상 없음은 0/0 + rate=null, 관측된 0%는 0/양수다.
- 스쿼드 상세 API는 선택된 canonical 경기만 합산하여 `focusFireObservation`을 반환한다. 같은 경기 중복은 한 번만 반영하고, 같은 ID의 관측값 충돌은 missing 처리한다. 전체 분자/분모로 합산하며 하나라도 구버전·누락·비호환이면 전체 값은 missing으로 보류한다. 모든 경기에 필드가 없으면 unsupported다.
- 새 관측값을 기존 엄호율, 30% 고정 비교 기준, AI 입력 또는 화면의 점수에 연결하지 않았다. 실험 필드가 있는 경기가 포함되면 기존 엄호값이 섞여 있어도 엄호율·화력 집중 점수·종합 등급을 보류한다. 기존 결과 버전 전체를 올리거나 과거 원본을 일괄 재분석하지 않는다. 기존 캐시는 지표 필드가 없는 상태로 남고 정상 재분석 시에만 채워진다.

### 운영 확인과 추가 AI 품질 보강

PR #187 배포 커밋 `ba797e973d1c974634656d386be3f211ad7ed13b`에서 MiaeQ_Q 스쿼드 AI 요청 HTTP 200과 화면의 ‘보류’를 확인했다. 스쿼드 탭 재방문의 캐시 유효 구간에는 추가 squad-analyze 런타임 로그가 없었다. 이는 해당 세션 확인이며 전체 트래픽 비용 절감률은 아니다.

운영 결과에서 팀 고립도를 특정 팀원의 책임으로 단정하고 킬·어시스트 비중으로 킬 독점 의도를 추측하는 문장이 발견됐다. develop에서는 개인 위치·백업·복구 기록이 없음을 프롬프트에 명시하고, 개인 피드백의 해당 표현을 보류한다. 새 생성과 캐시 반환 모두 적용하며 스쿼드 AI 캐시 버전만 `squad-partial-v2`로 구분한다. 단어 기반 후처리는 모든 의미 오류를 검증하지 못하므로 지속적인 실제 응답 검토가 필요하다.

## 텔레메트리 계산 선행 감사

[수집·필터·계산 감사](2026-09-07-telemetry-calculation-audit.md)에서 위치 identity 오류와 분석 캐시 이중 샘플링을 재현·수정했다. 같은 두 경기의 팀원 4명 모두 원본/투영/캐시 주요 값이 일치하고 집중사격 5초 6/40도 유지됐다. 다음 단계는 계산 버전별 결과·benchmark·공개 map 캐시 이행을 먼저 완성하고 대표 경기 정답 표본을 넓히는 것이다. 기존 5.6 고립도는 구버전 위치 오류로 재현됐으므로 새 집중사격 관측을 검증할 때 기존 고립 점수를 정답으로 사용하지 않는다. 관측 점수 공개와 종합 등급 해제는 계속 보류한다.
