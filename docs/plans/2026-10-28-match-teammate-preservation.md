# 전적 목록 팀원 이름 보존

## 목표와 범위

`KangHeeSung_` 전적에서 확인한 응답 순서에 따른 팀원 누락을 수정한다. 기본 전적과 장기 성과 요약을 합칠 때 현재 목록 API가 비공개 필터를 적용한 `teammate_names`를 사용한다. 분석 결과 우선순위와 성과 값은 유지한다. DB 저장·수집·캐시 키는 바꾸지 않는다.

이전 화면의 팀원 이름을 무조건 복원하면 이후 비공개 처리된 이름이 다시 보일 수 있다. 따라서 현재 목록 응답을 기준으로 이름을 넣고, 해당 응답에 이름이 없으면 이전 이름도 사용하지 않는다.

## 구현 계획

- [x] 최신 `origin/main`의 하위 워크트리를 만들고 기존 테스트를 확인한다.
- [x] `tests/stats-page-controller.test.ts`에 두 응답 순서, 상세 분석 우선순위, 목록 재조회 시 이름 제외를 검증하는 회귀 테스트를 추가하고 실패를 확인한다.
- [x] `hooks/useStatsPageController.ts`의 장기 성과 요약 구성에 현재 목록의 팀원 이름을 반영한다.
- [x] 기존 브라우저 fixture 하네스에 두 응답 순서를 추가하고 `375x667`, `390x844`, `430x932`, `1440x900`에서 이름 표시와 넘침을 검사한다.
- [x] 관련 테스트, `verify:core`, `verify:analysis`와 전체 단위 테스트를 실행하고 변경 전체를 별도 자체 리뷰한다.

## 검토 기준

- 장기 성과의 점수와 분석 지표가 유지된다.
- 두 API의 완료 순서에 관계없이 팀원이 표시된다.
- 현재 목록에서 제외된 이름을 이전 상태나 성과 요약에서 복원하지 않는다.
- 상세 분석 요약의 우선순위가 유지된다.
- 실제 계정 응답은 로컬 재현에만 사용하고 저장소에는 일반화한 fixture만 넣는다.

## 검증 기록

- 변경 전 관련 테스트: 3개 파일, 63개 통과.
- 하위 워크트리에는 로컬 보조 지침과 `docs-private/`가 없으므로 부모에서 읽은 지침과 저장소 구현·테스트를 기준으로 작업한다.
- 회귀 테스트는 수정 전 2개 실패를 확인했고 수정 후 controller·팀원·장기 성과·브라우저 하네스 테스트 83개가 통과했다.
- `verify:analysis`: 697개 통과, 기존 조건부 테스트 6개 제외.
- `verify:core`: ESLint 오류 0개·기존 경고 47개, TypeScript 통과.
- 전체 Vitest: 412개 파일·5,484개 테스트 통과, 조건부 204개 제외. Jest는 별도 실행해 통과했다.
- 브라우저: 위 네 크기에서 두 응답 순서씩 8개 시나리오 통과. 팀원 이름·가로 넘침·상세 API 추가 요청 없음·페이지 오류 없음을 확인하고 경기 행 스크린샷을 검사했다. 다른 smoke 시나리오 49개는 이번 실행 대상이 아니다.
- 실제 `KangHeeSung_` 최근 20경기 API 응답을 수정한 controller에 재생해 두 순서 모두 20경기의 팀원 이름 유지(2개 테스트)를 확인했다. 원격 데이터 재수집·수정은 하지 않았고 실제 응답 파일과 임시 테스트는 커밋하지 않는다.
- 별도 자체 리뷰: 현재 목록 이름 우선, 이름 부재 시 이전 값 제거, 상세 분석 우선순위, 성과 값 유지, 서버·DB 변경 없음과 fixture 외부 요청 차단을 확인했다. 독립 리뷰어 검증은 수행하지 않았다.
- 실제 모바일 기기·네이티브 앱과 운영 배포 검증은 실행하지 않았다.
