# 첫 반격 사격 근거 분리 구현·평가 계획

목표: 기존 점수와 첫 반격 명중 간격을 보존하면서, 피격 전 사격이 이어진 사례를 코칭의 반응 평가에서 제외한다. 사용자가 두 계정의 원본 확인 후 수정·평가를 요청한 범위다.

1. CombatHandler의 기존 교전 시작/첫 반격 지점에서 독립 관측기를 호출한다. 최근 무기 발사 기록·attackId 연결로 연사 중/최근 사격 불명확/검증 가능한 교전을 분류한다. 기존 교전 세션·점수는 바꾸지 않는다.
2. 새 관측 버전·적격 교전 수·이미 사격 중 제외 수·근거 부족 수·첫 반격 수/지연 합을 결과에 저장한다. 옛 결과의 평균으로는 새 관측을 복원하지 않는다.
3. 코칭·요약은 적격 관측만 읽는다. 제외 교전은 실패 분모에도 넣지 않는다. raw 명중 간격은 별도 reader와 기존 DB 열에 유지한다.
4. 비교 표본은 새 nullable 열/집계 열로 분리한다. 과거 평균으로 fallback하지 않는다. 기존 표본을 임의 보정하거나 운영 migration을 자동 적용하지 않는다.
5. 회귀 테스트: 3ms·201ms 연사 제외, 실제 피격 후 발사 적격, 로그 누락, 최근 단발 불명확, 늦은 반격, 오래된 캐시, 점수 보존, writer/RPC/view 계약.
6. KangHeeSung_·MiaeQ_Q 원본으로 로컬 재계산하고 개선 전후 명중 간격·적격 값·점수를 비교한다. verify:core/analysis/unit/migrations와 실제 Gemini 코칭을 검증한다.

연사 후보 기준은 피격 전 300ms 안의 같은 무기 발사 2회 이상, 마지막 발사 200ms 이내, 두 발 간격 200ms 이하로 보수적으로 둔다. 이는 인간 반사신경의 하한이 아니라 최근 사격 문맥을 확인하는 창이다. 최근 한 발만 있거나 발사 연결이 없으면 평가를 보류한다. 발사 표본이 없는 결과는 반격 실패로 보지 않는다. 이 임계값의 일반 모집단 보정은 이번 두 계정 검증으로 입증하지 않는다.
