# LoL 경기 상세·최근 통계 보강

2026-10-23 기준. 저장된 Match-V5 원문을 재사용해 상세 참가자 지표, 팀 목표 요약, 최근 최대 5경기의 큐별 표본 통계를 노출한다. Riot Match-V5 추가 호출과 DB 스키마 변경은 없다.

## 지표 계산

- 킬관여율: `(본인 킬 + 어시스트) / 같은 팀 참가자 킬 합계 × 100`. 팀원 킬 합계 또는 본인 킬/어시스트가 불완전하거나 팀 킬 합이 0이면 미제공한다.
  본인의 유효한 팀 ID가 없을 때도 미제공하며, 결측 팀 ID끼리 같은 팀으로 묶지 않는다.
- CS/분: `(일반 CS + 정글 CS) / (경기 초 / 60)`. 골드/분: `골드 / (경기 초 / 60)`. 경기 길이가 300초 이상일 때만 분당 수치를 계산한다. 경기 길이·원본 CS·골드는 보존하며, 300초 미만·누락·0초는 분당 수치를 미제공한다.
- 합산 KDA: 전체·큐별·챔피언별 모두 유효 경기 중 K/D/A가 완전한 경기의
  `(Σ킬 + Σ어시스트) / Σ데스`로 계산한다. 데스 0 경기의 킬·어시스트도 포함한다.
  합산 대상이 있고 Σ데스가 0이면 `perfect: true`, 비율은 `null`이다.
  합산 대상이 없으면 `perfect: false`, 비율은 `null`이다.
- 평균 K/D/A: 합산 KDA와 같은 완전 표본 n으로 `Σ킬/n`, `Σ데스/n`,
  `Σ어시스트/n`을 계산하며 실제 0은 포함한다. K/D/A 중 하나라도 결측이면
  그 경기 전체를 KDA와 세 평균에서만 제외하고, 승률 표본에는 그대로 포함한다.
- 경기별 비율 평균을 합산 방식으로 바꿔 퍼펙트를 포함한 표본을 일치시키고,
  적은 데스 경기의 비율이 평균을 크게 흔드는 문제를 줄인다.
- 평균 관여율: 유효 경기의 제공된 킬관여율을 산술평균한다. 팀 ID·팀 킬 등
  결측으로 계산할 수 없는 경기는 관여율 평균의 분모에서 제외한다.
- KDA 비율 표기: 개별 경기는 `(킬 + 어시스트) / 데스`를 소수 둘째 자리까지 `X.XX:1`로 표시하고 데스 0은 `Perfect`로 표시한다. 요약·챔피언 합산 KDA도 `X.XX:1` 또는 `Perfect`로 표시한다.
- 승률: 유효 표본 승리 수 / 승패가 있는 유효 경기 수. 이 승률 표본 수와 KDA 분모는 서로 다를 수 있으며, 챔피언별 경기 수는 승률 표본 수를 뜻한다.
- 합산 KDA 비율은 소수 둘째 자리, 평균 K/D/A는 소수 첫째 자리,
  승률·관여율은 정수 퍼센트로 표시한다.
- 팀 총킬·총골드는 참가자 원자료 합계이며, 구성 값이 하나라도 빠지면 부분합 대신 미제공한다. 팀 tower, dragon, baron, riftHerald, horde, inhibitor 값은 `info.teams[].objectives`의 처치 수와 최초 획득 여부를 사용한다.

## 결측·표본 규칙

- 숫자 지표와 경기 길이에서 누락, 비유한 값, 음수는 `null`로 바꾸고 실제 0은 보존한다. 비율의 필수 필드가 하나라도 없거나 분모가 0이면 `null`이다. 화면은 `미제공`으로 표시하되 KDA의 `perfect` 상태는 `Perfect`로 표시한다.
- `gameEndedInEarlySurrender` 또는 `teamEarlySurrendered`가 참인 경기와 300초 미만 경기는 최근 통계에서 제외한다. 300초는 제품 휴리스틱이며 개별 경기의 세부 값은 표시한다.
- 최근 표본은 Riot의 기존 최신 경기 ID 요청 최대 5건 안에서 계산한다. 큐 필터 `전체`, `솔로(420)`, `자유(440)`, `ARAM(450 또는 ARAM 모드)`를 화면과 같은 규칙으로 서버 집계하고, 표본·유효·제외 수를 함께 보여준다.
- 미등록 큐는 전체 큐 표본에만 포함하고 경기 카드에는 `큐 <id>`를 표시한다.
- 포지션은 Match-V5 원문 `participant.teamPosition`을 기록한다. `TOP`, `JUNGLE`, `MIDDLE`, `BOTTOM`, `UTILITY` 외 값과 빈 값은 `미분류`로 집계하며, 큐별 유효 경기 수에 포함한다.
- 함께 플레이한 소환사는 같은 유효 경기의 본인 `teamId` 참가자만 PUUID로 묶는다.
  2경기 이상 함께한 Riot ID만 응답하며 상대 팀은 제외한다. 승률은 함께한 경기의
  승패 중 확인 가능한 값으로 계산하고, 경기 수 내림차순·승률 내림차순·이름
  오름차순으로 최대 5명 표시한다. 응답에는 PUUID를 포함하지 않는다.
  본인 팀 ID가 없거나 유효한 양의 정수가 아니면 동료를 추정하지 않으며,
  같은 경기에서 중복된 PUUID는 한 번만 센다. 확인 가능한 승패가 전혀 없으면
  승률은 `null`이며 화면은 `미제공`으로 표시하고 정렬에서는 실제 0% 뒤에 둔다.
- 검색 응답은 검색 중 이미 읽은 경기 원문에서 경기 상세 참가자 DTO를 함께 구성한다. 상세 UI는 추가 경기 API 요청을 보내지 않는다.
- 참가자 상세는 모바일에서 기본 지표와 피해·와드·CS·아이템을 두 줄로 배치해
  마지막 아이템 슬롯까지 컨테이너 안에 보이게 한다. 데스크톱은 피해 막대에
  가로 공간을 더 배정하고 카드 요약과 팀별 소환사 목록을 한 행에 배치한다.
- `visionWardsBoughtInGame`을 제어와드 설치로 대체하지 않는다. objective damage와 turret damage도 별도로 취급한다.

## 검색 결과 2단 레이아웃

- 프로필 헤더는 전체 폭이다. 1024px 이상에서는 왼쪽 320px과 나머지 오른쪽
  열을 16px 간격으로 나누며 전체 결과 폭은 최대 1280px이다.
- 왼쪽 열에는 솔로·자유 랭크 카드, 최근 챔피언, 포지션 분포, 함께 플레이한
  소환사를 쌓는다. 랭크 큐가 응답에 없으면 해당 카드에 `Unranked`를 표시한다.
  티어는 텍스트 배지를 사용하고 챔피언은 아이콘과 경기 수 내림차순 통계를 표시한다.
- 오른쪽에는 최근 유효 경기의 전적·승률 SVG 게이지·평균 K/D/A·합산 KDA 비율·
  평균 관여율과 큐 필터를 둔다. 항목마다 붙던 표본 수 표시는 제거하고,
  집계 범위를 요약 헤더와 왼쪽 통계 제목 부근에 한 번씩 표시한다.
  왼쪽은 `최근 N경기 · 큐`, 요약 헤더는 유효·제외 경기 수도 함께 표시한다.
  큐 필터는 좌우 통계가 같은 `summaries[filter]`를 사용하도록 함께 갱신한다.
- 1024px 미만의 DOM 순서는 프로필 → 랭크 2장 → 요약·경기 목록 →
  챔피언·포지션·함께 플레이이다. 640px 이상 태블릿의 랭크는 2열이다.
- 카드 배경·테두리와 12~16px 간격을 통일하고 숫자는 `tabular-nums`를 사용한다.

## 경기 카드 배치·자체 리뷰

- 카드 내용 폭 900px 이상에서는 챔피언·레벨과 주문/룬 2×2, 경기 정보,
  KDA와 세부 지표, 아이템 7칸, 팀별 5명 2열, 펼치기 버튼을 한 행에 정렬한다.
  560~899px에서는 이름 목록을 숨기고 지표를 둘째 줄로 배치한다. 화면 전체
  너비 대신 이름 있는 컨테이너 쿼리로 오른쪽 열의 실제 너비를 따른다.
- 상세 참가자 행 역시 전적 열 860px부터 넓은 표를 사용하고 그보다 좁으면
  기존 모바일 두 줄 배치를 유지해 1024px의 2단 레이아웃에서도 넘치지 않는다.
- 모바일에서는 아이콘과 경기 정보, KDA·관여·CS·골드 지표, 아이템을 순서대로
  배치한다. 지표는 개별 `whitespace-nowrap`로 단위 중간 줄바꿈을 막고,
  공간이 부족하면 지표 전체를 다음 줄로 보낸다. 10명 목록은 숨기고 펼치기
  버튼은 오른쪽 전체 높이를 사용한다.
- 구 DTO의 주문·룬·아이템이 없어도 빈 4칸·7칸을 유지한다. 평균 KDA 필드가
  없을 때 발생하던 렌더링 오류와, 없는 포지션·동료 정보를 0 또는 빈 목록으로
  단정하던 표시를 `미제공`으로 고쳤다. 미분류 포지션 수도 별도로 표시한다.
- 서버 리뷰에서 팀 ID 결측에 따른 동료 오집계, 동일 경기 중복 참가자 집계,
  승패가 없는 동료의 0% 표시와 킬관여율의 팀 ID 결측 처리를 수정했다.
  KDA 비유한 값·음수도 미제공한다.
- 큐 선택 규칙과 서버 summaries 규칙이 일치함을 확인했다. 카드·상세는 검색
  응답의 참가자 DTO만 사용하며, 원문·PUUID를 응답이나 DOM으로 전달하지 않는다.
- 브라우저 fixture의 결측 시나리오가 원본 fixture를 수정하던 문제도 복제하여
  격리했다. 큐별 fixture 표본을 실제 선택된 카드 수와 맞췄다.

## 캐시·저장 영향

- 상세 DTO 캐시 키의 전용 버전을 `v2`에서 `v3`으로 올려 이전 payload 재사용을 막는다.
- 합산 KDA 계약에 맞춰 검색 DTO 캐시 prefix와 프로세스 내 검색 cache/inflight
  key를 `search:v4`에서 `search:v5`로 올린다. Data Dragon 버전과 상세 DTO `v3`의 기존 의미는 유지한다.
- 새 요약 필드는 `wins`, `losses`, `averageKills`, `averageDeaths`, `averageAssists`,
  `killsSampleSize`, `deathsSampleSize`, `assistsSampleSize`,
  `averageKillParticipationPct`, `killParticipationSampleSize`이다. 챔피언 요약에
  `championImageId`와 `perfect`를 제공한다. 전체·챔피언별 `kdaSampleSize`는
  DTO에서 제거한다. K/D/A 표본 수 3개는 같은 완전 표본 n이다.
  표본이 없는 평균은 `null`·표본 수는 0이며,
  구 DTO에 필드가 없어도 화면은 오류 없이 미제공 상태로 표시한다.
- 값은 기존 `lol_matches.request_json`에서 계산한다. 추가 Riot 호출 0회, DB 스키마/migration 변경 없음.

## 미확인 사항

- 브라우저 fixture 검증은 뷰포트 수준이며 실제 모바일 기기나 Riot API·운영 DB를 사용하지 않는다.
- Riot 원문에서 조기 항복 필드가 모드별로 제공되지 않을 수 있다. 필드가 없으면 해당 플래그만으로 제외하지 않고 300초 기준을 적용한다.
- `.agents/rules/project_rules.md`는 이 작업 폴더에 없다. 기존 3000번 개발 서버는
  종료·재시작하지 않았으며 커밋·staging과 PUBG 코드 변경을 수행하지 않았다.
