# 코칭 기준 추가 표본·반복 검증

사용자 요청: 검증 표본을 추가 확보하고 충분히 신뢰할 수 있는 결과까지 반복한다. PR #379의 기존 표본과 운영 기본값을 보존하며 공식 upstream 읽기를 추가한다. 로컬 파일 외 DB/R2 쓰기·배포는 하지 않는다.

## 먼저 고정하는 판정 조건

- 기존 지표별 benchmark n30, 역할별 학습50·검증20의 최소 가드를 낮추지 않는다. 지정 두 계정은 계속 학습에서 제외한다.
- 우선 대상은 실제 두 계정의 Steam 듀오 경쟁, 가장 큰 스쿼드 일반, 이미 benchmark 후보가 있던 스쿼드 경쟁이다. 다른 조건을 섞어서 수를 채우지 않는다. 희소 조건은 여전히 보류할 수 있다.
- 반격 benchmark는 독립 검증 n30도 확보하고, 계정 단위 bootstrap95% 구간의 평균 추정 반폭이0.15초 이하인지 확인한다. 이는 작업자가 정한 정밀도 목표이며 실력/반사신경 정확도 보증이 아니다.
- 역할은 유효한 후보에 대해 계정 bootstrap 칭호 일치율80% 이상을 목표로 한다. 불확실한 역할/계정은 판정을 보류한다. 모든 계정에 칭호를 강제로 부여하거나 특정 칭호 비율을 목표로 삼지 않는다.
- 이미 관찰한400계정은 개발·분포 산출 자료다. 추가 계정 중 고정 hash로 분리한 마지막 확인 표본은 후보를 만들거나 문턱을 조정하는 데 사용하지 않는다. 반복 중에는 개발 표본의 정밀도·coverage를 확인한다.
- 추가 배치에서 기준이 흔들리면 표본·경기 선택·관측/결측 정의를 조사한다. 새 계정과 표본 확대 결과를 전부 기록하고 실패 배치를 버리거나 seed를 바꿔 통과시키지 않는다.

## 실행

1. 공식 match→relationship-bound telemetry GET, size/identity/host/definition 검증, checksum이 있는 local shared source 생성. 정상/404/403/429/5xx를 구분하며 불가 자료를 성공으로 처리하지 않는다.
2. 기존 누락을 보완한 뒤 실제 부족한 조건의 새 계정·최근 유효10경기를 확보한다. private registry·계정 분리·완전 창·top5·raw/qualified 구분을 유지한다.
3. 동일 aggregate/classifier로 배치별 coverage·진단 분포·bootstrap·독립 비교를 반복한다. 마지막 확인을 통과하지 못한 기준은 활성화하지 않는다.
4. 회귀/공통/분석 검증과 독립 코드 검토 후 PR #379의 결과를 갱신한다. 운영 반영은 별도다.

공식 근거: https://documentation.pubg.com/en/rate-limits.html , https://documentation.pubg.com/en/telemetry.html , https://documentation.pubg.com/en/players-endpoint.html . 매치/텔레메트리는 앱 키 rate limit에 포함되지 않으며 player 조회는10계정씩·응답 rate header를 준수한다.

## 최종 확인 전 보수적 보완 (13:16 KST)

정밀도 계산의 한 계정 반복 문제를 막기 위해 n30 외 독립 계정20도 요구한다. 역할 안정성은 전체 평균이 아니라 해당 역할을 관측한 최종 계정들의 bootstrap 일치율로 판단한다. 80% 미만인 개별 계정의 판정은 안정으로 제시하지 않는다.

1차 새 계정 manifest는452계정(듀오 경쟁172·스쿼드 경쟁140·스쿼드 일반140), 최종 확인95개를 고정했다. 부족했던 듀오 경쟁 목표400을 채우려고 검증된 공식 metadata의 다른 경기에서 한 계정씩228개를 추가했다. 2차 manifest는680계정·최종 확인141개이며 seed와 분리 hash를 바꾸지 않았다. 같은 초기 seed 경기에서는 서로 다른 roster에서 최대4계정을 골랐으므로 완전한 경기 독립 표본이라고 단정하지 않는다.

최종 분석을 보기 전에 강화한 조건: 개발 대상의 요청 경기 ID와 겹치는 최종 개인-경기는 benchmark 확인에서 제외한다. 역할은 best5 중 한 경기라도 개발 요청 경기와 겹치면 해당 최종 프로필을 제외한다. 중복 전후 수를 모두 보고하고, 부족하면 더 수집한다. 최종 확인 계정은 여전히 후보 fitting·반복 기준 조정에 넣지 않는다.

## 관측 가능 표본 확보를 위한 3차 배정 (최종 결과 열람 전)

유효 반격이 관측되는 비율과 모드 혼합 제외 때문에 같은 수의 원시 계정이 같은 수의 역할 표본을 만들지 않는다. 분리 hash/모든 문턱을 유지하고, 이미 정한 검증 목적에 맞춰 듀오 경쟁 development-holdout60·스쿼드 경쟁 final60·스쿼드 일반 final60을 추가 고정했다. 경기별 최대 한 계정이며 최종 확인의 결과 값은 아직 분석하지 않았다. 이는 검증 집단의 층별 추가 확보이며 train CDF에 final 자료를 넣는 방식이 아니다.

3차 새 계정 manifest:860계정, final261계정, SHA256 `db51164dd0539edd1b8ce2b90eaabcbc295bdd917716440837d4e1b07d3974c9`. 추가 표집은 결과의 크기/칭호가 아닌 모드·유형·hash 집단으로만 정한다. 최초400계정과 이후 표집 경로가 달라 전체 PUBG 무작위 모집단으로 일반화하지 않는다.
