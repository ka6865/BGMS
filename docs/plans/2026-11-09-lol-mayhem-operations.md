# 증바람 현황과 운영 방식

작성일: 2026-11-09. 기준: `origin/main`(31afd888), 운영 DB 읽기 조회, GitHub Actions 최근 실행 기록.

## 1. 현재 구현

공개 화면은 `/lol/kr/aram-mayhem` 하나다. 관리자 화면은 `/admin/lol/mayhem-datasets`(증바람 자료)와 `/admin/lol/augments`(공식 증강)다.

| 콘텐츠 | 출처 | 수집 | 공개 방식 | 현재 공개본 |
| --- | --- | --- | --- | --- |
| 공식 증강 목록·설명·아이콘 | Riot 클라이언트 자료 | `lol-augments-sync` 매일 | 관리자 공개 | 16.21(10/23). 16.22는 수집만 됨 |
| 챔피언별 증강 통계 | aramgg Data API | `lol-mayhem-champion-dataset` 6시간 | 관리자 승인 | 16.21(11/4) |
| 챔피언 티어 | aramgg | `lol-mayhem-reference-dataset` 6시간 | 관리자 승인 | 16.21(11/4) |
| 아이템·신발 평가 | aramgg | 위와 같음 | 관리자 승인 | 16.22, 173명(11/5) |
| 과거 패치 증강 순위 | aramgg | 위와 같음 | 관리자 승인 | 16.10~16.21(11/4) |
| 추천 조합·전체 선택률 | arammayhem.com `/data/` | `lol-mayhem-dataset` 6시간 | 증강 연결 + 관리자 승인 | 16.21(11/5) |
| 증강 관측 이력 | 위 자료 누적 | 별도 수집 없음 | 공개 자료에서 계산 | - |

공개 노출은 `LOL_MAYHEM_CHAMPION_DATASET_ENABLED`, `LOL_MAYHEM_ITEMS_ENABLED`, `referencePublicEnabled()`로 켠다. 원본은 R2에, 목록·공개 상태는 Supabase에 둔다. 모든 수집은 비공개 후보(`pending`)로만 저장되고, 사용자 화면에는 승인된 자료만 나온다.

## 2. 확인된 운영 문제

1. **추천 조합 수집 실패**: 11/7부터 4회 연속 `reviewed_dataset_empty`로 실패했다. 증강 연결 정보는 패치마다 따로 승인해야 하는데, 승인된 연결은 16.21용 206개뿐이다. 운영 DB에서 대조해 보니 206개 모두 16.22에서도 같은 ID·같은 한글/영문 이름의 활성 증강이다. 다시 승인할 필요 없이 그대로 이어받을 수 있다.
2. **승인 병목**: 11/5 이후 승인된 자료가 없다. 패치는 16.22로 바뀌었지만 공개 화면은 아이템만 16.22이고 나머지는 16.21이다. 자동수집이 정상이어도 사람이 누르기 전까지는 반영되지 않는다.
3. **대기 후보 누적**: 아이템 평가 대기 후보가 4일 만에 1,628건, 132MB 쌓였다. 고유 해시가 1,515개라 같은 내용이어도 원본이 조금씩 달라 중복으로 걸러지지 않는다. 과거 순위도 같은 정규화 해시가 패치마다 3건씩 쌓였다. 저장 한도 2GB(`reference_storage_budget`)에 걸리면 수집이 멈춘다. 지금 속도면 약 두 달 남았다.
4. **패치 전환 연쇄**: 공개 화면은 공식 증강 공개 패치(`lol_augment_publication`, 현재 16.21)를 기준으로 조합·티어를 조회한다. 공식 증강을 16.22로 공개하면 16.22 조합·티어 승인본이 없는 동안 해당 섹션이 비게 된다.
5. **실패 원인 기록 부족**: 11/5 `reference_snapshot_invalid`는 실패한 챔피언과 검증 사유가 로그에 남지 않아 원인을 확정하지 못했다.

참고: 챔피언 통계가 11/4에 멈춘 것은 장애가 아니다. aramgg 원본이 아직 16.21.5라 `unchanged`로 처리되고 있다. 증바람 외 항목으로는 `champion-stats`가 Riot 키 권한 오류로 11회 연속 실패 중이다.

## 3. 운영 원칙

**검증을 통과한 자료는 자동으로 공개하고, 예외만 사람에게 넘긴다.**

지금의 승인 버튼은 사람이 실제로 대조하는 절차가 아니라 형식적인 클릭이 됐고, 그마저 실행되지 않아 공개 자료가 멈춰 있다. 기계로 판단할 수 있는 조건은 코드로 확인하고, 사람은 조건을 벗어난 경우만 본다.

### 자동 공개 조건(콘텐츠 공통)

- 스키마와 출처 검증 통과(현재 검증 그대로 사용)
- 패치가 현재 공개본과 같거나 더 새로움
- 챔피언 수·행 수가 직전 공개본의 90% 이상
- 미연결 증강이 없거나, 미연결 증강을 제외해도 위 수량 조건을 충족함

조건을 벗어나면 대기 후보로 두고 관리자 화면에 사유를 한 줄로 보여준다. 공개 이력과 되돌리기는 기존 publication 테이블의 `previous_release_id`를 그대로 쓴다.

### 증강 연결 이어받기

새 패치에 연결 정보가 없으면 직전 패치의 승인된 연결을 쓴다. 단, 원래 패치에서 그 연결이 실제로 채택됐고(삭제 판정 제외), 같은 `platform_id`가 새 패치에서도 내부 증강이 아니며 한글·영문 이름과 등급이 같을 때만 이어받는다. 새 패치에 사람이 저장한 행(승인·거절)이 있으면 이어받지 않는다. 이름이 바뀌었거나 새로 생긴 증강만 검수 대상으로 남긴다.

저장 RPC는 DB의 승인 연결 행으로만 증강 ID를 확정하므로, 이어받은 연결은 새 패치 행으로 저장한다(`evidence.carriedFrom`, 검수자는 원래 연결의 검수자). 다음 수집에서는 이 행을 원래 패치 기준으로 다시 판정하므로 여러 패치를 거쳐도 기준은 사람이 검수한 패치 하나다. 관리자가 같은 행을 다시 검수하면 일반 연결로 바뀐다.

결과가 0건일 때 실패 대신 "검수 대기"로 기록하는 방안은 보류한다. 저장 RPC가 빈 후보를 받지 않아 관리자 화면에 검수할 목록이 생기지 않으므로, 실패 알림을 유지하는 편이 낫다.

### 대기 후보 정리

- 같은 대상에 새 후보가 들어오면 이전 대기 후보는 정리한다. 파일은 R2가 아니라 Supabase Storage `lol-augment-snapshots`에 있고 해시 주소라 여러 후보가 공유할 수 있으므로, 남은 후보가 참조하지 않는 파일만 지운다.
- 정규화 결과가 직전 후보·공개본과 같으면 새로 저장하지 않는다.
- 승인된 자료와 공개 이력은 계속 보존한다.

### 패치 전환

공개 화면은 해당 패치의 승인본이 없으면 가장 최근 승인본을 보여주고, "16.21 기준" 같은 패치 표시를 붙인다. 공식 증강 공개 시점과 관계없이 화면이 비지 않게 하기 위해서다.

- 2026-11-09: 자동 공개를 허용한다(PR 3 진행).
- 2026-11-09: PR 3 자동 공개는 관리자 적용 버튼과 같은 대상·차단 규칙에 수량 10% 감소 보류를 더했다. 참조 자료(티어·아이템·과거 순위)는 대상마다 수량이 고정이라 수량 기준을 적용하지 않는다. 운영 기준은 `docs/operations/2026-11-04-lol-mayhem-champion-dataset.md`의 "자동 공개"에 둔다.
- 2026-11-09: 16.22 공식 증강 변경 기록 32건을 실제 상태와 대조해 30건 승인·2건 제외(내부 전용 증강 이름, 파싱 불완전 경고)하고 16.22 도감을 공개했다. 이어 16.22 추천 조합·아이템 173명·패치 순위 16.10~16.22가 자동 공개됐다. 챔피언 통계·티어는 공급원이 16.21.5라 16.21 공개본을 유지한다.
- 2026-11-09: 16.22 확인 중 증강 10개 처리. 공식 이름·등급이 같은 활성 5개(간지럼 괴물, 구원, 마나 없음 상관없음, 무리한 진입, 튕기는 꿀벌)와 관리자 결정에 따라 이케시아의 몰락(원본 영문 Void Immolation)을 1361로 연결했다. 16.21에 비활성으로 검수한 증강이 이후 패치 공식 자료에서 빠지면 삭제로 판정한다(흡혈병, 양자 연산, 어깨 위의 악마, 눈덩이 업그레이드).
- 2026-11-09: 공개 화면에 "패치노트" 탭을 추가했다. 승인된 공식 변경 기록(`lol_augment_patch_changes`)을 공식 증강 공개 패치까지 보여주고, 패치별 수집 스냅샷의 툴팁에 계산식·수치를 채워 바뀐 문장만 전후로 비교한다. 툴팁에 없는 값은 내부 값 이름을 아는 단어로만 한국어로 옮긴다. 변경 감지는 해시로만 남아 있던 내부 이름이 평문으로 풀린 경우를 같은 값으로 본다(16.22 "수치 변경" 19건 중 8건이 이 경우였다).
- 2026-11-09: PR 4 — 새 패치 공개본이 없으면 직전 패치 공개본을 기준 패치 표시와 함께 보여주고, 추천 조합 자동 공개는 현재 공식 패치 후보만 시도한다. 관리자 요약에 공개 중 패치와 자동 적용 안내를 표시한다.
- 2026-11-09: PR 1 머지 후 수동 실행으로 16.22 연결 206행 저장과 16.22 검수 후보(#12, 선택률 206·조합 424, 미연결 신규 증강 6개) 생성을 확인했다.
- 대기 후보 보존은 기본안 "같은 대상의 최신 1건만 유지"로 진행한다. 별도 지시가 있으면 PR 2에서 바꾼다.
