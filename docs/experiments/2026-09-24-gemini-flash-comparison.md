# 전날 스쿼드 경기 해설: Gemini Flash 비교 (2026-09-24)

검증 대상은 2026-09-23 미라마 스팀 경쟁전 스쿼드 우승 경기 `372fc5fd-7b71-46cf-a891-192691e5f474`다. 공식 [Gemini 모델 목록](https://ai.google.dev/gemini-api/docs/models)의 정확한 호출 ID인 `gemini-3.6-flash`, `gemini-3.7-flash`, `gemini-3.8-flash`를 사용했고, 세 모델 모두 계정의 Models API에서 `generateContent` 지원과 입력 한도 1,048,576토큰을 확인했다.

동일한 한국어 지시문과 입력을 각 모델에 한 번씩 성공적으로 전달했다. 입력은 전체 텔레메트리 34,772건 가운데 랭커 팀의 교전·무기 획득·착지·차량 관련 원본 이벤트 301건과 코드로 검증한 팀 명단, 교전, 처치, 무기 출처, 위치 표본, 자기장 자료다. 세 호출의 입력은 각각 31,875토큰이다. 결과는 모두 JSON으로 받았고, 응답 시간은 성공한 호출 기준이다. 3.8은 503 서버 혼잡 응답 두 번 뒤 세 번째에 성공했다. 503과 응답 시간은 당시 서버 상태의 영향이 있으므로 모델의 일반적 속도나 안정성 순위로 해석할 수 없다.

세 모델 모두 팀원과 주요 무기, 마지막 수류탄·MG3 처치의 큰 흐름은 읽기 쉽게 설명했다. 동시에 시각·상대 팀의 오귀속과 근거 없는 위치·인원·의도 묘사가 발견됐다. 소생의 확인 가능 여부에 대한 평가는 아래 재점검에서 입력 누락으로 보정했다. 한 경기 한 번의 출력으로 모델 간 일반적 우열을 단정할 수 없으며, 이 시험에서는 3.8을 택해도 원본 기록 수준의 정확한 해설이 자동으로 나오지 않았다.

사이트는 모델 문장을 바로 게시하지 않는다. 모델은 검증된 사건의 ID를 고르는 데 쓰고, 공개 문장은 텔레메트리에서 계산한 명단·처치·실제 발사·무기 출처·거리로 구성한다. 집 방어, 푸시 의도, 시야와 엄폐는 텔레메트리만으로 확인되지 않으므로 표시하지 않는다. 자유 해설을 쓰려면 문장별 근거 ID와 인물·팀·시각·무기 검증을 추가한 뒤 별도로 평가해야 한다.

비교에 사용한 원본 응답은 로컬의 `tmp/daily-gemini-comparison-results.json`에 보관했다. 301건은 선택된 원본 이벤트이며 전체 34,772건을 세 모델에 그대로 넣은 비교는 아니다.

## 2026-09-27 재점검: 입력 누락과 모델 오류 분리

`tmp/compare-daily-gemini.ts`, 저장된 입력·출력 JSON, 원본 텔레메트리를 다시 대조했다. 신규 모델 호출은 실행하지 않았다.

- 비교 입력의 `evidence`에는 `facts`가 없었고, 선택된 원본 이벤트 301건에도 `LogPlayerRevive`가 없었다. `revive`/`Revive` 필드는 없으며, 소생이라는 단어는 일반적인 해석 한계 안내에만 등장했다.
- 원본에는 `2026-09-23T08:19:33.722Z`의 `You1Shuo1-_- → Emmm_XiaoXiao` 소생이 있다. 매치 시작 `08:05:55Z` 기준 약 13:38이다. 현재 `buildDailyEvidence`는 이를 `facts`에 담지만, 비교 스크립트가 그 배열을 전달하지 않았다.
- 따라서 이 소생을 확인할 수 없다고 답한 것을 모델의 사실 누락 오류로 채점할 수 없다. 해당 건은 **평가 입력 구성 결함**이다. 인물·시각·상대 팀 오귀속과 근거 없는 지형·인원 묘사는 별도 오류로 남는다.
- 성공 응답의 캐시 입력 토큰은 3.6이 24,499, 3.8이 28,583이며, 3.7 응답에는 캐시 토큰 필드가 없다. 기존 실행은 모델 순서가 고정됐고 모델별 최종 시도만 결과 JSON에 남겼다. 성공 응답 시간만으로 비용·속도·안정성의 우열을 정하지 않는다.
- `tmp/daily-gemini-comparison-large-results.json`에는 별도의 큰 입력 시험도 있다. 3.6/3.7 오류와 3.8 성공이 함께 저장돼 있으나, 이 결과를 위의 동일 31,875 입력 토큰 비교와 섞어 평가하지 않는다.

다음 비교는 공통 근거 입력을 먼저 보완하고, 모델이 실제로 받은 입력에 정답 근거가 있는지 검사한 뒤 수행한다. 모델 원본 응답, 검증에서 거절한 내용, 최종 게시 문장을 각각 평가한다. 상세한 순서와 판정 기준은 [고도화 설계](../superpowers/specs/2026-09-27-learn-daily-replay-design.md)와 [구현 계획](../superpowers/plans/2026-09-27-learn-daily-replay.md)에 정리했다.
